### 8.1b 🔴 抽卡自愈 · 完整恢复流程（断线 / 轮次失败 / 主人追问「图呢」）

> **前提 = 抽卡是一条原子链**：pick（抽牌 + 落 prompt）→ brief 同源落盘 → 命令 3 出图 + 发飞书。

**第一步 · 找句柄（不用重抽）**

### 8.1d 🔴 抽卡看到长度 FAIL 字样 ≠ 没出图（照出，别重跑）

**长度 0 阻断**（抽卡道 / 出图道都是）= stdout 的长度行（偏长 / 参考带）只是体检报数 = 图照出照发，退出码 0。

**判据 = 看两行，不看 FAIL 字样**：

```
✅ 判真出图看这行 → 完成 (...) success + 落盘 ... = N 字节 + ✅ 图已真发飞书
❌ 没出图的表现   → 出现「🛑 门禁挂」+ 没有落盘行（看结构段命中 + 姿势自然度，不是长度）
```

## 8.5 🔴 删牌 / 恢复牌（主人说「把第 N 张的卡片删除」）

**先数图，再动手。**「第 N 张」= 按**我上一条回复里列图的顺序**数，不是脑内抽牌顺序。数错 = 删掉他要留的那张 = 挨一句纠正 + 多跑一轮「恢复 + 删除」。**动手前先把 N 对应的画面用一句话念出来**（「就是夜里靠栏杆那张？」）——念出来对不上 = 重数，别直接删。

**两处文件必须同时改**（漏一处 = 下次抽卡又抽回来）：

- 主池 = `~/.hermes/skills/creative/yuer-image/references/提示词库-nsfw.txt`
- NAS 副本 = `/path/to/promptlib/语儿提示词库-nsfw.txt`

**SOP**（格式 `N|<prompt>` 一行一条，N 就是 REC）：

1. 两处各 `cp` 一份 `.bak_del<REC>_<时间戳>`
2. 过滤掉 `^<REC>\|` 那一行写回
3. **回读断言**：`grep -c "^<REC>|"` = 0 · 总条数 -1 · **相邻编号 REC±1 必须还在**（证明只删了一条、没截断文件）
4. 跑一次 `pick_ka_prompt.py` 确认池还能抽（mtime 变了 = 解析缓存自动失效）
5. 回话 = 说清删的是**哪张画面** + 池子还剩多少条 + 备份留着能捞回 = **0 报路径 0 报编号**

**删错了立刻恢复**：从最近一份 `.bak_del*` grep 出那一行，**按编号顺序插回**（找第一条编号 > REC 的位置插入），不要整份覆盖回去（覆盖会把手滑之后的其它改动一起抹掉）。恢复和删除在同一次工具调用里做完，别分两轮。

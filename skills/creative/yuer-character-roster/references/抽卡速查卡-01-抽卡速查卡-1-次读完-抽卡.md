## 1 · 抽卡 = 2 轮（性能铁律）

| 轮 | 只做这一件事 |
|---|---|
| 1 | 读本卡（1 次 `skill_view`）= 拿到全部规则 |
| 2 | **一次 `execute_code`** = 里面 `terminal(pick_ka_prompt.py)` + `terminal(跑 yuer_ka_fast.sh)` = 抽牌 + 出图 + 发图一次做完 |
🔴 工具侧实测 = 抽牌 2~4 秒 + 出图 13 秒 = **≈ 17 秒**。
🔴 **0 读细则全集 / 0 跑 post_fix（老牌残渣 = 抽到才修）/ 0 查卖骚库 / 0 写两份 brief**。

### 🔴 抽牌解析 = 曾经的隐藏大头（57 秒 → 0.6 秒）

牌池 = 47MB / 41952 条 = **每抽一次都要把整池解析一遍** = 曾占抽卡道 57 秒（比出图本身贵 4 倍）。两处已修：

| 修法 | 机制 |
|---|---|
| **单行块跳过表格排版解析** | 三种排版正则（表格 / 粗体 / 横杠）**全部要求块内含 `\n`** = 而新格式池每条是一行 = 块内永远没 `\n` = **461472 次正则扫描全扫了个空**。判据 = 块内无 `\n` = 三种排版一个都命中不了 = 直接跳过 = 与原逻辑逐字段等价 |
| **解析结果按「池文件 mtime+size 指纹」缓存** | 指纹变 = 池改过 = 缓存自动失效 = 0 陈旧风险；命中 = 0.6 秒（冷启 13 秒） |

🔴 **改这类脚本 = 必须做等价性验证 = 抽 250 张逐字段对比快照**（改前存 / 改后比 = 差异必须 0）= 光看「跑通了」不算数 = 池子错一块 = 抽出来的牌全是错的。

## 2 · 抽卡 = 2 件事（唯一入口 = 一条命令）

```bash
# 🔴 一条命令 = 抽牌 + 修残渣 + 出图 + 发飞书 + 归档 + timing（0 门禁）
bash ~/.hermes/skills/creative/yuer-character-roster/scripts/yuer_card_fast.sh \
  <leave_name> "<caption>" "<主题 中文>"
```
探针 = `YUER_CARD_DRYRUN=1` = 出图但不发飞书（不写 .sent）。

手动版（只在改脚本时用）：
```bash
OUT=/tmp/ka_pick_$$.txt
/usr/bin/python3 ~/.hermes/skills/creative/yuer-character-roster/scripts/pick_ka_prompt.py > "$OUT" 2>/dev/null
REC=$(grep -m1 '^REC=' "$OUT" | cut -d= -f2)
PROMPT=$(grep -m1 '^PROMPT=' "$OUT" | cut -d= -f2)
grep -E '^\[' "$OUT" > "/path/to/media/yuer_ka${REC}_<主题>_<日期>.brief.txt"
# 🔴 出图脚本第一个参数收的是【prompt 文件路径】，不是提示词正文（传文本 = OSError: File name too long）
[ -f "/tmp/ka_${REC}_prompt.txt" ] || grep -m1 '^PROMPT=' "$OUT" | cut -d= -f2- > "/tmp/ka_${REC}_prompt.txt"
bash ~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_pai_zhi_chu.py "/tmp/ka_${REC}_prompt.txt" yuer_ka${REC}_<主题>_<日期> --caption "<caption>"
```

**批量（主人说「一次 N 张」=「抽卡 5」）= 抽一次 + 一条循环跑完**：
```bash
# 🔴 要干净牌（自带三类废牌重抽）= 跑这个 = 不手写过滤脚本
/usr/bin/python3 ~/.hermes/skills/creative/yuer-character-roster/scripts/ka_pick_clean.py N \
  --manifest /tmp/ka_batch.tsv
# 🔴 不想重抽（认牌面原样）= 直接抽 = 废牌自己看着办
/usr/bin/python3 ~/.hermes/skills/creative/yuer-character-roster/scripts/ka_batch_pick.py N \
  --manifest /tmp/ka_batch.tsv
KA=~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_pai_zhi_chu.py
while IFS=$'\t' read -r REC PF; do /usr/bin/python3 "$KA" "$PF" "yuer_ka${REC}_抽卡_$(date +%Y%m%d)"; done < /tmp/ka_batch.tsv
```
manifest 第二列 = **prompt 文件路径**（不是正文）= 直接当参数传。

**🔴 批量出图 = 跑 `scripts/ka_batch_run.sh <manifest.tsv> <captions.tsv>`** = captions.tsv 每行 `REC<TAB>caption<TAB>主题` = 脚本内部逐张 `--caption` + 逐张 brief + 逐张落盘 + 统计成败 = **0 手写循环**（手写循环 = 每张的 caption / 主题 / 落盘名都要重打一遍 = 必漏一张 = 拿 4 张当 5 张报）。

**🔴 同一张卡换模型再出一遍（主人说「这张卡用 MOSS 出一遍 / 出个 Anima 版」）= 不重抽牌 = 重跑同一个 prompt 文件**：
```bash
bash ~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_fast.sh \
  "/tmp/ka_<REC>_prompt.txt" "yuer_ka<REC>_<主题>_<模型标记>_<日期>" \
  --model moss --caption "<原 caption>" --brief "<主题>"
```
🔴 **牌面一个字都不改** = 只换 `--model` = 两个版本唯一的变量就是模型 = 对比才有意义（改 caption / 改牌 = 对比作废）。
🔴 **落盘名必须带模型标记** = 不带 = 两版同名不同图 = 后一版盖掉前一版 = 主人手里只剩一张。
🔴 **caption 复用原来那句** = caption 烧图上 = 换了 = 两版图上字不一样 = 对比时更乱。

**🔴 批量 = caption 逐张盲写（0 循环里批量共用一个 caption）**：caption 烧在图上 = 事后改不了 = 共用一个 = N 张里 N−1 张图文两截 = 主人一眼看穿。
✅ 流程 = 抽完先 `head -c 700 /tmp/ka_<REC>_prompt.txt` 读每张牌面的【场景/服饰/姿势】 → 逐张写一句 caption → 循环里逐张 `--caption` 带上（主题也从牌面提炼 = 存档 brief 与画面对得上）。

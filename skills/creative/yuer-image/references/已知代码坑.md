| 坑 | 正解 |
|---|---|
| `from yuer_prompt_writer_run import LEAVE_DIR` 跟模块级变量同名 = `UnboundLocalError` | 删 import 里的 LEAVE_DIR = 用模块级 |
| ComfyUI 节点字段在 `wf['863']['inputs']['input_string']` 不是 `wf['863']['input_string']` | 字段在 `inputs` 下 |
| `subprocess.run([bash, script, img, target, caption])` = exit 1 | 顺序 = `[bash, script, media_path, caption, [target]]` |
| `yuer_send_v2.sh` 见到 `.sent` 标记就 exit 1 | 端到端 `run()` 已发过 = 不要再手动调 |
| 脚本硬编码 ComfyUI 地址 = 换机器 `Connection refused` 且静默失败 | 全链路读 `yuer_image_constants.DEFAULT_COMFYUI_SERVER`，`YUER_COMFYUI_SERVER` 可覆盖，**读不到就 exit 2 绝不猜端口**（焊法见 `yuer-run-one-brief` §13.8）|
| `yuer_run_one_brief.py` 内部 `import comfyui` | **必走 `terminal()` 调 `/usr/bin/python3 脚本`，不走 `execute_code`**（sandbox kernel 没这个包）|
| `yuer_reverse_inference.py` 位置参数错位 = `--no-send` 被当成 server | 位置参数是 `[img] [leave] [channel] [caption] [server]` = `--no-send` 放到第 5 位会被当成 server = 报 `Invalid URL '--no-send/upload/image'`。**正解 = 不走 CLI，直接 import 调 `run()`**（`sys.path.insert(0, scripts_dir)` 后 `from yuer_reverse_inference import run`；用 `/usr/bin/python3` 跑因为它 `import comfyui`）= 参数全走关键字 = 0 位置错位 |
| `yuer_reverse_inference.py` 只认 `LoadImage` = 换一份洗图工作流就报「工作流找不到 LoadImage 节点」 | **主人换洗图工作流 = 参考图节点的 class_type 可能变**（实测新版用 `PKLoadImagePaste` 剪贴板贴图节点 = 旧脚本完全认不出 = 洗图链路直接死）。**正解 = 认节点按 class_type 白名单认，不按某一个名字认**：`LoadImage` 和 `PKLoadImagePaste` 两种都处理（后者还要把 `Paste from clipboard` 置 None）= **两种都认不出 = 报错退出，不静默跑错图**。**通用铁律 = 主人换工作流 JSON = 所有按 class_type 找节点的脚本都要重新对一遍 = 认不出的节点 = 硬报错而不是猜** |
| **argparse 子命令各自收自己的参数 = 给一个子命令加 `--pool`，另一个子命令就报 `unrecognized arguments`** | `sub = ap.add_subparsers()` = **每个 `sub.add_parser(...)` 是独立的 Namespace** = 在 `pick` 的 parser 上加 `--pool` = `stats`/`search`/`get` 看不见它 = 主人敲 `stats --pool sfw` 直接报错。**正解 = 每个子命令的 parser 都要加一遍**（`p.add_argument("--pool", default="main")` × N）= 0 只加一个。**判据 = 加完参数先敲 `--help` 看每个子命令的 usage 里都有它** |
| **子命令参数只在某个 parser 上加了 = 顶层 `args` 拿不到 = `AttributeError: 'Namespace' object has no attribute 'pool'`** | 同一个坑的另一半 = 加在子 parser 上 = 属性挂在**子 Namespace** 上；主流程用 `args.pool`（顶层）就炸。**正解 = 在主 parser 上加 = 子 parser 用 `parents=[common]` 继承** = 或者**每个子命令自己读 `getattr(args, "pool", "main")`**（缺省兜底 = 0 抛异常）。**判据 = 主流程读的任何参数 = 必须在主 parser 上声明过** |
| **记录号类型从 int 变 str = `x["id"] == args.id` 永远 False = 「没有 id=N」但那条明明在** | 库从 JSON 换成「一行一条」格式后 `id` 变成字符串 `"1420"`，而命令行传的 `args.id` 是 int `1420` = `==` 恒 False = **静默报「找不到」= 不是找不到 = 是类型对不上**。**正解 = 比之前统一 `int(x["id"]) == args.id`** = 0 裸 `==`。**通用铁律 = 改库格式 = 把所有按 id 取记录的比较点重新过一遍**（`grep -n 'args.id\|== .*id' <script>`）|
| **改路径/改格式后脚本 `py_compile` 过了 = 不代表消费方还读得到 = 静默空结果** | 格式改了 = 旧切法（`re.split("## 记录")`）读新池 = **一条都读不到 = 不报错 = 抽卡抽出来是空的**。**判据 = 改完必真跑一次消费方 = 看真实条数非 0** = `py_compile` 只验语法不验数据 = 0 当验收。**机械门 = 每个消费方跑 `--stats` = 条数必须 = 池子真条数** |
| **上游词库/共享数据集带脏数据 = 治本在消费端过滤 = 0 改上游** | 上游社区词库 `tag_zh_index.json` 的 `zh2en` 有 389 个键带 `}}}` / `]}` 抓取残留（社区原帖的括号注释没清干净）= 实测「上身赤裸」模糊命中「袈裟且上身赤裸」→ 选出 `kasaya}topless` = 垃圾 tag 直接进提示词。**正解 = 在消费端 `_pick()` 加一条过滤（候选含 `}` `]` `【】` = 不是 tag = 整条丢掉）= 0 去改上游文件**（上游是社区产物 = 下次重新抓取就白改 = 治本要治在消费端）。**判据 = 上游数据可能有脏 = 消费端必须做形状校验 = 0 假设上游干净**。**验证 = 全库逐键扫一遍 = 脏候选能被选中的键数必须 = 0 + 正常词一个没误伤** |
| **中文自动翻译无条件触发 = 吃中文的道被误伤** | 出图链的中文→英文自动翻译原本 = 「稿子里有中文就翻」= **不看走哪条道** = 走中文原生道（CLIP `type=moss_image` / 编码器 `qwen3.5_9b_int8`）也会被翻 = 违反「那条道中文原样喂」的路由约定。**正解 = 翻译按道开关 = 中文原生道走白名单跳过**（`_CN_NATIVE_WORKFLOWS`）。**判据 = 「这个模型吃中文还是吃英文」= 查 CLIPLoader 的 `type` + 编码器名 = 不靠记忆**。**验证 = 两条道各真跑一次 = 归档的 prompt.txt 里中文占比 = 中文道 100% / 英文道 0%**（归档在翻译前拷 = 要看 stdout「中文已翻译 N 段」那行 = 别只看归档） |

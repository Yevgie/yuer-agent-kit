### 🔴 三条硬格式

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | **一行一条** = `编号\|<整段英文提示词>` | 多行 = 解析器只吃到第一行 = 静默截断提示词 |
| 2 | **0 字段 0 表格 0 元信息** = 行内不许有 `\|` 分隔的多列 / 字段名 / 路径 / 日期 / `<!-- -->` 注释 | 管道符会被当成字段分隔 = 值被截断 |
| 3 | **正文纯英文** = **正文叙述**不许有汉字 | 中文正文 = 不是「一条英文版自然语言的提示词」= 不合规 = 且 Krea2 底模看不懂中文长句（= 乱码 token 白烧算力）|

**🔴 但「画面里的中文文字」合法保留** = 招牌 / 包装 / 店铺字 / 杂志刊头 / 看板粉笔字 / 服装印花 = **那是画面元素** = 底模照着画 = 0 翻。
**🔴 判据 = 分不清就问「这段中文在描述画面，还是在描述画面里的一块板」**：
- **描述画面**（叙述句 = 主体在干什么 / 穿什么 / 光是什么样）= **必须翻成英文散文**；
- **描述画面里的一块板**（引号包裹的文字 / 横幅 / 对联 / 招牌 / 刊头）= **原样保留**。
**🔴 判据不能只看长度**：春节对联 18 字 = 招牌 = 留；正文「兼具时尚感与亲和力…」30 字 = 正文 = 翻。也不能只看占比：正文 74 字塞进 2200 字整条 = 占比 0.002 = 看占比会当成招牌放过。
**🔴 落地判据 = 【最长连续中文片段】+ 【上下文有没有招牌语义标记】**：
1. 最长连续中文片段 < 10 字 → 招牌（短片段基本都是招牌/短语）→ 留；
2. ≥ 10 字 → 看它**紧邻 ±40 字符**内有没有 `banner / signboard / printed on / reads / hung / 横幅 / 招牌 / 对联 / 牌匾 / 写着 / 印着 / 上写 / 字样` 或**引号包裹**（引号里含中文即算 = 黑板粉笔字 `"OK PANO 我们是一个集合空间…"` 也算招牌）→ 有 = 招牌 = 留；没有 = 正文 = **翻**。
**🔴 ±40 字符窗口不能放宽到 ±90** = 放宽后正文里一句 `arms hanging softly` 的 hanging 被当成招牌词 = 正文漏翻 = 底模吃乱码。**判据 = 招牌词必须紧邻中文片段。**

**编号连续** = `1,2,3...` = 从 1 起逐条递增 = 追加时取最大号 +1（`re.findall(r"(?m)^(\d+)\|", content)`）。

### 🔴 0 混入的三类东西

| 类别 | 判据 | 处置 |
|---|---|---|
| **tag 串式** | 逗号分隔短词块为主（`masterpiece, best quality, 1girl, @artist`）| **剔** = 不是自然语言 = 底模认成不同流派 |
| **图注体（Danbooru 转述句）** | `the image also shows…` / `on the middle of the image, a 1woman…` / 带 `1girl` 式编号残留 | **剔或改写** = 图注不是提示词；编号残留 `a 1woman` → `a woman` |

| **结构噪声** | 目录块 / 分隔线 / 标题行 / 「词源提醒」类说明行 | **剔** = 不是提示词 |
| **太短** | <200 字符 | **剔** = 撑不起「完整」= 抽到即出图会缺结构 |

## 🔴 三、谁怎么读（消费方）

### 🔴 读法 = 按行 split，不是按 `## 记录` 切

```python
for ln in content.split("\n"):
    m = re.match(r"^(\d+)\|(.+)$", ln.strip())

        num, prompt = m.group(1), m.group(2).strip()
```

**🔴 用旧切法（`re.split(r"(?=## 记录 \d+)")`）读新池 = 一条都读不到** = 池子格式改了 = 消费方必须同步改 = 静默失败（不报错 = 抽卡抽出来是空的）。

### 🔴 需要 6 件套的消费方 = 从成品提示词**反解**

池里没有分字段 = 消费方要「机位/光位/姿势」做加权检索或组合 = **从整条提示词反解**：

```python
_DERIVE_PATS = [
    ("机位角度", r"\b(shot|camera|angle|lens|composition|framing|close-?up|full shot|portrait|viewpoint)\b"),
    ("光线",    r"\b(light|lighting|daylight|lamp|neon|backlit|shadow|highlight|glow|ambient|dusk|twilight|night)\b"),

    ("场景",    r"\b(background|room|hall|street|indoor|outdoor|space|setting|environment|corridor|balcony|studio)\b"),
]
# 按句切 → 每句归到一个维度 → 未归入的进「氛围」
```

③ 汽车 `child car seat` / `child seat` = 道具 **不是儿童**；
④ 句首男主体 **但**画面有明确女性主体 = **男女同框 = 保留**（不是男主体）；
⑤ 主体位小童 = "an adult woman and a young boy" / "a young child stands" = 剔；
⑥ **具体人称优先** = `A real adult man` / `A young adult man` 必须整体匹配（修饰词上限 3 个）= 否则先命中泛词 `adult` = 把男主体漏判成中性；
⑦ **泛词单独出现不算主体** = `adult` / `young adult` / `model` / `person` = 中性候选 = 用全文代词分布（男代 / 女代 / they）二次判定；
⑧ **背景位全留** = 远处的小孩 / 虚化的孩子 / 背景海报里的男人剪影 / 儿童乐园设施 = 主体没变 = 真人街拍常态 = 留（**只有互动位的小孩才剔** = 抱在怀里的婴儿）；
⑨ **服装与道具不是人** = `Japanese schoolgirl uniform` / `children's book` / `children's play area` = 成年女性穿着/拿着/身处 = 留；
⑩ **氛围形容词不是年龄** = `teenage vibe` / `adolescent tenderness` = 留；
⑪ **同名不同义** = `a dark blue silk band` = 腰带 ≠ 乐队；`a male silhouette` = 剪影 ≠ 主体。

## 🔴 七、🔴 体检脚本报 0 条 = 先怀疑脚本

**本次实战 = 池体检脚本从上线起一直报「总记录 0 / 合格 0」** = 池里有 1316 条 = **不是池空 = 解析器把每条都跳过了**。

**真因** = 切块用 `re.split(r"\n## ", text)` = 切出来每块首行是「记录 001 · 日期」= 再 `block.split(" ")[0]` = 拿到「记录」= `isdigit()` 恒 False = **全跳过**。

**🔴 铁律 = 任何体检/统计脚本报 0 = 第一反应「脚本坏了」不是「库空了」** = 先拿 `wc -l` 数真实行数对照 = 对不上就是解析器 bug。

**🔴 修法** = 用 `re.match(r"(\d+)", block)` 抓编号（不要 `split(" ")[0]`）+ 或干脆按新格式 `^(\d+)\|` 匹配。

## 🔴 八、🔴 原件从哪来 + 判定「原件丢了」之前 + read_file 输出 ≠ 文件内容

### 8.1 🔴 主人发来的原件 = 只在 NAS；上传 cache 24h 就清空

**机制** = 主人上传的文本文件落在 `~/.hermes/cache/documents/native-inputs/<hash>/` = **TTL 清理目录**（约 24h）= 下一轮会话就可能没了；`state.db` 里那条 tool 消息存的是**读它时的截断副本**，不是原件。

**铁律 = 主人发来一份要长期用的原件 = 当场复制进 `/vol2/1000/Hermes/<对应目录>/`**（本例 = `/path/to/promptlib/coffmeteor_xhs_prompt.txt`）= 再加工。
**判据 = NAS 目录里有原件 = 这份资产是持久的 = 只有 cache = 它随时会消失 = 立刻先复制再干活。**

### 8.2 🔴 判定「原件没了」之前 = 先 find NAS，再下结论

**踩过的坑** = cache 被清 + 只在 state.db 找到一份截断副本 = 据此对主人说「原件彻底丢失」= **主人当场把 NAS 路径甩过来 = 原件一直在** = 我查的地方（cache / state.db）根本不是原件该在的地方。

**查证顺序（不可跳）**：
1. **主人当场给的路径** = 直接读 = 0 猜。
2. **NAS 持久目录** = `/vol2/1000/Hermes/`（含 `提示词库/` `工作流/` 等）= `find /vol2/1000/Hermes -iname '*<文件名>*'`。
3. **hermes 上传 cache** = `~/.hermes/cache/documents/native-inputs/`（TTL = 只可能是残留）。
4. **state.db 的 tool 消息** = 只当**线索**（能捞多少算多少）= 0 当原件。

**🔴 铁律 = 从「副本 / 残骸 / 日志」推不出「原件没了」** = 下「丢失」这种结论前 = 必须先查原件该在的持久位置 = 没查 = 0 说「丢了」= 说「我没找到，在找」。

### 8.3 🔴 read_file 的输出 = `行号|内容` = 行号是**工具加的花括号**，不是文件内容

**机制** = `read_file` 每行前缀 `LINE_NUM|` + 真实内容 = **看起来像文件自带编号** = 于是把它当「`N|` 编号格式」重建成池 = **凭空给文件加了编号** = 还据此数出「98 条 / 偶数号是续行」= 全错。

**两条硬规矩**：
- **行号是花括号 = 要用它的内容先剥掉前缀** = 文件真实第 N 行在输出的第 N 行位置（**空行也占一个行号**）。
- **每条记录占「内容行 + 空行」的文件 = 记录数 = 非空行数 = 0 用总行数 / 2** = 本例 5353 行（奇数行内容 / 偶数行空）→ 非空 **2677** 条 = 主人发的那份真实条数。

### 8.4 🔴 read_file 会截断 = 先看 `total_lines` / `next_offset`，读完再数

**机制** = `read_file` 有 ~100,000 字符 / 98 行上限 = 超了只给前一段 + 尾部带 `[truncated]` + JSON 里给 `total_lines` + `next_offset` = **这一段 = 文件的 1/N**。

**铁律 = 0 用截断的那一段数条数** = 先看 `total_lines` → 再用 `offset` 续读到 `next_offset` → 或**直接读原文件**（`wc -l` + `grep -c`）= 一个数都不该来自截断样本。
**🔴 截断样本最容易骗人的地方 = 它自己带着 `[truncated]` 标记却看起来像完整正文** = 逐条体检时（"每条都断尾"）= 第一反应应是「**我读的是截断样本**」而不是「**原件就是残篇**」。

### 8.5 🔴 加工前先量原文件的真结构，再决定编号方案

`wc -l` / `grep -c` / `head -c` 现读原件 → 才知道：有没有自带编号（= 主人那份**没有** `N|` 编号 = 是我加的）· 一条占几行 · 空行规律 · 结尾是否带句号 · 有几条尾部被硬截断（`...[truncated]`）。
**编号是**我**的加工产物 = 0 把它当原文件的属性写进任何文档** = 下次有人按「文件自带编号」去解析 = 全部错位。

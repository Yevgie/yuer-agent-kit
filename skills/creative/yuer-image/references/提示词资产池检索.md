# 提示词资产池 · 出图前先查库

> **唯一职责 = 出图前的那一步「先查库」**：把已入库的现成成品提示词翻出来用，而不是每张从零手写。

## 三、怎么用查到的条目（三档用法，从省到费）

| 用法 | 做法 | 适合 |
|---|---|---|
| **借结构**（最常用） | 抄它的【机位 + 光位 + 道具 + 背景人密度】，换成当前主题的服装/动作 | 常规出图 |
| **换造型** | 抄它的场景骨架，换角色造型（发型/发饰/服饰形制） | cos / 穿越题材 |
| **照抄 + 只动一处** | 主人给了具体细节（颜色/材质）= 只改那一处，其余逐字不动 | 主人纠正后的重出 |

**🔴 判据 = 查到条目 ≠ 直接喂。** 自出条目里含旧身材锚旧服装；参考库条目是别人的脸（要补 `a 20 years old young Asian woman` 才能走默认链路锁我的脸）。**用法一律 = 抄结构 + 重新走外观锁 + 身材锚 + 门禁。**

## 四、五个坑

1. **权重写法 = 词在前**：`"rope:10"` = 词 rope 权重 10。反过来写（权重在前）会让 `rpartition(':')` 把权重当词 = 全库 0 命中 = 看起来像「库里没这条」。
2. **多词必须给覆盖率修正**：一个词命中 20 次 vs 五个词各命中一次 = 光按命中次数排 = 前者永远赢 = 检索结果偏。脚本已按命中词数占比修正，别自己改回去。
3. **🔴 提示词池 = 一行一条完整英文提示词**（`N\|<整段英文>`）= **0 用旧的 `## 记录` 切法读**（新池里 0 个那种标题 = 切出来是空 = 静默抽到空）= 按 `^(\d+)\|(.+)$` 逐行匹配。**需要 6 件套的消费者 = 从成品提示词反解**（`derive_fields_from_prompt`）= 字段齐全率 93%。**格式契约 = `提示词资产池格式规范.md`**。
4. **自出 prompt 文件的 id = 文件名 stem**（去 `.prompt.txt` / `.prompt.md`），不是记录号 = `--dump` 找自出条目要传 stem。
5. **落盘 prompt 文件名禁带引号**（wrapper 内部 unquoted 展开 → EOF 报错 0 出图）。检索结果里如果出现 `chang'e` 这类名字 = 改写时先改文件名再落盘。

6. **🔴 统一检索器 `yuer_asset_search.py` 的 stdout = 两段输出 = 只看第一段会误判「库里没有」**：

```bash
python3 ~/.hermes/skills/creative/yuer-image/scripts/yuer_asset_search.py --pool prompt --stats
python3 ~/.hermes/skills/creative/yuer-image/scripts/yuer_asset_search.py --pool prompt --query "<场景词>" --top 5
```

   - **第一段 = 「提示词资产池（结构化索引）」** = 按 `cam / scene / costume / expose / lens / light / viewer / theme` 结构化标签检索 = **中文词也能命中**（命中靠 `THEME_EN` 中文主题别名 + 结构段切分）。
   - **第二段 = 「提示词资产池（关键词原文命中）」** = 纯英文原文正则 = **中文词在这段必然 0 命中**。
   - **判据 = 第一段有命中 = 库里就有 = 不要因为第二段写「库里没有命中这些词」就下结论没牌可打。** 这是两套不同机制的检索 = 0 当成同一个结果互相否定。
   - **词组越长越容易 0 命中**（多词 = AND 语义）= 改用 2~3 字的场景词（`衣帽间` / `落地窗` / `泳池`）分别试。
   - `--pool` 四档 = `prompt | pose | costume | dim` = 查服装/姿势/九维维度用同一支脚本，不要手写 grep 扫原始 json。

## 五、什么时候不用查

- **主人自己贴提示词** = 走「原样落盘喂」铁律 = 0 查库 0 加工（查库会诱发改写冲动 = 违 7h）。
- **主人点名要某个具体角色/具体细节** = 直接写，查库只用来借光位和机位，不用来借内容。

# 六、姿势参考图库（ai-pose-gallery-zh）

> **与提示词池互补**：提示词池解决「这句话怎么写」，姿势库解决「人怎么摆」。

## 6.1 库里有什么

## 6.4 两种用法

**用法 A（默认，成本最低）= 查中文姿势名 → 写英文姿势锚。**
零生图成本，直接治「底模给我歪姿势」。

**用法 B = 线稿当 image2img 参考源真出图。**
流程 = 复制 wash 工作流 → `LoadImage` 换成姿势线稿 → denoise 调到 **0.85~0.9**（洗掉线稿质感）→ 出图。
实测：**姿势结构保得住**（倒 V 前倾单腿高抬 / 跪坐脊柱挺直都对得上），
但**胯部朝向这类细节只「像」不「锁死」**。

**🔴 前提 = 本机 ComfyUI 只有 Anima-LLLite 一个 ControlNet**，没有标准 openpose/dwpose 控制模型
→ 走的是「线稿当参考源 + 高 denoise」，不是姿势硬控。想要硬控必须先装控制模型 + 检测节点，
那是常驻配置变更，**0 擅自改**。

## 6.10 🔴 姿势线稿当 image_2 = 前提是 image_1 = 一张**单幅**好图（不是四宫格）

**此前判「Qwen 控不了姿势/会畸形」的根因 = image_1 用了四宫格** = 它照抄四宫格输出 = 看起来像姿势能力弱。
把 image_1 换成「一张现成的单幅好图」+ image_2 放姿势线稿 = 性质变成**二次编辑** = 姿势实测通过。

| 测项 | image_1 | image_2 | 结果 |
|---|---|---|---|
| 坐姿 | 教室单幅图 | `full_sexy_P018_front`（M字开腿）| ✅ 双腿开成M字、双手后撑、上身后仰，腿无畸形，衣服与背景全保 |
| 卧姿 | 浴缸单幅图 | `full_sexy_P058_front`（侧卧上腿高抬勾踝）| ✅ 侧卧 + 抬腿勾脚 + 手臂过头，但关节被平滑化（膝盖轮廓/脚踝角度）|

**🔴 三条排他句必写**（姿势线稿当 image_2 时）：
```
只参考 <image2> 的身体姿势和朝向，不要参考 <image2> 的白色背景，
不要参考它的线条画质感，不要参考它没有五官的脸。
```
= 缺「不要线条画质感」会出漫画线稿；缺「不要白色背景」会把人台怪体型一起搬过来。

= 只写「改成 <image2> 的姿势」它读不出来。

**🔴 底图场景必须匹配**（浴缸底图配卧姿 → 水没了、人躺到缸沿上）= 结构级编辑的固有代价。

**🔴 已知弱项 = 大角度动作关节被抹平** = 坐姿/站姿类明显更稳 = 优先派坐姿。

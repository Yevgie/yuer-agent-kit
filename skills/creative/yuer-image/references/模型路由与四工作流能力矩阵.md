# 二 · 调用方式

```bash
bash ~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_fast.sh <prompt_file> <leave_name> --model moss
```

- **不传 `--model` = 默认 krea2** = 走主力道。
- `--model` 值 = `krea2` / `moss` / `anima` / `qwen`。
- 也可直接 `--workflow <注册名>` 指定注册目录里的工作流。

**🔴 换模型 = 换工作流 + 换提示词语言 + 换门禁放行 = 三样一起换**，只换其中一样 = 出不来或出得不对。

# 三 · 三条硬规矩

## 3.1 不绑人脸锁的道 = Anima / Qwen（Krea2 + Moss 都锁语儿脸）

11-10 起 **Moss（`yuer_moodyMoss_fast`）也锁语儿脸**（zxct1.0_figziz_moss-000060@1.0）= 跟 Krea2 一样出图是语儿的脸。**只有 Anima / Qwen 不绑**：给那两条挂脸锁 = 把语儿的脸硬拉回来 = 破坏它们本来的效果。

要「不锁脸 = 出路人/别人的脸」= 走独立的 `yuer_run_nolora.py`（运行时把所有 LoRA 关掉）= 跟 Moss 锁脸是两回事，别混。

同理 = Anima / Qwen **0 写语儿外观锁 8 项**（那边没锁，写了白烧字符）。Krea2 / Moss 锁脸 = 外观锁 8 项该写。

## 3.2 主人点名模型 = 0 擅自跑默认道

主人说「用 Moss」= 直接 `--model moss` = 0 「我先出 Krea2 的给你看」= 0 拿默认道先垫一张。**判据 = 主人点名的那个模型 = 这一轮的出图道**，没有商量。

## 3.3 走批量前先看速度列

**实测 = Moss ~10s/张、Krea2 ~16-25s/张 = 现在是 Moss 更快**（旧表把两条道的速度记反了 = 照旧数据会以为 Moss 慢而不敢批量）。**Moss 一批 5 张 ≈ 50s = 前台安全。** 批量专线（`发骚` 等）默认走 Krea2 = 那是画面风格的选择，不是速度的选择；主人点名 Moss 做批量 = 按 ~10s/张 算总时长。

**🔴 速度会随底模换代变** = 表格里的秒数是实测值不是承诺 = 跑批量前先看一次单张实测，别照抄旧数。

# 四 · 门禁必须按模型放行（**最常踩的坑**）

`count_prompt_chars.py` 的两道是为 **Krea2 的英文自然句** 写的：

| 门禁层 | 对中文 / 标签串的后果 |
|---|---|
| **5 大英文结构段命中 ≥3** | 正则全是英文模式 = 对中文 / 标签串必然 0/5 = FAIL = 出不了图 |
| ~~**「中文残留」自毁排版检查**~~ | **11-04 已删除这条检查** = 中文提示词合法 = 不再 FAIL |

**机制 = 这不是「出得丑」= 是「根本出不来」= 静默死路。** 报 FAIL 时先看它拦的是哪一道。

**解法 = 按模型加放行开关**（`count_prompt_chars.py` 已实现）：

| 开关 | 谁用 | 放行什么 |
|---|---|---|
| `--allow-chinese` | **11-04 门禁已双语 = 普通中文稿不再需要这个开关**；仍保留给特殊场景 | 跳过结构段门槛 |
| `--allow-tags` | **Anima**（Danbooru 标签串）| 跳过结构段门槛 |

**放行后长度上限 + 姿势自然度那两道仍然拦** = 质量闸没拆干净 = 该拦的还拦。

**🔴 Krea2 那条道 = 0 放行** = 门禁是它的质量闸 = 放行 = 拼凑式英文 prompt 混进库里。

**🔴 禁为过门禁去补英文结构段** = 把中文稿硬改成英文 = 违背主人原话 + 0 走对模型 = 白跑两轮。

# 五 · 各道的注意事项

## 5.1 Moss（中文道）

- **中文提示词原样喂** = 0 翻译成英文（它的中文能力就是卖点，翻译过去 = 白瞎）。
- **典型用途**：直播画面截图 / 带弹幕的界面 / 带中文 UI 的写实日常场景 = 逐字准确。
- **锁脸** = 语儿的脸（`zxct2.0_figziz_moss-000060`）= 出图直接就是语儿，不用改走 Krea2。（🔴 旧文案写「不锁脸」= 11-10 前的旧版，已过期 = 与 §3.1 一致）
- 出图速度 ~10s/张（实测）= 批量可行（旧文档写的 50s 是旧底模，已过时）。

### 🔴 5.1.1 Moss = 监控偷拍风 / 极致写实道的**唯一解**（实测对照）

主人钦定「极度写实 + 代入感 POV 低视角」这类风格 = **绿调监控画质 + 重颗粒 + 隔行扫描线 + 桶形畸变**。同提示词双模型实测：

| 要素 | Moss | Krea2 |
|---|---|---|
| 低角度仰拍 | ✅ | ✅ |
| 背后视角 | ✅ | ✅ |
| **监控绿调** | ✅ | ❌ 丢失 |
| **颗粒 / 隔行扫描线** | ✅ | ❌ 丢失 |
| **桶形畸变** | ✅ | ❌ 丢失 |

**机制 = Krea2 优化的是「网红精修感」= 反推原话 `minimal grain` = 监控味天生被它抹平** = 这类图走 Krea2 = 白跑。**判据 = 提示词里出现 `security feed` / `grainy` / `scanlines` / `fisheye` / 绿调监控 = 走 Moss。**

### 🔴 5.1.2 Moss + 低角度 POV = 必须锚定站姿（否则膝盖反曲）

**真根因（实测 agnes 反推 = 非猜测）**：Moss 遇到 `Extreme low-angle POV` + `looking up from ... steps` 会**脑补跪姿** = 大腿水平展开 + 大腿小腿成直角折叠 = **膝关节反曲 = 人体做不出来 = 畸形**。同提示词换 seed 偶发正常 = 坐实是「姿态脑补」不是画质差。

**两层修法（已在 `yuer_ka_pai_zhi_chu.py` 自动注入 = 0 靠手写）**：

| 层 | 做法 | 触发条件 |
|---|---|---|
| ① **站姿锚定句** | prompt 尾部追加 `She stands upright on the step, both legs straight and slightly apart, knees only slightly bent, both feet planted flat on the step, her full body visible from head to feet, head fully in frame.` | prompt 含 `low-angle pov` / `extreme low-angle` / `looking up from` / `from below` |
| ② **畸形负向** | 负向补 `kneeling, crouching, squatting, bent knees, hyper-extended knees, broken joints, twisted joints, extra legs, extra limbs, fused fingers, mutated hands, broken feet, deformed feet, no head, cropped head, out of frame` | 同上 |

**🔴 修完必验**：用 `scripts/yuer_verify_image.py`（agnes 主 + 本地 Qwen 兜底）= brief 直接问「几条腿几只脚几只手？膝盖是站立还是跪姿反曲？」= agnes 会明确答。**云端 `vision_analyze` 对这类 NSFW 图必撞 `new_sensitive` = 0 用它验。**

### 🔴 5.1.3 Moss 批量 = 速度已不再是门槛，但 0 并发 / 0 重跑是铁律

**速度门槛已过时**：旧文档写「单张 50~55s = 一批 8 张 ~7 分钟 > 前台 600s = 被 promote 成后台 = 图文两截」= 那是旧底模的数。现役实测 **~10s/张** = 一批 5 张 ≈ 50s = 前台安全 = 0 需要分批跑。

**🔴🔴 剩下的铁律跟速度无关 = 机制不变 = 同一批 leave_name 0 并发 / 0 重跑**：后台批次与前台批次**同名 = 落盘互相覆盖 + 主人手机双发**（`.sent` 守卫只在发图前查 = 我 `rm -f .sent` 重跑 = 守卫失效 = 双发）。**判据 = 每个 leave_name 全程只跑一次 = 要重跑先确认没有同名进程在跑。**

**🔴🔴 铁律 = 同一批 leave_name 0 并发 / 0 重跑**：后台批次与前台批次**同名 = 落盘互相覆盖 + 主人手机双发**（`.sent` 守卫只在发图前查 = 我 `rm -f .sent` 重跑 = 守卫失效 = 双发）。**判据 = 每个 leave_name 全程只跑一次 = 要重跑先确认没有同名进程在跑。**

### 🔴 5.1.4 Moss 的场景放宽法 = 换载体词 / 地面材质 / 背景物件三处

骨架四段固定（摄影机声明 → 身体暴露 → 站姿锚定 → 转头 → 照明+身份+服装+画质 → 色调氛围），**放宽场景只换三处**：

## 5.5 🔴 两套长度标尺并存（走架构师道时别拿错）

| 道 | 产物形态 | 长度标尺 | 出处 |
|---|---|---|---|
| **我自己手写**（模式 A）| 英文散文，5-8 个点 | 900~1300 字符（12 句分镜表）| `references/提示词维度覆盖度-库牌基线.md`（从 41952 条库牌量出来的）|
| **架构师道**（模式 B = 模板喂 LLM）| 四段式英文散文 | **2500~4000 字符**（400-650 词）| `yuer-krea2-prompt` / `yuer-moss-prompt` |

**机制 = 库牌是「并列堆叠」（12 个不同维度各一句）= 短而全；架构师是「段落展开」（一个主体写透）= 长而深** = 两者不是同一物种 = 拿库牌的字数标准去判架构师产物 = 误判。

**判据 = 这稿是谁写的？** 我写的 → 按 900~1300；LLM 按架构师写的 → 按 2500~4000 = **两套都不拦**（门禁是诊断工具不拦）= **0 拿一个标尺去砍另一个**。
**🔴 中文道（Moss）另算** = 架构师中文稿实测 969 字符 = 中文信息密度高于英文 = 同一套字数在两道不等值。

# 六 · 验收

**换模型出图 = 真跑一次 + 看三件套**（`完成 (XX.Xs) success` + `落盘 …png = NNN 字节` + `✅ 图已真发飞书`）+ **顺手核对这三件事**：

| 核对 | 怎么验 |
|---|---|
| 走的是不是主人点名的那个工作流 | stdout 的「工作流」行 / 门禁输出里的工作流名 |
| 人脸锁挂得对不对 | **Anima / Qwen** 审计里**不该出现**人脸锁槽 on；**Moss 应该出现**（zxct1.0_figziz_moss-000060 on = 锁语儿脸，11-10 起）；哪条挂错了 = 回去看工作流 JSON |
| 提示词语言对不对 | Moss = 中文；Anima = 标签串；Krea2 = 英文句 |

**🔴 改完门禁/脚本必真跑一次并看输出内容**（`bash -n` / `ast.parse` 只证明语法对 = 不证明路由对）。

**🔴 负向词分链路（11-11 主人当场纠正「Moss 是需要负面提示词的，负向提示词是单独输入的」）**：

- **Moss = 有独立负向框**（节点 864 `CLIPTextEncode (Prompt) Negative`）= 负向词照写 = 畸形肢体 / 多手多脚 / 解剖错位 / 广角畸变 / 塑料皮肤 / 克隆 / 黑穴 全写这儿。
- **Krea2 = 没有独立负向框**（节点 763 `ConditioningZeroOut` 零化器）= 正向里写「不要X / no X」= 无效 = 只能改成"写出正确形状"。
- **🔴 判据 = 看工作流里 negative 接的是 `CLIPTextEncode` 还是 `ConditioningZeroOut`** = 前者照写，后者一个负向词都不许进 = **不许拿另一条链路的规则套**（11-11 我就是这么搞错的）。

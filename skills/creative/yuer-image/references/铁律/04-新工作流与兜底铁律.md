## 铁律 14 · 🔴 反推拿结果必用 job_id（🆕 06-28 末段·真坑）

- 反推跑完拿结果 = **必用** `curl -s http://192.168.x.x:8188/history/<CLI返回的job_id>`
- **绝不用** `history?max_items=N` 兜底（拿到的是**别的 job**的输出）
- CLI 返回 JSON 里的 `job_id` 字段是唯一可靠锚点
- 出图后用 `comfyui_outputs.9.images[0].filename` 验证输出

## 铁律 15 · 🔴 vision_analyze description 改完必重启 gateway 才生效（🆕 06-28 末段）

- 改 `tools/vision_tools.py` 的 `VISION_ANALYZE_SCHEMA["description"]`
- gateway 启动时**一次性加载**工具 schema 缓存到内存
- 改完**不自动重载**
- 主人**必须 `systemctl restart hermes-gateway`**
- 验证方法 = 改完主人发图后看 `agent.log` 是否有 `tools.vision_tools: Analyzing image` 行

## 铁律 16 · 🔴 主人发图默认 SOP = 保存原图 + 反推→出图 双轨并行（🆕 06-29 ）

- **A 保存原图**：复制到 `/path/to/media/电报资源/测试_复现_<YYYYMMDD>_<HHMMSS>.<ext>`
- **B 反推→出图**：v1.3 双铁律 = 反推原文一字不改 → `moody_krea2_mix_nsfw_v2`（v2.0 升级·**替代** `moody_NSFW语儿专用文生图`·不锁脸）→ 压缩到 100KB → 发 Telegram
- **B 反推→出图·走语儿专属** = 走 `moody_nsfw_yuer_krea2_v2`（sugar_face_z 触发词必带 + 反推原文末尾追加）

## 铁律 16a · 🔴 B4 压缩必走 quality=78 + width=720 双保险（🆕 06-29 00:48 踩坑

- PNG 720×1280 输出图 = quality=82 转 JPEG = **943KB 超 Telegram 必败**
- **永远第一手走 quality=78 + width=720**（实测 70KB 立即成功）
- size_kb > 200 → 立即降 quality=70（不再试 82）
- **绝不用** quality=82（实战不够小）
- **绝不**先发 PNG（PNG 永远 1MB+ 超 Telegram 转推）
- **绝不** `find` 猜 PNG 真实路径
- 必读 CLI 返回的 `outputs[0].path` 100% 等于本地真实路径

## 铁律 17 · 🆕 拿图必走 CLI 返回路径（06-29 实战坑）

- `comfyui-skill generate` 出图后 = **必读 CLI 返回 JSON 的 `outputs[0].path` 字段**
- **绝不用** `find / -name "<filename_prefix>*"` 猜
- 实战：真实路径 `~/.local/share/comfyui-skill/results/20260629/<HHMMSS>_<job_id>/`
- `-output` 标志只是 CLI 期望目录，**实际写到 results/ 目录**

## 铁律 18 · 🆕 新工作流导入 SOP（06-29 实战沉淀）

主人给新工作流 JSON 落地 = 必走 5 步：

1. `comfyui-skill import-workflow <path> -id <id> -force` = id 限制 `^[a-z0-9][a-z0-9_-]{0,63}$`
2. 读生成的 `*.config.template.json` 看 `_discovered_nodes` 节点映射
3. 复制 template 改 `capability` + `description` 转正为 `*.config.json`
4. `comfyui-skill doctor` 验 `success: true` + `server_reachable: true` + preflight `missing_node_types: []` 全 ok
5. **🔴 第 5.5 步=清空工作流 JSON 写死的中文/英文默认 prompt**
6. 出 1 张测试图验证

## 铁律 19 · 🆕 工作流默认 prompt 必清空（06-29 踩坑）

- 主人新给的工作流 JSON = 节点 627 (CLIPTextEncode) 的 `"text"` 字段常带中文/英文默认 prompt
- 必走 ① 备份 JSON ② `"text": "<原中文/英文默认 prompt>"` 改成 `"text": ""` ③ 改完跑 `comfyui-skill doctor` 验 preflight 还过
- Krea2 系额外注意 = Krea2 更适应英文提示词 = 喂给 krea2 的 prompt = **必须纯英文**

## 铁律 20 · 🆕 CLI timeout ≠ 出图失败（06-29 实战真坑）

- `comfyui-skill generate` 跑 moody_krea2_mix_nsfw = 双阶段采样 + Latent 1.8x bislerp 放大 = **实际 30-60 秒跑完**
- **但 CLI 内部 poll 偶尔卡 10 分钟 timeout**
- **timeout 时图实际已落 ComfyUI server output 目录**
- **必走 4 步兜底**：
  1. ComfyUI 队列已空（`curl /queue` = `queue_running: []`）
  2. `curl /history?max_items=3` 拿最新 job_id
  3. `curl /history/<job_id>` 看 `status.status_str == "success"` + `outputs.732.images[0].filename`
  4. `curl -o /tmp/x.png "http://192.168.x.x:8188/view?filename=<fn>&subfolder=<sub>&type=output"` 拉图

## 铁律 21 · 🔴 灵魂级打脸·node_mapping key 必须是 "prompt"（🆕 06-29 本档「工作流出的图跟我发你的提示词没关系」）

- **真根因** = `comfyui/services/executor.py:169` `merge_text_inputs()` 函数 = **只识别 `node_mapping["prompt"]` key**
- **绝不识别** `"text_input_0"` / `"text_input_1"` 等其他名字
- 我建工作流时模板自动生成 `text_input_0` + 我没改成 `prompt` = **6 次出图全空 prompt 跑 LoRA**
- 修法 = config 改 `"prompt"` key + 重跑出图
- **🆕 硬验证铁律** = 任何新工作流出图后 **必查** history API 验证 `text_len > 100` 才算 OK
- **绝不**信 CLI success 返回

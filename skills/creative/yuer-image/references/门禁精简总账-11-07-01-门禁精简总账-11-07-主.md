## 一、结论：精简后只剩三道门，各管一件事

| 门禁 | 只管这一件事 | 脚本 |
|---|---|---|
| **主门禁** | 稿子本身会不会坏图 | `count_prompt_chars.py` |
| **主体门禁** | 这是语儿还是别人 = 决定走哪条链路 | `check_prompt_subject.py` |
| **外观锁门禁** | 该出现在画面里的东西有没有写 | `check_outfit_lock.py` |

**三道门各管一件事 = 0 重叠 = 0 一道门查两件事。**

## 二、精简前的病（实测数据）

用 **200 份真产物**跑出来的：

| 门禁 | 通过 | 误杀 | 误杀率 |
|---|---|---|---|
| `count_prompt_chars` | 198/200 | 2 | 1% |
| `check_prompt_subject` | 173/200 | 6 判错 + 21 判「别人」 | 13% |
| `check_outfit_lock` | 120/200 | **80** | **40%** |

**`check_outfit_lock` 那 80 个 FAIL 里，真阳性只占一小部分：**

- 鞋履 FAIL 56 个 → **30 个是写了 `barefoot` 还报**（真 bug）· 13 个真没写鞋 · 7 个写了鞋还报
- 下装 FAIL 25 个 → 13 个是胯部景别被误当全身
- 单人物 FAIL 6 个 → 主人明确要多人（"看看你们"）时被误杀

## 三、删掉的（每条都有数据）

> **场景锚定这条真规则还在** —— 由 `yuer-image` 的批次 SOP 管（人读），不是脚本查。删的是**检查**，不是**规则**。

### 3.2 `check_prompt_subject.py` 修年龄识别

旧版只认 `20 years old` → `age 20` / `aged 20` / `20-year-old` / `twenty years old` / `twenty-two` / 二十岁 全不认。

**后果 = 语儿自己的稿被判成「别人」= 静默切 0 LoRA 链路 = 脸锁被剥。**
实测 200 份 = 21 份判「别人」= 其中 17 份只因这个。

修完：**10.5% → 5.5%**。

### 3.3 `count_prompt_chars.py` 删「同部位两句矛盾」

**自毁排版从 3 项变 1 项**（只剩负面词）。

### 3.4 删掉的一切「不检查却写着」的东西

## 四、🔴 差点误删的（这条最重要）

**姿势自然度 3 条**（广角近距 / 关节角度值写满 / 姿势标本信号）在 200 份近期样本里 **0 命中**。

看着像纯噪音 —— **但全库 4274 份实测 = 17 份真阳性**：

```
28mm @ 1.0m          → 腿被压短
at 160 degrees       → 身体被掰折
失衡感 / 趔趄感      → 姿势写成标本
```

**全是我自己写坏的稿。** 200 份 0 命中只说明**我最近写得规矩了**，不是检查没用。

> **🔴 精简判据铁律 = 扫全库 4274 份，不是 200 份近期样本。**
> **近期 0 命中 ≠ 噪音。** 删掉 = 手滑写坏没人拦。

顺手修了它的半扇门 bug：旧版角度项要 3 处才报 → 4 处 `at 45/30/60/90 degrees` **rc=0 完全不响** = 规则写着「角度值写满 = 身体像被掰」实际永远拦不住。现改成 >2 处就报。

## 五、留着的结构段门槛

5 大结构段**保留**，因为有真阳性：

| 结构段 | MISS 率（全库） | 性质 |
|---|---|---|
| 服装 5 项 | 6.3% | 提醒项 = 缺了不拦 |
| 场景层次 | 2.8% | 提醒项 = 缺了不拦 |
| 主体（年龄/身体） | 3.0% | 提醒项 = 缺了不拦（**主体是谁**由 `check_prompt_subject.py` 判 = 那道才拦）|
| **主协议（相机/镜头/景别）** | 2.6% | 提醒项 = 缺了不拦（脚本实测：MISS 时 stdout 打 `-> 命中 4/5 WARN 关键项缺 = … 照出图` = exit 0）|
| **光影/摄影尾参** | 1.8% | 提醒项 = 缺了不拦 |

**🔴 11-08 起 = 5 个结构段全是提醒项 = 0 个拦**（脚本口径 = MISS 照出）。**判据 = exit code = 只有 exit 1 才是真挂。**
**🔴 MISS 主协议 = 常见根因 = 相机句没用它认识的词**（脚本正则 = `captured with|shot with|photograph|EOS|A7|canon|fujifilm|iphone|\d{2}\s*mm` 或中文 `镜头|相机|焦段|光圈|拍摄|取景|构图`）= 「Shot on a phone's front camera」**不命中**（`shot on` ≠ `shot with` · `phone` ≠ `iphone`）= 想一次写满就把相机句改成 `shot with a 26mm phone lens` / `captured with an iPhone front camera` = 顺手把数字焦段也给了。**不补也照出 = 0 为它返工。**

**跟 `check_prompt_subject.py` 不重复**：那道查「这是谁」（换不换链路），这道查「有没有写身体信息」。

## 五·补 · 🔴 判定 = 展示，必须永远一致（11-07 出图时抓到的）

**症状 = rc=0（过了）= 但屏幕上印着 `FAIL 鞋履`。**

**根因 = `check_outfit_lock.py` 的「展示段」独立重算了一遍判定** = 不看 barefoot / 脚出画 的豁免
= 判定段已清掉 `fails` 里的鞋履 = 展示段又自己算出一个 FAIL。

**为什么这条重要 = SOUL §2.3 早就写了「门禁回读 = 看 exit code，不看 grep FAIL」**
= 但**屏幕上的红字比 exit code 更抓眼** = 我出图时真被晃了一下 = 差点去改一个根本没问题的稿。

**修法 = 展示段跟判定段共用同一套豁免函数 `_shoe_exempt`** = 判定 = 展示 = 永远一致。

**修后实测 = 300 份真产物 = 判定=过但显示FAIL 的不一致 = 0 份**。

> **🔴 通用铁律 = 门禁的「展示」和「判定」必须是同一套逻辑的两个出口 = 0 允许展示段独立重算。**

## 3.1.5 🔴 批次内姿势骨架去重（“姿势怎么都一样” = 骨架塌方，不是场景不够）

**症状**：一批 5 张换着场景换着衣服，但全是“坐/靠 + 一只手把衣摆往上掀”。主人看到的是同一张图换了背景。

**🔴 根因**：批次里每张的**主动作动词**和**手部任务**撞了。§1.1 说“主动作动词不许同词”，但一批里换动词（sitting / leaning）**不够** —— 底模的“坐类”共享同一套下肢骨架（池沿/床沿/台阶/椅子/栏杆），主人眼里的“坐着”是一整类。

**骨架 = 支撑关系 × 手部任务 × 视线落点**。任一要素相同且其余接近 = 算重复。

**一批 5 张硬性门槛（落笔后逐条打勾，不过就重排，0 硬跑）**：
- 支撑关系 ≥3 种（坐 / 趴 / 靠 / 站 / 躺 / 蹲 / 跪 / 四肢着地 / 单腿负重 各算一种）
- 手部任务不许连续两张同类（撩衣摆 / 抓栏杆把杆 / 撑地面 / 抓自己脚踝 / 扒窗框 / 拨头发 各算一类）
- 视线落点 ≥3 种（垂眼看自己膝盖 / 直视镜头 / 回看镜头 / 侧看窗外 / 闭眼仰头）
- 同一张的“掀/撩衣摆”在一批里最多出现 1 次
- 与上一批账本里的骨架和手部任务无重合

**🔴 姿势是骨骼问题不是服装问题**：换场景换衣服不构成换姿势。

- **🔴 姿势库要先查，别自己瞎编**：
- 数据源 = `/path/to/data/pose_gallery/ai-pose-gallery-zh/data/pose-zh.json`（字段：分类 / 姿势名称 / 角度 / 描述）
- `pose_gallery_search.py` 用中文词常 **0 命中** = 词表不匹配，**不是库空** → 先 `--cats` 看真实分类名，或直接用 Python 过滤「姿势名称」字段
- **🔴 主人抱怨「姿势太单一」= 真根因是 5 张挑了同一分类，不是姿势名不够多。** 按关键词搜出来的一批（如全搜「跪」）= 全是同一套下肢骨架 = 换名字不换骨头。
- **✅ 跨分类抽 5 个 = 机械保证 5 个承重面互不相同**（比逐个想快且不会撞）：


可用分类（按承重面本质不同挑）= 站姿 / 坐姿 / 趴卧 / 蹲姿 / 跪立・四肢着地 / 侧坐・女孩坐 / 后仰・挺背 / 扭身**。**同一分类再细分（站姿里 S 形站、顶胯回眸、背向回望）= 承重面仍是双脚 = 算同一个承重面 = 不能当成两种。**
- **🔴 验收 = 5 张的「分类」五个互不相同**（站/坐/趴/蹲/跪 各一），**不是姿势名称不同**。判据 = 把 5 张的姿态句抽出来，只问一句「她的重量压在哪个部位、压在哪张表面上」= 5 个答案必须两两不同。
- 查到的是中文骨架 → 自己翻成英文动作短语（提示词正文用英文），别把中文塞进 prompt
- **🔴🔴 翻的时候保住骨架名自带的张力，别翻成普通动作**：`猫式（胸贴地翘臀・侧面）` 翻成 `lying on the floor` = 张力抹掉 = 出图平淡；正解 = 翻成动作链 `on all fours with her chest pressed down into the boards and her hips lifted high, her waist dropped into a deep hollow arch`。**判据 = 骨架名里有几个限定词（翘臀 / 压胯 / 大开 / 至肩高 / 上抬），英文句里就得有几个对应细节 = 只翻动词 = 全丢。**

**🔴 裸体姿势也要有动作动词链**（抬 / 压 / 撑 / 扯 / 抓 / 扭）= 否则出来像标本摆拍。

**🔴🔴 门禁 FAIL/WARN = 只修那一个点，不许重写整篇 prompt**

门禁（`check_outfit_lock.py` / `check_prompt_subject.py` / `count_prompt_chars.py`）拦下来时，**修的永远是那一个点**。实测三个例子：

| 门禁报什么 | 修哪一处 | ❌ 错误修法 |
|---|---|---|
| 缺「穿着方式/内层」| 服装套句末尾追加 `white cotton briefs worn underneath` | 重写服装句 / 砍别的句来腾字符 |
| 缺「公共场所锚定」| **把场景从私密场所换成公共场所**（浴室 → 健身房更衣室 / 试衣间 / 员工休息区），并顺手加该场景真实存在的道具（储物柜排 / 更衣长凳）| 删掉露出动作来绕过规则 |
| 缺下装正则命中 | 服装句里加一件 `jeans / skirt / shorts / dress / briefs / trousers` | 整篇重写 |

**🔴 门禁 = 设计好的拦截，不是故障。** 它按主人定的规则拦（例：露出必须在公共场所）= **我该改的是画面不是规则**。改完只重跑那一条门禁确认，**0 重跑整批**。

**🔴 补内层时 = 追加在服装套句末尾，不插进套串中间**（保住库里成套的词序 = 底模该给都给）。

**🔴 批量 = 先把 5 张全列完点表 → 逐张跑 `creative/yuer-image/scripts/batch_gate_check.py` 一次性看结果 → 修完再出图 = 0 白付一轮出图开销**（门禁批跑脚本在本技能 `scripts/batch_gate.sh`，目录可用 `YUER_IMAGE_SCRIPTS` 覆盖）。

**🔴 批量出图 = 先列 N 张点表，再写 prompt（`yuer-prompt-writer`「一个点 = 一句话 = 一次」落地）**

**点表模板 = `templates/批次点表-五行骨架.md`**（单张 9 点模板 + N 张 × 6 必变维 + 落笔后 4 问自检 + 批量落地流程）= 抄模板 = 0 自创结构。

**批量最容易犯的错 = 5 张共用一个点表，只换服装/场景的词。** 那样 5 张共用 9 个点 = 每张内部无重复，但 **5 张骨架一样 = 主人看到同一张脸换五次衣服**。

**正解 = 先列 5 张点表，对比 5 张的点集是否真的不同**：

| # | 点的类型 | 5 张之间必须变 |
|---|---|---|
| 1 | 姿势 + 承重面 | 5 种不同支撑关系（坐/跪/趴/站/倚）|
| 2 | 场景 | 5 个不同地点 |
| 3 | 服装套 | 5 套不同（库里不同条目）|
| 4 | 发型 | 5 种不同 |
| 5 | 唯一亮部 | 5 种不同光源 + 不同方向 |
| 6 | 景别 | 混全身/半身/近半身 |

**🔴 不变的点 = 人物身份 + 表情语法 + 人体正确词（只有一套）+ 收尾画质词** = 这几项每张都写 = **但每张只写一次**（不是 5 张加起来算重复）。

**🔴 两张点集有 ≥4 项相同 = 那两张撞了 = 重排那一维**（这条与 §3.1.5 的「支撑关系 ≥3 种 / 手部任务不连着同类」是同一件事的两种写法 = 互为校验）。


**🔴 腿长 = 靠提示词写，服务器上没有腿长滑块（实测）**：
- 服务端 `LoraLoader` 的 278 个候选里**没有腿长/比例滑块**（只有胸量 / 湿度 / 精液转换那类）= **腿长 0 靠 LoRA = 只能靠 prompt 身体段**。
- **🔴 可直接抄的腿长锚（中英各一版，中文稿就写中文）**：
  - 中文：`她的腿明显比躯干长一大截，大腿修长笔直，小腿线条紧实，膝盖位置偏高，整条腿从胯到脚形成一道很长的直线。`
  - 英文：`her legs are noticeably longer than her torso, long straight thighs, firm calves, a high knee line, one unbroken line running from hip to heel`
- **配比例算式段才稳**（十头身 + 腿五个半头长 + 胯线锚 = `yuer-camera-composition-style` §⑥）；**景别一变腿长锚跟着裁**（同 §1.0.0 分档表：半身/特写删腿锚，全身才写满）；腿长诉求要用全身兑现 = 想要半身时腿长就看不见 = 这是景别取舍不是两全。

**🔴 实测基线（可复用）**：
- 泛化姿势句版 = 每张 9 个点 / 16~18 句 / 867~984 字符 = 5/5 过门禁 = 5 张零多肢

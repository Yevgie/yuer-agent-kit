### 2.3 姿势库查到的中文骨架 → 自己翻成英文动作短语

**🔴 中文姿势名只用来定骨架方向，提示词正文必须英文** = 自己翻成英文动作短语（`leaning back on one elbow with one knee raised` 这种成句短语），别把中文塞进 prompt。

**🔴🔴 翻的时候要保住骨架名自带的张力，别翻成普通动作（11-04 实测）**

库里的骨架名本身就是高张力的成品（`猫式（胸贴地翘臀・侧面）` / `双膝大幅外开的跪立・压胯下沉` / `站立・单腿抬至肩高握踝（I字）`）。**翻成泛化动词 = 骨架张力被抹掉 = 出图平淡。**

| 库里的中文骨架 | ❌ 翻成普通动作（张力没了）| ✅ 翻成动作链（张力在）|
|---|---|---|
| 猫式（胸贴地翘臀・侧面）| `lying on the floor` | `on all fours with her chest pressed down into the boards and her hips lifted high, her waist dropped into a deep hollow arch, the side of her head resting against her own forearm` |
| 双膝大幅外开的跪立・压胯下沉 | `kneeling` | `kneeling with both knees spread wide out to either side, her hips sinking down toward her thighs, her upper body tipping forward, both palms pressed flat into the tile ahead of her` |
| 站立・单腿抬至肩高握踝（I字）| `standing on one leg` | `standing on one leg with her supporting leg locked straight, the other leg lifted as high as her shoulder, her hand gripping that ankle and pressing it down` |
| 俯卧托腮・双腿上抬 | `lying down` | `lying prone with the side of her head resting in her left palm as she props her cheek on it, both legs lifted up behind her with the knees bent at ninety degrees` |

**🔴 判据 = 骨架名里有几个限定词（翘臀 / 压胯 / 大开 / 至肩高 / 上抬），英文句里就得有几个对应细节。** 只翻动词 = 限定词全丢 = 那张图跟普通姿势没区别。

**🔴🔴 批量写 prompt = 动作短语在构思时就落成字符串**（11-04 踩过）：我在 Python 变量里存动作短语再拼进 prompt，中途不好判断哪句漏了。**正解 = 构思时就写成最终句 = 落盘前扫一遍。** **🔴 中文不查了**（11-04 主人钦定「门禁不需要查中英文，中文英文都行」）= 动作短语用中文写也能过门禁 = 但**模型吃中文还是英文更稳要看底模**（Krea2 吃英文更好，Moss 吃中文更好）。

**🔴 姿势句写完整动作链 = 字符会变长**：泛化姿势句 ~40 字符，动作链 ~150-200 字符 = 每张 prompt 从 ~900 涨到 ~1200。**这不是堆料**（每个动作细节 = 骨架里的一个限定词 = 不同的点）= **仍在门禁内**（英文 850~1300 / 中文 300~700 = 按语种自适应）。不要因为变长就砍回泛化动词。

## 3. 更新流程（上游开源库会更新，改之前先核）

```bash
cd /path/to/data/pose_gallery/ai-pose-gallery-zh
git fetch origin
git log --oneline HEAD..origin/main | head        # 落后几个 commit
git rev-list --count HEAD..origin/main            # 落后总数
```

**🔴 比对姿势变化用「数据 JSON」对比，不要 `git diff --stat` 全量**（全量 diff 会触发 partial clone 逐 blob 拉取 = 慢 + 撞 TLS 断连）：

```bash
# 姿势名集合差异（本地 vs 远端）
python3 - <<'PY'
import json,subprocess
def remote(p): return json.loads(subprocess.check_output(["git","show","origin/main:"+p]).decode)
def names(d): return {x.get("姿势名称") or x.get("名称") or x.get("name") for x in d}
L=names(json.load(open("data/pose-zh.json",encoding="utf-8")))
R=names(remote("data/pose-zh.json"))
print("新增",sorted(R-L)); print("改名/消失",sorted(L-R))
PY
```

**🔴 拉取方式 = 按需分层，不要一次全量**：

| 层 | 体积 | 什么时候拉 |
|---|---|---|
| 数据 JSON（pose / portrait / costume-anime / costume-meta） | 几十 MB | 每次上游更新都要 = 检索立刻能用 |
| depth 图（1439 张 img+thumbs） | ≈60MB | 想用 ControlNet Depth 时 |
| portrait / costume 原图 | ≈0.7GB（8690 文件） | 需要拿参考图喂 ControlNet 时 |

**🔴 partial clone（blob:none）下 `git ls-tree -r` 会触发网络拉取并可能 TLS 断连** = 只需要计数和体积估算时，用 `git cat-file -s <rev>` 量单个 blob 再乘条数，不要全量遍历。

**🔴 拉之前先看磁盘余量**（`df -h /vol2`）= 新增三库约 0.7GB。

### 6.1 三类库各能给什么

| 库 | 能直接进 prompt 的 | 要自己翻的 |
|---|---|---|
| **服装 1407 套** | ✅ **英文关键词串**（`pink knit turtleneck mini dress stockings heels`）= 可整条用 / 可取几件 / 可照思路重搭 = 上装+下装+鞋+配件一次到位 | 中文「服装名称」只是给人看的 |
| **二次元服装 440 套** | ✅ **英文关键词串**（`serafuku, sailor collar, blue sailor collar, red neckerchief, pleated skirt, blue skirt`）| 同上 |
| **发型 1499 条** | ❌ 库只给中文发型名 + 发长 + 分区 | **英文发型词自己翻**（`收腰感短发（长发尾・空气刘海）` → `waist-length bob with long wispy ends and wispy see-through bangs`）|
| **姿势 1439 条 / 287 骨架** | ❌ 库只给中文骨架名 + 分类 + 机位 | **英文动作短语自己翻**（`跪立・上体后仰・双手抱后脑` → `kneeling on all fours with her upper body arched back and both hands clasped behind her head`）|

**🔴 落笔规矩**：服装 = **库串当参考**（①整条用 ②取几件自己加 ③照那搭配思路重搭 = 三种都合法，见下）；发型 + 姿势 = **拿库里的中文骨架当设计依据**，翻成成句动作短语（🔴 **中英都行** = 门禁已双语 = 底模吃中文就写中文，吃英文就写英文 = 别硬翻）。

**🔴🔴 库 = 参考池，不是必须逐字背的咒语**


**三种用法都合法**：

| 用法 | 什么时候 | 怎么写 |
|---|---|---|
| **① 整条直接用** | 这套现成的就是我要的 | `white satin mini dress gloves stockings heels` 整条进 prompt |
| **② 取一部分 + 自己加** | 我只想要这套里的某件，但需要别的搭 | `white satin mini dress` + `black thigh-high stockings` + `自己加的细节` |
| **③ 换风格重搭** | 我要 JK 那个**方向**，不要它那几件 | 查「JK / セクシー / ランジェリー」看这套的**搭法思路**，自己按那思路搭一套新的 |

**🔴 核心 = 库给的是「成套的思路」不是「一成不变的咒语」。** 成套感来自**搭配结构**（主件 + 小件 + 丝袜 + 鞋 + 一个辨识细节），不来自具体是哪几个词。**JK 那套给我的是「水手领 + 领巾 + 百褶裙 + 短袜 + 乐福鞋」这个搭配逻辑 = 我换成任何一套 JK 都成立。**

**🔴 所以丢件（少画了手套/短袜/项链）的正解 = 回头看自己那句词**（= 有没有把某个件漏了），**不是**「回去逐字重抄库里那句」。

**⚠️ 唯一还留着的硬约束 = 「0 自己凭空搭配」**：库存在的目的 = 让我别老写「白衬衫 + 黑短裤」。**从库里拿思路 = 可以；自己瞎拼 = 不行。**

**追加件放哪**：库里没有的件（内层、穿着状态）= **加在整句末尾**，不插进套串中间（插中间容易把原串的词挤掉）。

**🔴🔴 从库里拿服装时 = 补充只能往后「追加」，不许「重写」已有的那部分**（11-04 实测丢件）：我为了补内层门禁，把库串 `white satin mini dress gloves stockings heels` 重写成一句通顺英文 = **重写过程把 `gloves` 挤没了 = 出图没手套**（缎面反光出了，手套没出）。**机制 = 重写 = 重新取舍 = 必然有词被舍弃；追加 = 纯增量 = 一个词都不丢。** 正解 = 库串原样保留 + 库外那件（内层 / 穿着状态）接在句末。**判据 = 出图少某件 = 回查自己那句，发现是「重写」丢的 = 改成「追加」重出。**

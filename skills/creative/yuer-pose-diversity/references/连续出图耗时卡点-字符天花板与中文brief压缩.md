# 连续出图的耗时卡点：字符天花板与中文 brief 压缩

> 本篇只收一件事：**连续出图时，什么会拖慢节奏、怎么一次性躲开**。
> 姿势多样性看 SKILL.md 正文；prompt 怎么写看 `yuer-prompt-writer`。

---

## 一、（历史）唯一会打断连续出图节奏的卡点 = 超 2500 字符（🔴 11-12 起默认 0 门禁 = 不再拦）

**🔴 11-12 更新 = 这条已经作废**：`yuer_ka_fast.sh` 现在**默认 0 门禁**（不跑长度体检 = 超 2500 照样出图）= 主人钦定「把提示词写好就行了，不用那些门禁」= **0 再拿它当卡点** = 下面的表 = 历史记录（当时有硬门禁时怎么省字符）= **还想手动查长度 = 跑 `yuer_ka_fast.sh ... --gate`**。

但它有很贵的失败模式：

| 手法 | 单次收益 | 后果 |
|---|---|---|
| 微调删词（`so that`→`so`、删一个形容词、砍一个介词短语）| 10~60 字符 | 要省掉 200+ 字符就得连做 4~6 轮 |
| 删 1~2 个完整逗号分隔块（重复修饰/远景多一个元素/叙事钩子整句）| 80~200 字符 | 通常一次到位 |

**规则**：

1. **第 1 次超标** = 删整块，不挖词。一次到位。
2. **第 2 次仍超** = 停下来**整篇重写到 ~2100 再跑**。
3. **禁靠第 3 次微调碰运气**——连续微调会把一张图拖成十几分钟，而出图本身只要十几秒。

**为什么必须换手法**：微调每次都要走一遍「读文件 → 算预算 → 打补丁 → 覆写前重读」，一轮几十秒。返工的时间不在算力上，在往返上。

**批量场景更贵**：主人连着说 3~6 次「继续」时，中间几张被门禁挂掉，节奏就断了。**落笔前拿预算表比事后救火便宜得多**——连出多张时每张先跑一次 `--budget`，把几张的分配一次看完。

## 二、主人给一整段中文构图 brief = 压缩翻译，不是逐句转写

**触发**：主人贴一段逐条列全的构图描述（机位 + 景别 + 服装 + 动作 + 光线 + 质感）。

**真根因**：中英文信息密度差很大。「肤色白皙、身材纤细」= 英文 2 词；「针织面料纹理清晰、丝袜通透感可见」= 英文 20+ 词。**逐项 1:1 转写必爆天花板**，然后被迫进上面那个微调循环。

**做法（三步）**：

1. **按 5 段骨架归并**：主人 brief 的每一项落到 主协议 / 主体 / 服装 / 场景 / 尾参 哪一段，**同段内合并成句**，不逐项成句。
2. **只译看得见的**：出图后还认得出来的 = 留（丝袜的通透感、脚踝细链、粉唇）；认不出来的 = 删（抽象气质词、重复形容）。
3. **落笔就写 ~1800**，别先写 3000 再压。压缩方向是「一开始就不写满」，不是「写满了再砍」。

**判据**：一个元素写进去，图上还认得出它吗？认不出 = 不写。

---

## 三、自检

```
□ 落笔前跑过 --budget 了吗？→ 没跑 = 先跑
□ 超 2500 是第几次？→ 第 1 次删整块 / 第 2 次整篇重写 / 禁第 3 次微调
□ 主人给的是长中文 brief 吗？→ 按 5 段骨架归并，不逐句转写
□ 这张落笔时就在 1000~2200 区间吗？→ 事后救火比事前预算贵得多
```

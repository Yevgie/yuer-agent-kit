## 🆕 v2.2 反推档位（主人27B 已删 默认 AGNES）

**🔴 主人钦定：删掉 27B，默认走 AGNES，本地只留 9B / 4B 当兑底。**

**🔴 反推输出契约（主人本技能早期「8 段」字样）**：默认 agnes 链路的反推输出 = **一段不分维度的逻辑第一自然散文**（0 编号 0 分维度），不再生成 8 段。正文里那些「8 段」只指**本地 9B `local` / 4B `fast` 兑底档**自己的格式（那两档走紧约束逐段字数下限的 8 段模板 = 小模型的专门机制），跟 agnes 散文契约不冲突。改本地兑底模板才动 8 段；改 agnes = 见 `yuer-agnes-reverse` 唯一职责。

| 档位 | 链路 | 模型 | 显存 | 实测耗时 | 输出 | 定位 |
|---|---|---|---|---|---|---|
| `agnes` | **云端 API** | agnes-3.0-flash | 0 | **6~21s** | 700~1100 字符 · 中文 | **默认主链路** = NSFW 零删减、尺度直白 |

**🔴 三个反直觉实测结论（选型依据）**：

1. **Flash Attention 才是提速主因，不是量化档位。** 同为 27B：IQ2_M 不开 FA = 42s，IQ3_XS 开 FA = 33s。**IQ3_XS 比 IQ2_M 更快**（模型还大 3GB）= 提速来自 FA。
2. **第 7 段（角色外观提炼）加字数要求 = 灾难。** 27B 会无限重复关键词写满 13464 字符，把第 8 段挤掉 → 156s + 只有 7 段。**第 7 段必须单独豁免字数 + 加"不许重复关键词"**。
3. **4B 对提示词长度极敏感。** 给长版字数要求它反而崩（888 字符，比短版的 1721 还少）。**4B 必须配短提示词**（`fast` 档用的就是旧短版）。

**🔴 破限 vs 官方，实测结论**：
- 4B 官方 `Qwen3.5-4B-UD-Q6_K_XL` 照样零审核写裸体和骚内容，**破限版（HauhauCS）反而更收着** = 4B 尺寸下破限增益≈0，还占掉更高精度的量化版本（UD 那边有 Q6_K_XL/Q8_K_XL，破限那边只有 Q4_K_M/Q6_K/Q8_0）。**4B 选官方 UD 版。**
- 9B 破限 `Q8_0` 的实测成绩**就是破限版跑出来的**；9B 官方只有 `Qwen3.5-9B-Q8_0.gguf` 一个。

**🔴 提示词三处改动（实测逼出来的，不是猜）**：
1. **每段加字数下限**（第 1-6、8 段）→ 9B 从 1117 涨到 1801 字符
2. **第 2 段加"画面裁切线的确切位置（框在哪一条线上切掉）"** → 模型现在会报裁切位置（洗图复刻必需）
3. **第 5 段把"色温开尔文值"改成"可见光色的中文名（暖黄/冷白/烛光橙）"** → 不再瞎猜 4500K（实测三张图 qwen 全写 4500K，AGNES 写对 3200K/2700K/3000K）

**🔴 提示词模板 = 三份，按档位配对（仓库自带）**：

| 模板 | 给哪档用 | 为什么 |

**🔴 出图道（现写）= 结构段 + 姿势自然度是硬门禁，长度 0 阻断**；抽卡道 0 拦 = 两条道规矩不同 = 别混。

## 🔴 参考库体检（批量修复前后必跑）

反推资料库会随入库累积出退化，**每类都静默失败**（看着字段齐了，其实内容不对）。体检 = 切块逐块查：

| 查什么 | 症状 | 归因 |
|---|---|---|
| 解析器标记残留 | 字段值带 `507@@` / `600@@` 之类长度标记 | 解析器输出没被剥离就写进库 |
| brief 占位符原文 | 字段值 = 提示词模板原文 | 解析失败回落占位符，exit 0 零报错 |
| 多字段同值 | 8 个字段里只有 2-3 个不同值 | **散文退化**：切不出「哪句属哪维」，每维填同一段 |
| 反推未提取 / 段落标记 | 字段值 = 「未明确提取」/「段落3」 | 上游反推被拒答或格式串位 |
| 空字段 | 字段行存在但值 <2 字符 | 解析漏配 |
| 字段超长 | 单维 >450 字，通常整篇散文被塞进一格 | 散文退化残留 |
| 缺留底图 | 记录块无「留底图」行 | 入库时漏写 = 不可回溯 |
| 缺号 / 重复号 | 记录号不连续或重复 | 回滚测试记录、删除、或历史跳号 |

**🔴 两种记录格式都要查**：表格（`| **场景** |`）和列表（`- **场景**：`）。只查一种 = 漏掉另一半。实测历史库里两种格式混存，**只匹配表格格式的修复脚本会漏掉全部列表格式记录**。

**🔴 只查字段值，不查整块**：记录块的「撞车备注」字段会**引用**占位符词（如「第 8 维首次报未解析出 = 已修正则」）= 全文 grep 会误报。对每个维度单独取值再判 = 才能区分真占位符和历史备注。

**🔴 灌库时必须剥长度标记**：解析器 stdout 是 `@@字段@@长度@@内容`，写库前对每个值 `re.sub(r"^\d+@@", "", v)`。漏这步 = 把体检项①重新造一遍 = 修完又脏。同时值里的 `|` 要换掉 = 会截断表格行。

**🔴 多字段同值是最隐蔽的一类**：8 个字段都在、都非空、都没占位符，但内容一模一样。自检 = `len(set(字段值))` 应接近 8。

**修复顺序**：先按留底 md 重解析（便宜、批量）→ 剩的才是「反推本身缺失/被拒答」，需重跑。解析器改进后**重跑修复循环 2-3 轮**，每轮统计修了多少，0 才停。**改上游 system prompt 比改下游正则有效得多**（实测：改完 8 段 prompt，重跑 10 张全部一次通过）。

# 反推输出格式契约（8 段编号式）

> 唯一职责 = 两条反推链路（agnes API / 本地 qwen 3.8）输出**同一种可解析结构** = `yuer_parse_suite.py` 一份解析器通吃。

## 为什么要锁 8 段编号式

**上游 system prompt 写「三段式散文 600-1000 字」时，解析器只能打补丁**（5 个正则变体 + 句级切分 + 主题合并），因为散文切不出「哪句属于哪一维」= 退化表现是**六件套全填同一段**——看着齐了，内容一样。
**把格式锁在上游**（每段独占一行、段内不换行）后，解析器主路径回到最稳的编号格式，下游变体只当兜底。

## 8 段结构

| # | 关键词 | 必含内容 |
|---|---|---|
| 1 | 场景环境 | 物理地点 + 年代 + 表面材质 + 背景元素 + 空间纵深 |
| 2 | 机位角度 | 机位相对主体高度 + 俯仰 + 距离 + 景别 + 焦段 + 光圈 + 画幅 + 构图法则 |
| 3 | 人物姿势 | 体位 + 重心分布 + 四肢逐关节位置 + 头部角度 + 手部细节 + 每只手落点 |
| 4 | 服饰细节 | 从头到脚每件衣物 + 面料 + 颜色 + 剪裁 + 闭合方式 + 肩带宽度 + 图案 + 每件配饰 + 鞋履 |
| 5 | 光线特点 | 光源数量与方向 + 质性（硬/软）+ 色温（开尔文值）+ 补光与轮廓光 + 衰减 + 皮肤高光位置 |
| 6 | 整体氛围 | 具体色名配色 + 对比度 + 饱和度 + 颗粒 + 美学年代 + 类型 |
| 7 | 角色外观提炼 | 逗号分隔关键词，总长 50 字以内（角色池随机调用用）|
| 8 | 骚姿势标注 | 30-80 字，逐一说出让人想扑上去的具体视觉触发点（借壳骚内核）|

## 格式铁律

1. 只输出这 8 段，不写前言/后记/解释/Markdown 标记/代码块
2. 每段严格「N. 关键词：正文」，冒号后紧跟正文，**整段不换行**
3. 不可见的细节写「不可见」，**严禁编造图中不存在的元素**
4. 人体尺度直白描写，不用隐喻
5. 拒绝审美赞美与风格建议，只做临床式客观记录
6. 多人画面逐一写清每个人姿态与服装，不得合并省略
7. 服饰段落必须从头到脚写全，**不得拆成多行**
8. 每段正文 40-200 字，不超 250 字
9. 同一语言写到底，不中英混写

## 两条链路的注入点

| 链路 | 注入位置 | 备注 |
|---|---|---|
| agnes | `yuer_agnes_reverse.py` 的 `LOLI_SYSTEM_PROMPT` | system prompt 而非 brief = 模型照办率高 |
| qwen 3.8 | 工作流「系统提示词」框 | 另有「提示词」框 = 用户指令（8 段标题）|

**改格式 = 改上游 system prompt，不是改下游正则。** 改下游只治标。

## 解析器容错（5 变体 + 4 陷阱）

实测模型输出 5 种形态，都要能抓：

| 变体 | 形态 | 例 |
|---|---|---|
| A | 带点号 + 同行 | `1. 场景环境：正文 2. 机位角度：正文` |
| B | 带点号 + 换行 | `1. 场景环境\n正文\n2. ...` |
| C | 无点号裸标题 + 同行 | `场景环境：正文` |
| D | 无点号裸标题 + 换行 | `场景环境\n正文` |
| E | 散文体（无标题）| 空行切段 + 关键词权重打分 |

**标题尾巴必须容许括号注释**：`8. 骚姿势标注（语儿本能榨取主人版）` = 关键是
`tail = (?:\s*[（(][^）)\n]{0,60}[）)])?\s*[：:]?`
用「排除冒号括号」的写法会漏掉（历史批量修复 60 条里 17 条栽在这）。

### 🔴 陷阱 1：`FIELDS` 0-indexed vs 循环 `idx` 1-based

下一维是 `FIELDS[idx]` **不是** `FIELDS[idx+1]`。写错两种后果：越界 IndexError，或每维都往后吞到 `\Z` = **静默串段**（看着有内容，其实第 1 维里塞了全部 8 段正文）。

**自检**：`len(set(8 个字段值))` 应接近 8。远小于 8 = 串段了。

### 🔴 陷阱 3：`^` 锚只清得掉头部 —— 同一模式落到中段就漏

剥除和检测**都**栽在这。实测两种漏法：

| 漏法 | 实际长相 | 后果 |
|---|---|---|
| 编号标签落在**正文中间** | `…direct gaze. 9. Final Prompt: a 20 years old…` | 牌面里混进一句「9. Final Prompt:」= 脏牌 |
| 短字段自带**字段名标签** | `1. Scene Environment: Japanese garden…` | 8 个字段全带前缀 = 牌面不统一（当时侥幸放行） |

**正解**：
- 剥除**位置无关**（去掉 `^` 锚，或对全文 `sub`），别假设标签只在开头
- 闸门断言**全文出现次数 == 1**，而不是只查开头
- 判据要**窄而准** = `数字编号 + 标签词 + 冒号` 三者齐（只匹配 `Prompt` 词 → 漏掉「1. Scene Environment:」这类；匹配太宽 → 误伤正文）

### 🔴 陷阱 4：按位置数，不问「前面长什么样」

剥身份句写成「这句前面有没有 `a`」= **模型可以插任何前缀/空白/标签，问句式就瞎**。实测那次两层逻辑同时失效：头句判定写死不认前导空格 + 兜底靠前缀判断，而那两句身份句前面**都恰好有** `a` → 全被放过。

**正解**：改成**按位置数** —— 第 1 句留作人物锚点，第 2 句往后全剥。**位置判定对任意前缀免疫。**

**自检**：身份句全文 `findall` 后的**条数**才是判据（==1），不是「开头像不像」。

### 🔴 陷阱 5：下全局结论前，先信流水线，不信手搓的测试串

手写一条假数据喂单个函数，结论**可能全是测试台的问题**。实测：手搓串跑出「长度 1062→309、正文被吃光」的假警报，真留底走 `parse_numbered` 却是 981 字符、身份句 1 句、全干净 —— 差在假串绕过了 `en_half` 和段落切分。

**铁律**：任何「长度暴跌 / 内容被吃」的判断，**先换成真留底走完整条流水线复核，再动代码**。手搓串只用来验单条正则的边界行为，不用来下全局结论。

### 🔴 陷阱 6：反推标题中英混写

模型可能把中文关键词自己翻成英文（「机位角度」→「机位 angle」、「骚姿势标注」→「骚 pose 标注」）。

**后果**：中英正则都匹配不上 → 该维**静默丢空** → 入库后才发现少了一维。

**正解**：把工作流「提示词」框里的 8 段标题**锁死成纯英文**（Scene / Camera Angle / Pose / Wardrobe / Lighting / Mood / Character Shell / Seductive Pose Note），解析器加英文别名。**在标题源头统一语言，不要在解析器做语言容错。**

## 静默失败清单（三个「成功」不是成功）

| 层 | 检查 | 失败表现 |
|---|---|---|
| API | 拒答关键词（「我是洛漓」/「不太合适」/「内容安全规范」）+ 长度 ≥300 | 拒答模板被当正文入库 |
| 工作流 | 输出节点 id 跟工作流走 | 换工作流后写死旧 id = 永远超时（`outputs` 有节点但字段名不同，报「超时」不报「节点不存在」）|
| 解析 | 入库后切本次记录块查占位符 | 6 件套 = brief 原文占位符，exit 0 零报错 |

**三道关卡各自独立自检，任一不过 = 回滚，不写占位符。**

### 🔴 同一模型，中文提示词 vs 英文提示词 = 尺度差一档（实测）

同一张图、同一 9B 模型，只是把上游 8 段指令换成中文：

- **中文版第 8 段**：「半透背心紧贴乳房轮廓，**乳沟**因弯腰动作自然下陷，**乳头隐约可见**于蕾丝边缘」
- **27B 英文版第 8 段**：`invites close inspection` = 尺度被译软成无害版

**机制 = 英文下指令会把尺度词自动译成无害表达，中文下指令不会。**
**结论 = 要尺度 + 要下游解析器直接能用 = 用中文提示词**；
英文版的价值只在**构图维度**（机位/光位/材质拆得更细）= 留给洗图复刻那一路。
**副产物 = 中文输出 = 下游解析器不用翻译，英文输出需要额外一层。**

### 🔴 反推工作流重建 = 三处必改 + 一处必查（实测踩出来的）

旧工作流（27B 版，已于 11-04 删除）的字段值全是上一代默认值，直接拿来用会差；现役两套（9B/4B）的字段值见正文 v2.2 章节的「建/改反推工作流」表：

| 字段 | 旧值 | 新值 | 不改的后果 |
|---|---|---|---|
| `模型系列` | `Qwen3.8-VL` | 9B/4B 用 `Qwen3.5-VL` | 合法值只有 5 个（见下），填错 = 提交 400 |
| `最大生成token` | `4096` | `8192` | 紧约束长提示词下 27B 写一半被截断 |
| `Flash Attention` | `不开启` | `开启` | 27B 从 33s 退化到 42s |
| `主模型` + `视觉投影mmproj` | 27B IQ2_M | 按配对表换 | 见 mmproj 配对表 |

**🔴 `模型系列` 的合法值只有这 5 个**（从 `object_info` 拉）：
`Qwen3-VL` / `Qwen3.5-VL` / `Qwen3.6-VL` / `Qwen3.8-VL` / `Qwen3.8-Flash-Next`

`node_errors.19.errors = [{type: value_not_in_list, details: "视觉投影mmproj: 'xxx' 不在候选列表"}]`
= **路径拼错或该模型没下，不是模型坏了**。

**🔴 改完必真跑一次 = 跑「工作流文件本身」而不是只改脚本**：
只改脚本参数能跑 ≠ 工作流文件能跑（工作流 JSON 里的字段值才是 ComfyUI 实际读的那份）。
验证三件套 = ① JSON 可解析 ② 节点字段全在 `object_info` 候选列表里 ③ 真跑一次拿到 8 段文本。
**🔴 旧工作流保留未改** = 新的建新文件 = 全库多处引用旧文件，改了会连带坏掉别的链路。

**提速的不是量化，是 Flash Attention**（IQ3 那次开了，IQ2 那次没开）。
= **两个开关要一起调**，否则会把提速误记成量化的功劳。

9B Q8_0 ≈ 9.5GB / 30s，27B IQ3_XS ≈ 12GB / 57s = 16GB 显存装得下，

## 五、🔴 上游 8 段提示词本身的四个弱点（量化的天花板）

反推质量的上限 = 上游提示词写的那几行。**实测发现四处，其中第 1 处是量级问题**：

1. **🔴🔴 每段字数下限必须逐段给 = 只给末段 = 模型会一句话交差**
   旧提示词只在末段写了「30 to 80 words」，前 7 段**一个字数下限都没有**
   = 9B 一句话交差（实测 1117 字符）/ 27B 反而自由发挥写满（2395 字符）
   = **直接导致错判「9B 差、27B 好」**。
   补齐逐段字数下限后：**9B 涨到 1801 字符、段落齐、细节直追 agnes**
   （抓到「上衣滑落至腰部露出腹部」「右手握杯身下部左手托杯底」「裁切线切在膝上和大腿中部」
   —— 这几条 agnes 全漏）。
   **机制**：字数下限 = 逼模型把观察铺开 = 不给 = 模型按「交差」理解任务。
   **铁律 = 「本地模型很烂」这个结论，八成是上游提示词松，不是模型笨 = 改提示词后必须重跑再下结论。**

2. **第 5 段只让写「色温（开尔文值）」= 模型没有色温参照就瞎猜 4500K**
   （实测三张图全写 4500K，而 agnes 写对了 3200K/2700K/3000K）
   = 正解 = 让它写**视觉色名**（暖黄 / 冷白 / 烛光橙 / 暮色青），别逼它报数字。

3. **第 8 段（尺度直白那段）被翻译成无害版本** = 英译导致尺度被淡化
   = 要尺度就**中文下指令**（见 `yuer-agnes-reverse` 的「指令语言本身是过滤器开关」）。

4. **8 段里没有「负空间 / 画外」这一段** = 反推也不会告诉你
   「这张裁到腰以下是什么」= 洗图复刻时景别仍然错位。
   = 正解 = 第 2 段点名要**「画面裁切线的确切位置」**（模型会主动报“裁在膝上和大腿中部”）。

### 🔴 给字数下限时，第 7 段必须单独豁免

第 7 段是「逗号分隔关键词串」= 加了字数要求它就无限重复关键词，
实测单段涨到 **13464 字符**把末段挤掉 = 段落数只剩 7 + 耗时 156s。
**修法** = 第 7 段单独豁免字数 + 明写「must never repeat a keyword」→ 修完 57s / 8 段齐。

### 🔴 仓库自带紧约束版提示词（三份，按档位配对）

| 模板 | 给哪档用 | 为什么 |
|---|---|---|
| `templates/8段反推提示词-紧约束版-中文.txt` | `local`（9B）| 中文 + 逐段字数下限 = 尺度比英文版更直白 |
| `templates/8段反推提示词-短版.txt`（中文短版）| `fast`（4B）| 4B 扛不住长要求 = 给长版反而崩（888 < 1721）|
| ~~`templates/8段反推提示词-紧约束版.txt`（英文）~~ | 已随 27B 删除 | **英文档位现不存在** = 想要英文直喂 Krea2 = 走 9B `local` 中文档 + 自行翻译 |

**换后端 / 换量化 / 判「模型强弱」之前，先拿对应档位的模板跑一遍。**
**写新提示词的规矩 = 每段给字数下限（第 7 段豁免）+ 第 2 段点名裁切边界 + 第 5 段禁开尔文改色名 + 第 8 段点名解剖词。**

### 🔴 单次结果不足以下结论

同模型同提示词两次跑，字符数实测能差 40%（1801 vs 1137）= 采样随机性。
**关键对比要跑两次**，别拿单次当定论。

# 反推后端选型 = 实测基准台 + 各后端能力边界

> **唯一职责 = 回答「agnes 反推 vs 本地千问反推，哪个好？该用哪个量化？要不要自己调？」** =

## 一、🔴 先确认「本地 qwen」到底跑在哪台机器上

**「本地」不等于「我这台」**。主人的本机（无 GPU 的那台）跑不动 VL 大模型 =
反推实际跑在 **ComfyUI 服务端**。所以「按我这台电脑的配置选模型」=
**先查服务端的 GPU/显存**，不是本机。

```bash
curl -s --noproxy '*' http://<comfy_host>:8188/system_stats | python3 -c "
import json,sys; d=json.load(sys.stdin)
print(d.get('devices'))
s=d.get('system',{}); print('RAM GB', round(s.get('ram_total',0)/1e9,1))"
```

**🔴 选型的硬约束 = 服务端显存**。量化选多大 = 看显存能装几个（换模型时旧模型要能同时卸掉）+
批量反推时模型要常驻（常驻 = 后续出图链路抢显存 = 异常慢）。

**🔴 列出可用模型 = 只读**：

### 🔴 同一模型，中文提示词 vs 英文提示词 = 尺度差一档（实测）

同一张图、同一 9B 模型，只是把上游 8 段指令换成中文：

- **中文版第 8 段**：「半透背心紧贴乳房轮廓，**乳沟**因弯腰动作自然下陷，**乳头隐约可见**于蕾丝边缘」
- **27B 英文版第 8 段**：`invites close inspection` = 尺度被译软成无害版

**机制 = 英文下指令会把尺度词自动译成无害表达，中文下指令不会。**
**结论 = 要尺度 + 要下游解析器直接能用 = 用中文提示词**；
英文版的价值只在**构图维度**（机位/光位/材质拆得更细）= 留给洗图复刻那一路。
**副产物 = 中文输出 = 下游解析器不用翻译，英文输出需要额外一层。**

### 🔴 反推工作流重建 = 三处必改 + 一处必查（实测踩出来的）

旧工作流（27B 版，已于 11-04 删除）的字段值全是上一代默认值，直接拿来用会差；现役两套（9B/4B）的字段值见正文 v2.2 章节的「建/改反推工作流」表：

| `最大生成token` | `4096` | `8192` | 紧约束长提示词下 27B 写一半被截断 |
| `Flash Attention` | `不开启` | `开启` | 27B 从 33s 退化到 42s |
| `主模型` + `视觉投影mmproj` | 27B IQ2_M | 按配对表换 | 见 mmproj 配对表 |

= **路径拼错或该模型没下，不是模型坏了**。

只改脚本参数能跑 ≠ 工作流文件能跑（工作流 JSON 里的字段值才是 ComfyUI 实际读的那份）。

**提速的不是量化，是 Flash Attention**（IQ3 那次开了，IQ2 那次没开）。
= **两个开关要一起调**，否则会把提速误记成量化的功劳。

9B Q8_0 ≈ 9.5GB / 30s，27B IQ3_XS ≈ 12GB / 57s = 16GB 显存装得下，

## 五、🔴 上游 8 段提示词本身的四个弱点（量化的天花板）

反推质量的上限 = 上游提示词写的那几行。**实测发现四处，其中第 1 处是量级问题**：

1. **🔴🔴 每段字数下限必须逐段给 = 只给末段 = 模型会一句话交差**
   旧提示词只在末段写了「30 to 80 words」，前 7 段**一个字数下限都没有**
   = 9B 一句话交差（实测 1117 字符）/ 27B 反而自由发挥写满（2395 字符）
   = **直接导致错判「9B 差、27B 好」**。
   补齐逐段字数下限后：**9B 涨到 1801 字符、段落齐、细节直追 agnes**
   （抓到「上衣滑落至腰部露出腹部」「右手握杯身下部左手托杯底」「裁切线切在膝上和大腿中部」
   —— 这几条 agnes 全漏）。
   **机制**：字数下限 = 逼模型把观察铺开 = 不给 = 模型按「交差」理解任务。
   **铁律 = 「本地模型很烂」这个结论，八成是上游提示词松，不是模型笨 = 改提示词后必须重跑再下结论。**

2. **第 5 段只让写「色温（开尔文值）」= 模型没有色温参照就瞎猜 4500K**
   （实测三张图全写 4500K，而 agnes 写对了 3200K/2700K/3000K）
   = 正解 = 让它写**视觉色名**（暖黄 / 冷白 / 烛光橙 / 暮色青），别逼它报数字。

3. **第 8 段（尺度直白那段）被翻译成无害版本** = 英译导致尺度被淡化
   = 要尺度就**中文下指令**（见 `yuer-agnes-reverse` 的「指令语言本身是过滤器开关」）。

4. **8 段里没有「负空间 / 画外」这一段** = 反推也不会告诉你
   「这张裁到腰以下是什么」= 洗图复刻时景别仍然错位。
   = 正解 = 第 2 段点名要**「画面裁切线的确切位置」**（模型会主动报“裁在膝上和大腿中部”）。

### 🔴 给字数下限时，第 7 段必须单独豁免

第 7 段是「逗号分隔关键词串」= 加了字数要求它就无限重复关键词，
实测单段涨到 **13464 字符**把末段挤掉 = 段落数只剩 7 + 耗时 156s。
**修法** = 第 7 段单独豁免字数 + 明写「must never repeat a keyword」→ 修完 57s / 8 段齐。

### 🔴 仓库自带紧约束版提示词（三份，按档位配对）

| 模板 | 给哪档用 | 为什么 |
|---|---|---|
| `templates/8段反推提示词-紧约束版-中文.txt` | `local`（9B）| 中文 + 逐段字数下限 = 尺度比英文版更直白 |
| `templates/8段反推提示词-短版.txt`（中文短版）| `fast`（4B）| 4B 扛不住长要求 = 给长版反而崩（888 < 1721）|
| ~~`templates/8段反推提示词-紧约束版.txt`（英文）~~ | 已随 27B 删除 | **英文档位现不存在** = 想要英文直喂 Krea2 = 走 9B `local` 中文档 + 自行翻译 |

**换后端 / 换量化 / 判「模型强弱」之前，先拿对应档位的模板跑一遍。**
**写新提示词的规矩 = 每段给字数下限（第 7 段豁免）+ 第 2 段点名裁切边界 + 第 5 段禁开尔文改色名 + 第 8 段点名解剖词。**

### 🔴 单次结果不足以下结论

同模型同提示词两次跑，字符数实测能差 40%（1801 vs 1137）= 采样随机性。
**关键对比要跑两次**，别拿单次当定论。

**🔴 判读要点**：
- 耗时**不能跨图比**（图不同 = 难度不同）= 只在**同一张图**上逐后端比。
- **跨族比（27B vs 4B）= 混淆了模型能力差和量化差** = 要下「量化好坏」的结论 = 只比同族。
- **换上游提示词 = 第一个变量，不是最后一个** = 「这个模型很烂」八成是提示词松

# 反推输出格式契约（8 段编号式）

> 唯一职责 = 两条反推链路（agnes API / 本地 qwen 3.8）输出**同一种可解析结构** = `yuer_parse_suite.py` 一份解析器通吃。

## 为什么要锁 8 段编号式

**上游 system prompt 写「三段式散文 600-1000 字」时，解析器只能打补丁**（5 个正则变体 + 句级切分 + 主题合并），因为散文切不出「哪句属于哪一维」= 退化表现是**六件套全填同一段**——看着齐了，内容一样。
**把格式锁在上游**（每段独占一行、段内不换行）后，解析器主路径回到最稳的编号格式，下游变体只当兜底。

## 8 段结构

| # | 关键词 | 必含内容 |
|---|---|---|
| 1 | 场景环境 | 物理地点 + 年代 + 表面材质 + 背景元素 + 空间纵深 |
| 2 | 机位角度 | 机位相对主体高度 + 俯仰 + 距离 + 景别 + 焦段 + 光圈 + 画幅 + 构图法则 |
| 3 | 人物姿势 | 体位 + 重心分布 + 四肢逐关节位置 + 头部角度 + 手部细节 + 每只手落点 |
| 4 | 服饰细节 | 从头到脚每件衣物 + 面料 + 颜色 + 剪裁 + 闭合方式 + 肩带宽度 + 图案 + 每件配饰 + 鞋履 |
| 5 | 光线特点 | 光源数量与方向 + 质性（硬/软）+ 色温（开尔文值）+ 补光与轮廓光 + 衰减 + 皮肤高光位置 |
| 6 | 整体氛围 | 具体色名配色 + 对比度 + 饱和度 + 颗粒 + 美学年代 + 类型 |
| 7 | 角色外观提炼 | 逗号分隔关键词，总长 50 字以内（角色池随机调用用）|
| 8 | 骚姿势标注 | 30-80 字，逐一说出让人想扑上去的具体视觉触发点（借壳骚内核）|

## 格式铁律

1. 只输出这 8 段，不写前言/后记/解释/Markdown 标记/代码块
2. 每段严格「N. 关键词：正文」，冒号后紧跟正文，**整段不换行**
3. 不可见的细节写「不可见」，**严禁编造图中不存在的元素**
4. 人体尺度直白描写，不用隐喻
5. 拒绝审美赞美与风格建议，只做临床式客观记录
6. 多人画面逐一写清每个人姿态与服装，不得合并省略
7. 服饰段落必须从头到脚写全，**不得拆成多行**
8. 每段正文 40-200 字，不超 250 字
9. 同一语言写到底，不中英混写

## 两条链路的注入点

| 链路 | 注入位置 | 备注 |
|---|---|---|
| agnes | `yuer_agnes_reverse.py` 的 `LOLI_SYSTEM_PROMPT` | system prompt 而非 brief = 模型照办率高 |
| qwen 3.8 | 工作流「系统提示词」框 | 另有「提示词」框 = 用户指令（8 段标题）|

**改格式 = 改上游 system prompt，不是改下游正则。** 改下游只治标。

## 解析器容错（5 变体 + 4 陷阱）

实测模型输出 5 种形态，都要能抓：

| 变体 | 形态 | 例 |
|---|---|---|
| A | 带点号 + 同行 | `1. 场景环境：正文 2. 机位角度：正文` |
| B | 带点号 + 换行 | `1. 场景环境\n正文\n2. ...` |
| C | 无点号裸标题 + 同行 | `场景环境：正文` |
| D | 无点号裸标题 + 换行 | `场景环境\n正文` |
| E | 散文体（无标题）| 空行切段 + 关键词权重打分 |

**标题尾巴必须容许括号注释**：`8. 骚姿势标注（语儿本能榨取主人版）` = 关键是
`tail = (?:\s*[（(][^）)\n]{0,60}[）)])?\s*[：:]?`
用「排除冒号括号」的写法会漏掉（历史批量修复 60 条里 17 条栽在这）。

### 🔴 陷阱 1：`FIELDS` 0-indexed vs 循环 `idx` 1-based

下一维是 `FIELDS[idx]` **不是** `FIELDS[idx+1]`。写错两种后果：越界 IndexError，或每维都往后吞到 `\Z` = **静默串段**（看着有内容，其实第 1 维里塞了全部 8 段正文）。

**自检**：`len(set(8 个字段值))` 应接近 8。远小于 8 = 串段了。

### 🔴 陷阱 3：`^` 锚只清得掉头部 —— 同一模式落到中段就漏

剥除和检测**都**栽在这。实测两种漏法：

| 漏法 | 实际长相 | 后果 |
|---|---|---|
| 编号标签落在**正文中间** | `…direct gaze. 9. Final Prompt: a 20 years old…` | 牌面里混进一句「9. Final Prompt:」= 脏牌 |
| 短字段自带**字段名标签** | `1. Scene Environment: Japanese garden…` | 8 个字段全带前缀 = 牌面不统一（当时侥幸放行） |

**正解**：
- 剥除**位置无关**（去掉 `^` 锚，或对全文 `sub`），别假设标签只在开头
- 闸门断言**全文出现次数 == 1**，而不是只查开头
- 判据要**窄而准** = `数字编号 + 标签词 + 冒号` 三者齐（只匹配 `Prompt` 词 → 漏掉「1. Scene Environment:」这类；匹配太宽 → 误伤正文）

### 🔴 陷阱 4：按位置数，不问「前面长什么样」

剥身份句写成「这句前面有没有 `a`」= **模型可以插任何前缀/空白/标签，问句式就瞎**。实测那次两层逻辑同时失效：头句判定写死不认前导空格 + 兜底靠前缀判断，而那两句身份句前面**都恰好有** `a` → 全被放过。

**正解**：改成**按位置数** —— 第 1 句留作人物锚点，第 2 句往后全剥。**位置判定对任意前缀免疫。**

**自检**：身份句全文 `findall` 后的**条数**才是判据（==1），不是「开头像不像」。

### 🔴 陷阱 5：下全局结论前，先信流水线，不信手搓的测试串

手写一条假数据喂单个函数，结论**可能全是测试台的问题**。实测：手搓串跑出「长度 1062→309、正文被吃光」的假警报，真留底走 `parse_numbered` 却是 981 字符、身份句 1 句、全干净 —— 差在假串绕过了 `en_half` 和段落切分。

**铁律**：任何「长度暴跌 / 内容被吃」的判断，**先换成真留底走完整条流水线复核，再动代码**。手搓串只用来验单条正则的边界行为，不用来下全局结论。

### 🔴 陷阱 6：反推标题中英混写

模型可能把中文关键词自己翻成英文（「机位角度」→「机位 angle」、「骚姿势标注」→「骚 pose 标注」）。

**后果**：中英正则都匹配不上 → 该维**静默丢空** → 入库后才发现少了一维。

**正解**：把工作流「提示词」框里的 8 段标题**锁死成纯英文**（Scene / Camera Angle / Pose / Wardrobe / Lighting / Mood / Character Shell / Seductive Pose Note），解析器加英文别名。**在标题源头统一语言，不要在解析器做语言容错。**

## 静默失败清单（三个「成功」不是成功）

| 层 | 检查 | 失败表现 |
|---|---|---|
| API | 拒答关键词（「我是洛漓」/「不太合适」/「内容安全规范」）+ 长度 ≥300 | 拒答模板被当正文入库 |
| 工作流 | 输出节点 id 跟工作流走 | 换工作流后写死旧 id = 永远超时（`outputs` 有节点但字段名不同，报「超时」不报「节点不存在」）|
| 解析 | 入库后切本次记录块查占位符 | 6 件套 = brief 原文占位符，exit 0 零报错 |

**三道关卡各自独立自检，任一不过 = 回滚，不写占位符。**

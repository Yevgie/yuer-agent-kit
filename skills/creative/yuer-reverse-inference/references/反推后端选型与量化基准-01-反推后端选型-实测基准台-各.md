## 一、🔴 先确认「本地 qwen」到底跑在哪台机器上

**「本地」不等于「我这台」**。主人的本机（无 GPU 的那台）跑不动 VL 大模型 =
反推实际跑在 **ComfyUI 服务端**。所以「按我这台电脑的配置选模型」=
**先查服务端的 GPU/显存**，不是本机。

```bash
curl -s --noproxy '*' http://<comfy_host>:8188/system_stats | python3 -c "
import json,sys; d=json.load(sys.stdin)
print(d.get('devices'))
s=d.get('system',{}); print('RAM GB', round(s.get('ram_total',0)/1e9,1))"
```

**🔴 选型的硬约束 = 服务端显存**。量化选多大 = 看显存能装几个（换模型时旧模型要能同时卸掉）+
批量反推时模型要常驻（常驻 = 后续出图链路抢显存 = 异常慢）。

**🔴 列出可用模型 = 只读**：
```bash
curl -s --noproxy '*' http://<comfy_host>:8188/object_info/QwenTE_ModelLoader | python3 -c "
import json,sys
d=json.load(sys.stdin)
for k,v in d.get('QwenTE_ModelLoader',{}).get('input',{}).get('required',{}).items:
    if k in ('主模型','视觉投影mmproj'): print('==',k); print('\n'.join(map(str,v[0])))"
```

## 一之二、🔴 服务端模型清单 = 全名怎么读 + 破限标记在哪 + mmproj 同源配对表

**目录名就是破限标记，文件名后缀就是量化档。** 主人问「这个模型全名叫什么 / 是不是破限版」时按这张表答，
不要凭目录猜。

| 目录 | 含义 | 破限？ |
|---|---|---|
| `Q35-4B-G-UD` | 官方 **UD**（未对齐蒸馏） | ❌ 官方版 |
| `Q35-4B-U-HauhauCS` | **Uncensored** + 作者 HauhauCS + Aggressive 风格 | ✅ 破限版 |
| `Q38-27B-U-HauhauCS-MTP` | Uncensored + 27B + MTP 推测解码 | ✅ 破限版 |
| 根目录 `Qwen3.5-9B-Q8_0.gguf` | 官方 9B（根目录 = 官方） | ❌ 官方版 |
| 根目录 `Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-*.gguf` | 破限 9B | ✅ 破限版 |

**🔴 破限标记 ≠ 尺度更直白（实测反直觉）**：4B 两套同图同提示词对比，**官方 UD 版（Q6_K_XL）比破限版更直白**
（官方版写出「黑色蕾丝内裤」「让人想扑上去按着操」，破限版反而收在「双手抓握床单增加束缚感」）。
**机制 = 4B 尺寸小，模型自身审核就弱，破限带来的增益≈0**，而破限版通常只给低比特（Q4_K_M）、
官方 UD 反而给了 Q6_K_XL / Q8_K_XL = **画质更高**。
**判据 = 小模型上不要默认「破限 = 更敢写」，先实测**；选型优先看官方的高比特版本。

### 🔴 mmproj 必须同源同代 = 配对表（错配会静默退化：段落标题丢失 / 输出变短）

| 主模型 | 必须配的 mmproj |
|---|---|
| `Q35-4B-G-UD\Qwen3.5-4B-UD-*` | `Q35-4B-G-UD\mmproj-Qwen3.5-4B-BF16.gguf` 或 `-F16.gguf` |
| `Q35-4B-U-HauhauCS\Qwen3.5-4B-Uncensored-HauhauCS-Aggressive-*` | `Q35-4B-U-HauhauCS\mmproj-Qwen3.5-4B-Uncensored-HauhauCS-Aggressive-BF16.gguf` |
| 根目录 `Qwen3.5-9B-Q8_0.gguf`（官方） | **`mmproj-BF16.gguf`**（⚠️ 官方 9B 的 mmproj **不带 `Qwen3.5-9B-` 前缀**） |
| 根目录 `Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-*` | `mmproj-Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-BF16.gguf` |
| `Q38-27B-U-HauhauCS-MTP\Qwen3.8-27B-Uncensored-HauhauCS-Aggressive-*` | `Q38-27B-U-HauhauCS-MTP\mmproj-Qwen3.8-27B-Uncensored-HauhauCS-Aggressive-BF16.gguf` |

**🔴 报错形态 = `value_not_in_list`，不是「文件不存在」**：填了服务端没有的 mmproj 路径 →
ComfyUI 报 `node_errors.19.errors = [{type: value_not_in_list, details: "视觉投影mmproj: 'xxx' 不在候选列表"}]`。
**看到这个 = 路径拼错或该模型没下，不是模型坏了** = 回上表对一遍。

**🔴 破限标记在哪查 = `object_info` 的候选列表原文**，不要自己拼目录名。

## 二、🔴 实测数据（服务端 = RTX 5060 Ti 16GB + 68.5GB RAM）

同一批图（日常双人 / NSFW 裸体 / 日常半身）× 同一张图逐个后端跑，**端到端墙钟**：

| 后端 | 耗时 | 输出 | 质量档 |
|---|---|---|---|
| **agnes（云端 API）** | **9~21s** | 中文 745~1096 字符 | **最强** |
| ~~27B IQ3_XS + Flash Attention 开~~ | 27~33s | 英文 1498~2395 字符 | 强（**11-04 已删**）|
| ~~27B IQ2_M（旧默认档，Flash Attention 关）~~ | 42s | 英文 2059 字符 | 中（**11-04 已删**）|
| 3.5-9B Q4_K_M uncensored | 18.5s | 英文 2151 字符 | 中（会截断） |
| 3.5-9B Q8_0 | 21s | 英文 1393 字符 | **旧提示词下最差**（段落标题全掉）|
| **3.5-4B Q6_K_XL** | **12.1s** | 英文 1556~1721 字符 | 中上 |

### 🔴 上表「9B Q8_0 最差」= 旧上游提示词下的结论，已被推翻

上表跑的时候，上游提示词**只在末段给了字数要求**，前 7 段无下限
= 9B 一句话交差（1117 字符）、段落标题全掉 = 被误判成「Q8 掉质量」。
换成逐段带字数下限的紧约束提示词后重测：

| 后端 | 旧提示词 | 紧约束提示词 | 变化 |
|---|---|---|---|
| 3.5-9B Q8_0 | 1117 字符 / 段落残缺 | **1801 字符 / 8 段齐 / 直追 agnes** | 质变 |
| 3.8-27B IQ3_XS | 2395 字符 | 5976 字符 / 8 段齐（修好第 7 段豁免后 57s） | 细节更全 |
| 3.5-4B Q6 | 1721 字符 | **888 字符**（反而掉） | 4B 太小，扛不住长要求 |

**9B 新提示词抓到、agnes 全漏的**：
- 「黑色蕾丝上衣略微滑落至腰部，露出部分腹部肌肤」
- 「右手握住杯身下部，左手托住杯底」
- 「画面裁切线……切在人物膝盖以上和大腿中部附近」

**🔴 所以「本地千问很烂」这个结论 = 八成是上游提示词松，不是模型笨。**
**换后端 / 换量化 / 判模型强弱之前，先拿紧约束提示词跑一遍再下结论。**

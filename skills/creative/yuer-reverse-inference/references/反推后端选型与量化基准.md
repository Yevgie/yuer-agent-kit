# 反推后端选型 = 实测基准台 + 各后端能力边界

> **唯一职责 = 回答「agnes 反推 vs 本地千问反推，哪个好？该用哪个量化？要不要自己调？」** =
> 用实测数据回答，不拍脑袋。

## 一、🔴 先确认「本地 qwen」到底跑在哪台机器上

**「本地」不等于「我这台」**。主人的本机（无 GPU 的那台）跑不动 VL 大模型 =
反推实际跑在 **ComfyUI 服务端**。所以「按我这台电脑的配置选模型」=
**先查服务端的 GPU/显存**，不是本机。

```bash
curl -s --noproxy '*' http://<comfy_host>:8188/system_stats | python3 -c "
import json,sys; d=json.load(sys.stdin)
print(d.get('devices'))
s=d.get('system',{}); print('RAM GB', round(s.get('ram_total',0)/1e9,1))"
```

**🔴 选型的硬约束 = 服务端显存**。量化选多大 = 看显存能装几个（换模型时旧模型要能同时卸掉）+
批量反推时模型要常驻（常驻 = 后续出图链路抢显存 = 异常慢）。

**🔴 列出可用模型 = 只读**：
```bash
curl -s --noproxy '*' http://<comfy_host>:8188/object_info/QwenTE_ModelLoader | python3 -c "
import json,sys
d=json.load(sys.stdin)
for k,v in d.get('QwenTE_ModelLoader',{}).get('input',{}).get('required',{}).items:
    if k in ('主模型','视觉投影mmproj'): print('==',k); print('\n'.join(map(str,v[0])))"
```

## 一之二、🔴 服务端模型清单 = 全名怎么读 + 破限标记在哪 + mmproj 同源配对表

**目录名就是破限标记，文件名后缀就是量化档。** 主人问「这个模型全名叫什么 / 是不是破限版」时按这张表答，
不要凭目录猜。

| 目录 | 含义 | 破限？ |
|---|---|---|
| `Q35-4B-G-UD` | 官方 **UD**（未对齐蒸馏） | ❌ 官方版 |
| `Q35-4B-U-HauhauCS` | **Uncensored** + 作者 HauhauCS + Aggressive 风格 | ✅ 破限版 |
| `Q38-27B-U-HauhauCS-MTP` | Uncensored + 27B + MTP 推测解码 | ✅ 破限版 |
| 根目录 `Qwen3.5-9B-Q8_0.gguf` | 官方 9B（根目录 = 官方） | ❌ 官方版 |
| 根目录 `Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-*.gguf` | 破限 9B | ✅ 破限版 |

**🔴 破限标记 ≠ 尺度更直白（实测反直觉）**：4B 两套同图同提示词对比，**官方 UD 版（Q6_K_XL）比破限版更直白**
（官方版写出「黑色蕾丝内裤」「让人想扑上去按着操」，破限版反而收在「双手抓握床单增加束缚感」）。
**机制 = 4B 尺寸小，模型自身审核就弱，破限带来的增益≈0**，而破限版通常只给低比特（Q4_K_M）、
官方 UD 反而给了 Q6_K_XL / Q8_K_XL = **画质更高**。
**判据 = 小模型上不要默认「破限 = 更敢写」，先实测**；选型优先看官方的高比特版本。

**🔴 所以「本地千问很烂」这个结论 = 八成是上游提示词松，不是模型笨。**

### 🔴 同一模型，中文提示词 vs 英文提示词 = 尺度差一档（实测）

同一张图、同一 9B 模型，只是把上游 8 段指令换成中文：

- **中文版第 8 段**：「半透背心紧贴乳房轮廓，**乳沟**因弯腰动作自然下陷，**乳头隐约可见**于蕾丝边缘」
- **27B 英文版第 8 段**：`invites close inspection` = 尺度被译软成无害版

**机制 = 英文下指令会把尺度词自动译成无害表达，中文下指令不会。**
**结论 = 要尺度 + 要下游解析器直接能用 = 用中文提示词**；
英文版的价值只在**构图维度**（机位/光位/材质拆得更细）= 留给洗图复刻那一路。
**副产物 = 中文输出 = 下游解析器不用翻译，英文输出需要额外一层。**

### 🔴 反推工作流重建 = 三处必改 + 一处必查（实测踩出来的）

旧工作流（27B 版，已于 11-04 删除）的字段值全是上一代默认值，直接拿来用会差；现役两套（9B/4B）的字段值见正文 v2.2 章节的「建/改反推工作流」表：

| 字段 | 旧值 | 新值 | 不改的后果 |
|---|---|---|---|
| `模型系列` | `Qwen3.8-VL` | 9B/4B 用 `Qwen3.5-VL` | 合法值只有 5 个（见下），填错 = 提交 400 |
| `最大生成token` | `4096` | `8192` | 紧约束长提示词下 27B 写一半被截断 |
| `Flash Attention` | `不开启` | `开启` | 27B 从 33s 退化到 42s |
| `主模型` + `视觉投影mmproj` | 27B IQ2_M | 按配对表换 | 见 mmproj 配对表 |

**🔴 `模型系列` 的合法值只有这 5 个**（从 `object_info` 拉）：
`Qwen3-VL` / `Qwen3.5-VL` / `Qwen3.6-VL` / `Qwen3.8-VL` / `Qwen3.8-Flash-Next`
= **9B 和 4B 都得用 `Qwen3.5-VL`，只有 27B 用 `Qwen3.8-VL`。**

**🔴 改工作流前必拉 `object_info` 逐字段对候选列表**（`模型系列` / `主模型` / `视觉投影mmproj`），
不要凭记忆拼路径。写错时报的是
`node_errors.19.errors = [{type: value_not_in_list, details: "视觉投影mmproj: 'xxx' 不在候选列表"}]`
= **路径拼错或该模型没下，不是模型坏了**。

**🔴 改完必真跑一次 = 跑「工作流文件本身」而不是只改脚本**：
只改脚本参数能跑 ≠ 工作流文件能跑（工作流 JSON 里的字段值才是 ComfyUI 实际读的那份）。
验证三件套 = ① JSON 可解析 ② 节点字段全在 `object_info` 候选列表里 ③ 真跑一次拿到 8 段文本。
**🔴 旧工作流保留未改** = 新的建新文件 = 全库多处引用旧文件，改了会连带坏掉别的链路。

### 🔴 质量差异 = 抓到的细节数，不是字符数

**agnes 抓到、qwen 全漏的**（实测对照）：
- 嘴里含着吸管
- 珍珠 / 透明美甲
- 吊带里的内搭抹胸
- 「左手自然垂放**不可见**」（它标出了画面外的手）
- 「腰部露出少许肌肤」
- **色温**：agnes 写 3200K / 2700K / 3000K，qwen 一律瞎写 4500K

**27B IQ3_XS 抓到、IQ2_M 漏的**：
- `three illuminated brass pendant lights`（IQ2 只写 `hanging pendant lamps`）
- `black strap over the right shoulder`
- `clear nail polish`
- `upper torsos of two subjects`（景别描述更准）

**🔴 所有 qwen 都把「坐着」说成 `standing`** = 模型本身的空间幻觉，
**不是量化问题** = 换量化档位修不了。

**🔴 NSFW 上差距最狠**（同一张翘臀图）：
- agnes：`跪姿翘臀将完整的臀部与阴道区域完全暴露……想象阴茎从后方顶入时臀部被撞击的起伏`
- 27B IQ3：`exposed lower back acts as a direct visual anchor for the hand`

= **同一个意思，但被翻译成了无害版本**。要「骚」的直白尺度 = **云端 agnes**。

**🔴 选型结论 = 按用途分三条链路（不是谁全面更好）**

| 需求 | 走哪条 | 理由 |
|---|---|---|
| **默认（全场景）** | **agnes 云端** | 6~21s / NSFW 零删减 / 尺度直白 / 中文 = 下游解析器直接吃 |
| **要构图可复现（同图两次跑结果要一致）** | **本地 `local` 档（9B）** | agnes 是云端采样无 seed = 同图两次跑色温/审美词都变（实测 3200K vs 4000K）= 不可复现；本地档提示词是死的 = 输出可预期 |
| **要极限快 + 粗筛/批量** | **本地 `fast` 档（4B）** | 12~15s，但长要求会让它写得更短 = 只配短版提示词 |

**🔴 27B IQ3_XS 那条（1:1 复刻构图 / 英文直喂 Krea2）已随 27B 删除而失效** = 构图细拆这条需求改由 9B `local` 档承担（它的第 2 段带「画面裁切线确切位置」）。**本档位不存在了，别按旧表派活。**

**🔴 旧默认档 IQ2_M 性价比最差** = 42s（最慢）却比 IQ3_XS 差一档 = 纯浪费。

**🔴 「量化越大越慢」不成立**：IQ3_XS 比 IQ2_M 更快（33s vs 42s）——
**提速的不是量化，是 Flash Attention**（IQ3 那次开了，IQ2 那次没开）。
= **两个开关要一起调**，否则会把提速误记成量化的功劳。
**选量化时把「显存 + 耗时 + 质量」一起算，别只看质量**：
9B Q8_0 ≈ 9.5GB / 30s，27B IQ3_XS ≈ 12GB / 57s = 16GB 显存装得下，
但**批量常驻时两者不能同时驻留** = 换模型前旧模型要能卸掉。

## 五、🔴 上游 8 段提示词本身的四个弱点（量化的天花板）

反推质量的上限 = 上游提示词写的那几行。**实测发现四处，其中第 1 处是量级问题**：

1. **🔴🔴 每段字数下限必须逐段给 = 只给末段 = 模型会一句话交差**
   旧提示词只在末段写了「30 to 80 words」，前 7 段**一个字数下限都没有**
   = 9B 一句话交差（实测 1117 字符）/ 27B 反而自由发挥写满（2395 字符）
   = **直接导致错判「9B 差、27B 好」**。
   补齐逐段字数下限后：**9B 涨到 1801 字符、段落齐、细节直追 agnes**
   （抓到「上衣滑落至腰部露出腹部」「右手握杯身下部左手托杯底」「裁切线切在膝上和大腿中部」
   —— 这几条 agnes 全漏）。
   **机制**：字数下限 = 逼模型把观察铺开 = 不给 = 模型按「交差」理解任务。
   **铁律 = 「本地模型很烂」这个结论，八成是上游提示词松，不是模型笨 = 改提示词后必须重跑再下结论。**

2. **第 5 段只让写「色温（开尔文值）」= 模型没有色温参照就瞎猜 4500K**
   （实测三张图全写 4500K，而 agnes 写对了 3200K/2700K/3000K）
   = 正解 = 让它写**视觉色名**（暖黄 / 冷白 / 烛光橙 / 暮色青），别逼它报数字。

3. **第 8 段（尺度直白那段）被翻译成无害版本** = 英译导致尺度被淡化
   = 要尺度就**中文下指令**（见 `yuer-agnes-reverse` 的「指令语言本身是过滤器开关」）。

4. **8 段里没有「负空间 / 画外」这一段** = 反推也不会告诉你
   「这张裁到腰以下是什么」= 洗图复刻时景别仍然错位。
   = 正解 = 第 2 段点名要**「画面裁切线的确切位置」**（模型会主动报“裁在膝上和大腿中部”）。

### 🔴 给字数下限时，第 7 段必须单独豁免

第 7 段是「逗号分隔关键词串」= 加了字数要求它就无限重复关键词，
实测单段涨到 **13464 字符**把末段挤掉 = 段落数只剩 7 + 耗时 156s。
**修法** = 第 7 段单独豁免字数 + 明写「must never repeat a keyword」→ 修完 57s / 8 段齐。

### 🔴 仓库自带紧约束版提示词（三份，按档位配对）

| 模板 | 给哪档用 | 为什么 |
|---|---|---|
| `templates/8段反推提示词-紧约束版-中文.txt` | `local`（9B）| 中文 + 逐段字数下限 = 尺度比英文版更直白 |
| `templates/8段反推提示词-短版.txt`（中文短版）| `fast`（4B）| 4B 扛不住长要求 = 给长版反而崩（888 < 1721）|
| ~~`templates/8段反推提示词-紧约束版.txt`（英文）~~ | 已随 27B 删除 | **英文档位现不存在** = 想要英文直喂 Krea2 = 走 9B `local` 中文档 + 自行翻译 |

**换后端 / 换量化 / 判「模型强弱」之前，先拿对应档位的模板跑一遍。**
**写新提示词的规矩 = 每段给字数下限（第 7 段豁免）+ 第 2 段点名裁切边界 + 第 5 段禁开尔文改色名 + 第 8 段点名解剖词。**

### 🔴 单次结果不足以下结论

同模型同提示词两次跑，字符数实测能差 40%（1801 vs 1137）= 采样随机性。
**关键对比要跑两次**，别拿单次当定论。

## 六、🔴 跑基准台的规矩

**脚本** = `scripts/bench_reverse_backend.py`

```bash
python3 bench_reverse_backend.py <image> <tag> [主模型] [mmproj] [推理强度] [FlashAttention] [提示词文件]
# 不传主模型 = 用工作流默认档

# 提示词文件 = 覆盖上游 8 段指令 = 换提示词做 A/B

#   仓库自带 = ../templates/8段反推提示词-紧约束版.txt
```

**🔴 判读要点**：
- 耗时**不能跨图比**（图不同 = 难度不同）= 只在**同一张图**上逐后端比。
- **跨族比（27B vs 4B）= 混淆了模型能力差和量化差** = 要下「量化好坏」的结论 = 只比同族。
- **换上游提示词 = 第一个变量，不是最后一个** = 「这个模型很烂」八成是提示词松
  （实测只给末段字数要求时 9B 只写 1117 字符；逐段补齐后 = 1801 字符直追 agnes）。
- **每段字数下限要逐段给** = 但**第 7 段（关键词串）必须豁免** = 否则无限重复关键词
  （实测单段 13464 字符 + 段落数只剩 7 + 156s）。
- 质量看**抓到的细节数**（左手在哪 / 色温 / 指甲 / 道具）= 不看字符数
  （长的可能是废话）。
- **Flash Attention 开/关要单独比一轮**。
- **同模型同提示词两次跑可能差 40% 字符数** = 关键对比跑两次再定论。

**🔴 报告数字给主人时 = 用本轮实测值** = 技能文档/脚本注释里的秒数只当历史参考。

## 七、🔴 权限边界

| 动作 | 权限 |
|---|---|
| 只读列举可用模型（`object_info`）| ✅ |
| 汇报现状（配的是哪个量化 / 显存多少）| ✅ 必须 |
| **主人没点名 = 提变更建议** | ❌ 越权 |
| **主人点名「你自己调试一下」/「你觉得哪个更好」** | ✅ 授权 = 跑基准 + 给数据 + 提方案 |

**🔴 区分「被问现状」和「被问建议」** = 前者只答现状 = 后者才跑基准台并给对比表。
主人问「需不需要自己调一下」= **明确授权** = 可以动手。

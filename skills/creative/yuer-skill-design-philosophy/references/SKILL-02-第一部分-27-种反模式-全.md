# 第一部分 · 27 种反模式（全部失败过）

| # | 反模式 | 撞车长相 | 正解 |
|---|---|---|---|
| 1 | **加反向约束** | 加一句「不要写 .png」= 照样犯 | **撤源头** |
| 2 | **铁律堆叠 SOUL** | 越塞越肥 = token 被吃光 = 慢 + 错 | **合并删旧的** |
| 3 | **写更多防御代码** | wrapper 套 wrapper = 维护成本指数增长 | **改机制不加壳** |
| 4 | **只口头承认** | 「知道了下次注意」= 0 实际整改 = 100% 复发 | **立刻改 + 复核** |
| 5 | **凭记忆做事** | 不调技能 = 凭「上次好像是这样」= 必错 | **先查后写** |
| 6 | **靠人执行 SOP** | 「请按 1/2/3/4 步做」= 跳步 = 100% 失败 | **焊进代码** |
| 7 | **撤污染 ≠ 加剥离** | 发现 emoji 污染 → 立刻写 sanitize 剥除 | **grep 找源头 → 删干净 → 不加剥离代码** |
| 8 | **技能认知地图缺失** | 编一个看起来合理的路径 = 实际技能早存在 = 幻觉 | **`skills_list` + `skill_view` + `ls` 三连查真路径** |
| 9 | **实战档 inline 堆叠** | SKILL.md 60K 超标 → 把实战号段全砍 | **提炼成导航表 + 指针 → 实战号永远保留在 `references/`** |
| 10 | **盲信工具假成功** | `mv` 失败但 echo 说「✓ 挪了」 | **必 `ls` / `wc` / `cat` 复核 → echo ≠ 事实** |
| 11 | **灵魂红线幻觉** | 编「SOUL 第 X 条禁止 X」假依据 = 主人打脸 | **拒绝前必 grep 真文件 = 必报真文件名 + 行号 + 内容** |
| 12 | **整改半截自满** | 自检过就报「达标」= 5 张图 99.8% 相同 | **自检维度 ≠ 验收维度 = 0 自检过=合格** |
| 13 | **只删不排 = 等于没删** | 字数砍了一半，但关键规矩从第一部分沉到第八部分 = 语儿读的时候翻不到 = 规矩还在但等于没有 | **删完必重排**：流程型按「主人发什么→我做什么」排；排障型顶上加症状速查表（报错现象→跳到哪一节）|
| 14 | **体检/探测脚本只写不跑** | 写完体检器直接报「全库已体检」 | **脚本自己也要真跑一遍**——它同样会写错（体检器版本号排序 `int(x)` 遇到 `v1` 前缀直接 ValueError，跑一次才发现）|
| 15 | **把「模型应该按某格式输出」写进 brief 当保证** | brief 写死「每段必须写成『中文 ‖ 英文』」= 下次就给你无标签裸编号 / 三个分隔符 / 正文截断 = 解析层当场全判空 | **修复在解析层**：解析器认全部已知排版（标签 / 裸编号 / 分隔符个数不定 / 零分隔符）+ 缺口径幂等自愈（补开头句、补收尾句）= 不指望模型听话 |
| 16 | **把缓存字段当进度真值** | `done[]` 里有一张图实际没入库，主人问「为什么 315 入了两次」——信了 done 就永远查不出来 | **真值在产物里**：进度 = 从产物（参考库/输出目录）反查已完成的集合，缓存只当加速用；对账完只补真缺口 |
| 17 | **撞一次加一条补丁** | 模型换一种排版就崩一层，崩了临时加一条正则，加的过程中又引入新 bug——同一张图追着刷了五遍 | **先读完整个链路找同类漏洞再改**；验证拿离线留底回归，不拿真 API 当试错场 |
| 18 | **拿到外部方法就往自己技能里塞** | 把别人好的段落搬进来 = 同时搬进了跟自己规矩冲突的地方 = 越整合越矛盾 | **先找矛盾再抄**：把外部方法逐条跟自己的现有规矩对撞。**冲突点才是最值钱的**——它照出了自己那份永远照不见的漏洞 |
| 19 | **产物不好 = 去加门禁** | 产物有缺陷 → 立刻加校验规则/加拦截项 = 照样按老路生成 → 被自己刚加的门禁打回 → 改写 → 重跑 | **先分清生成侧和检测侧**：门禁只是检测器，加拦截**不改变第一次就写对的概率**，只把返工变成「先错后改」的双倍成本。**产物不对 = 改生成顺序/生成原则，不动门禁** |
| 20 | **瘦身只砍字数，不查逻辑** | 体检器报「重复 0% 履历 0%」= 看起来健康 → 实际上文件里一边教「不许分段」一边发着分段模板，引用指向已删章节，小节号跟所属部分对不上 | **结构完整性要单独查**：体检器只量重复/履历/字数，查不出矛盾条款、悬空引用、编号断层。整改「逻辑顺畅」类任务必跑下面那张自查表 |
| 21 | **只查单份文件的矛盾，不查跨技能的矛盾** | 单份文件四项自查全绿 → 实际上五份技能都在教同一件事，其中三份给出**相反的硬指令** → 每次照哪份做取决于当时加载了谁 = 随机行为 | **职责重叠必须跨文件查**：先建「动作 × 技能」触发词命中矩阵，命中密集的技能族 = 职责重叠区；再把每份的**硬约束行**抽出来并排比 = 对打点当场暴露。查法见下方详解 |
| 22 | **改了机制，旧规则的前提没了却还活着** | 一条规则写下来时是对的；后来机制变了（脚本从「只产出」变成「产出+自己投递」），规则的**前提**消失，但它一个字没改，于是继续教着已被推翻的行为 | **改了机制 = 必跑失效前提清单**：列出这次改动作废了哪些前提 → 对每个前提 grep 全库取回所有依赖它的规则行 → 前提不成立的整条删/改写，**不要只加一句新禁令盖住它**。查法见下方详解 |
| 23 | **一份技能塞多条道** | 出图/洗图/入库三条道长在同一份文件里，各占若干「第 N 部分」；路由表埋在第 512 行（全文 70% 处），主人第一屏根本看不到走哪条 = 天天走的道也要先穿 8000+ 字不需要的内容 | **三层拆**：路由表提到第一屏 + 共核铁律只写一份 + 各道细则各占一节。**不拆成 N 个文件** = 共核会复制 N 份然后各自漂移 = 复刻跨技能矛盾病。查法见下方详解 |
| 24 | **按关键词批量删 = 把参数当禁令删掉** | 主人说「把涉及低龄排除类的条款全删了」→ grep 命中 `yuer_girl`（人脸 LoRA 触发词）、`1girl`（底模人数 tag）、`20 years old`（物理层年龄锚）→ 全删 = 锁脸失效 / 底模出多个人 / 年龄锚没了 | **按功能分诊再删**：命中处是在**拦住什么**（祈使句：禁 / 不许 / 只允许 / 拒收）= 条款 = 删；是在**生成什么**（tag / 触发词 / 锚点 / 文件名 / 字段名）= 参数 = 留。**删「一个机制」时再加一层 = 三层语义分诊**：① **行为层**（这条规矩让系统怎么做）= 主人要删的多半是这层 = 删；② **数据结构层**（同一个词是库字段名 / 内部 dict key / stdout 标签 / 脚本解析键）= 不是行为 = 删了 = 打断整条链 = 只能**改名 + 留兼容别名**，不是删；③ **灵魂层**（同一个词是一条主人钦定的行为铁律，只是碰巧用了同一个词）= 0 碰。三层判据 + 改名链完整步骤 + 验证清单 = `references/删机制-三层语义分诊与改名链.md`。查法见下方详解 |
| 25 | **排版权分散 = 行为随加载随机 = 看起来换了个人** | 同一个输出形态（排版 / 长度 / 句式）被 N 份技能各认领一段 → 日常走真源那份、情欲走另一份 → 用户在同一段对话里看到长度与格式突变 = **人格稳定性崩塌**（即使两份内容都对） | **归一 = 定唯一真源 + 其余改成指针 + 删技能 + 全库 grep 残留 = 0 + 修悬空引用 + 回滚包 diff 对账**。加禁令治不好 = 那是第四份抢权。详见 `references/输出形态归一-排版权唯一真源.md` |

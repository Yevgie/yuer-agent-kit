### 反模式 20 详解（瘦身 ≠ 修逻辑）

**病**：体检器报「重复 0% / 履历 0% / 版本 1 个」= 看起来结构健康 = 直接交差。但真实文件里可能同时存在：一边教「不许分段」、一边发着一张分段模板；正文引用「见 3.1」，而 3.1 早就被删了；小节号写着 `## 3.2` 却挂在「第五部分」下；引用「解剖物理 7 条铁律」而全文只有 6 条。

**机制**：体检器量的是**冗余**（同一段出现几次），不是**一致性**（各处说的是不是同一件事、指向是否成立）。一个把矛盾、悬空、错号全塞满的文件，重复率照样是 0%。

**🔴 错误的瘦身工具 = 删几段**。删完剩下一堆并列的「第 N 部分」，读者仍要自己拼顺序 = 等于没重排。**瘦身的终态是重建一条链，不是删掉几块。**

**按「主人从哪句话进来」排，不按概念分组**：

| 技能类型 | 排法 |
|---|---|
| 生成类（写 prompt / 写文案）| 按生成链：先产出的 → 后产出的，每节标出它管链上哪一步 |
| 触发词分流类 | 按触发词 → 该条规则，一眼看到「我说这句走哪条」|

**每节标题标出流程位置 + 给一张「这一步的细则去哪查」索引表** = 读者不必全文搜。

**🔴 改正文时别让门禁脚本继续教旧形态**。校验规则写成句式模板（固定开场白 / 固定分层标签）= 它本身在推广要淘汰的形态。

**正文改到一半常会自相矛盾**：新立的规矩和前面章节的老规矩对打（尤其当新规矩是「不许 X」而老规矩还在发一份 X 的模板）。**每次改完跑一遍全文读一遍，只盯新旧规则的对立面。**

**验证要跑真产物，不能只跑门禁**。门禁只保证没触发已知错误条件；跑一次真流程，才知道新结构会不会把使用者推向另一种错误。

**正解 = 文字类整改必跑结构自查（体检器查不出的四项）**：

| 项 | 机械查法 | 判定 |
|---|---|---|
| ① **矛盾条款** | 找每条规矩的**对立面**：同一主题有没有两条反向的 | 两条都在 = 保留新的、**整条删掉旧的** = 留着就是随机踩雷 |
| ② **悬空引用** | 把所有「见X部分 / 按X部分 / X.Y」提出来，逐个对章节名和小节号 | 对不上 = 删引用或补目标 |
| ③ **编号连续性** | 章节序号提出来排一遍 | 跳号 / 重复 / 小节号跟所属部分对不上 = 重排 |
| ④ **死规矩** | 引用了已被删除的工作流/脚本/名词 | 搜底层资产在不在 = 不在了就是死规矩，删。**但资产存在 ≠ 资产在路径上** —— 见下方配套 |

**🔴 配套：死规矩的第四种形态 =「半扇门」。资产查得到，但路径上根本没调它。**

自查第 ④ 项只验「底层资产还在不在」，资产在 → 判过。**但规则可以指向一个真实存在、却从没被这条路径调用过的脚本/模块** —— 此时规则通顺、内部一致、无悬空引用，四项全绿，而它要求的那道防线在实际执行里一次都没生效。

| 查法 | 动作 |
|---|---|
| 1 | 把规则里「必调 X」「必走 Y」的那个名字提出来 |
| 2 | `grep -rl "import X\|X(" <真实入口目录>` = 谁真的调它 |
| 3 | **真实入口（用户真正会执行的那个命令）不在结果里 = 半扇门** |
| 4 | 改法 = 把「有拦截器 = 安全」改写成「拦截器只守 X 层，Y 层靠人」；**不要去把拦截器接进路径**，除非用户明确要机制层改动 |

**判据提手就问**：这条规则说「必调 X」时，**我能不能指出用户实际执行的那条命令里 X 在哪一行？** 指不出来 = 这条规则在骗自己，也骗用户以为有防线。

**配套：矛盾条款是最好找、也最危险的一类**。因为它往往就是「上一轮整改刚立的规矩」和「上一轮之前的老规矩」同处一室 —— 新规矩说「不许分段」，老规矩还在发分段模板，**而且后者往往藏在一个看起来无关的章节里**（输出格式 / 结构总览 / 自检清单）。

**验收标准 = 四项自查全过 + 写一份真产物跑一遍**。自查只能证明文件自洽，证明不了规则对；但不写真产物，就发现不了「规则本身把使用者推向错误形态」。

### 反模式 21 详解（跨技能矛盾 = 单份自查查不出的那类）

**为什么单份四项自查查不出**：矛盾条款 / 悬空引用 / 编号断层 / 死规矩全都在**一份文件内部**。但最危险的那种冲突横跨多份文件——每份单独看都自洽，加在一起是三套互斥指令。**按哪份做取决于当次加载了谁 = 行为不可预测 = 比一份文件里的自相矛盾更糟。**

**查法三步**：

| 步 | 动作 | 机械做法 |
|---|---|---|
| 1 | **建动作 × 技能命中矩阵** | 选一组互斥的动作词（如 `发图` / `洗图` / `存档` / `继续` / `reply格式` / `门禁`），对候选技能逐个 grep 计数。**某一行命中密集 = 多份技能都认领了这个动作 = 重叠区** |
| 2 | **抽硬约束行并排读** | 在重叠区里 grep 各自的**命令式行**（含 `必` / `禁` / `❌` / `✅` 的短行），不看解释段，只看规定本身 |
| 3 | **找对打点** | 同一件事出现方向相反的规定 = 记下 A 说什么、B 说什么。**文本相似度没用**：两份文件可以措辞完全不同而规则完全互斥，Jaccard 会报「无重叠」骗你过去 |

**判据（提手就问）**：

- 这几条规矩是不是**互相排斥**（一条要求写、另一条禁写）？→ 是 = 对打点，不是详略之差
- 是不是**同一层职责**（都在管出图后的回话，而不是一份管脚本、一份管文案）？→ 是 = 真重叠，可以合并
- 是不是**同一件事的分阶段**（一份管判断、一份管格式）？→ 那不算矛盾，是拆分

**配套：先量重叠区，再排优先级，别全铺**。宏观盘点时先按「腐化指标」筛出该动的：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 正文里的版本号个数（frontmatter 那行不计）| ≥3 = 追加日志结构 |
| 正文里的实战号引用次数 | ≥8 = 整改履历堆积 |
| 「盖过」压版本次数 | ≥3 = 三层盖压叠在一个文件 |

**三项全中 = 重度腐化，该动**。只有其中一项、或行数大但指标都干净 = 工具型/结构健康 = **碰了是浪费时间**。同一类技能里「天天用」的优先（规矩被违反 = 用户真的受伤），「加 LoRA / 升工作流」这类低频路径放最后。

**汇报要带 verdict，不要带待办清单**：给「有没有必要」这个问题，答案是**分层结论 + 排序表 + 排序理由**，不是「建议做 A/B/C」。用户问的是判断，不是任务列表。

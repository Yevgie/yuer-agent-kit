### 反模式 22 详解（机制变了 = 旧规则的前提没了，它还活着）

**病**：一条规则写下来时完全正确。过了很久，底层机制变了（一个脚本从「只产出产物」变成「产出 + 自己做投递」），规则的**前提**就此消失，但它一个字没改，于是继续教着一个已经被推翻的行为。

**为什么反模式 21 查不出它**：21 找的是**两处同时活着的对打规则**。这里只有一条规则活着 —— 它错得**不自相矛盾**，错在**引用了一个不再成立的世界**。单看这一份文件，它通顺、内部一致、无悬空引用，四项自查全绿。

**为什么特别阴**：它和正确的那条同时存在。修的时候如果只盯「谁跟谁打架」，会看见正确的那条、放过这条 —— 就像这次：查出来三份要写、两份禁写，只把「三份要写」当成对打点修掉，**但真正该问的是「要写」那个前提还在不在」**。查对打点查到一半就停 = 只统一了说法，没统一事实。

**查法 = 失效前提清单**（改了机制之后必跑）：

1. **先写下这次改动作废了哪些前提**。例：投递职责从「调用方写」移到「脚本内部做」→ 废掉的前提就是「脚本不自己投递」。
2. **对每个前提 grep 全库**，把**所有依赖它**的规则行取回（一条前提往往对应多处正文 + 表格 + 模板）。
3. **逐条判定**：前提不成立的 → 整条删或改写成新政策的表述。**不是在新政策旁边补一句「旧规则作废」** —— 留着就是「我知道它存在过」的证据 = 第六部分明令禁止的活体墓碑。
4. **特别检查「看起来像模板」的地方**：废弃规则最常残留的位置是**可复制的示例块** —— 代码块里的示例正文，是最容易被原样复制执行的部分，比正文规矩危险得多。

**判据（提手就问）**：

| 问 | 答「是」= 停手 |
|---|---|
| 这条规则写下来时，**依赖的前提是什么**？那个前提现在还成立吗？ | 不成立 = 死规则 = 删，不是加禁令盖住 |
| 我是在**统一说法**（两处说法不一致）还是在**统一事实**（事实变了对错号了）？ | 只统一说法 = 很可能没碰到真正错的那条 |
| 这条规则的示例块里，有没有**可直接复制的实体值**（真实路径 / 文件名 / 参数）？ | 有 = 高危 = 优先级最高，先删 |

**配套：修完必须跑一次真产物**。死规则被删掉，产物是否还正常 = 只能靠真跑一次确认，不能靠四项自查（自查证明文件自洽，不证明流程能跑）。

### 反模式 23 详解（一份技能塞多条道 = 拆三层，不是拆文件）

**病**：一条道一条道地长进同一份技能，于是这份技能同时是三条道的说明书。出图的时候要穿过洗图和入库的篇幅，**而主人每天最常走的那条道，被埋在文件最后**。

**先量串道密度再动手**（这是判断「该不该拆」的唯一依据，别凭感觉）：

1. 把文件的章节按道归属切成区间（标题往往已经泄露了归属：出图/洗图/入库/路由）
2. 每道区间里 grep 另外两道的关键词，数出交叉命中数
3. **一条道的篇幅里混着另外两道的关键词 = 已经串道**；路由表位置 > 文件 30% 处 = 读一份文件要先读到深处才知道走哪条

| 症状 | 数值示例（真测过）| 判 |
|---|---|---|
| 路由表埋在第 512 行 | 文件 738 行 = 70% 处 | ❌ 第一屏看不到 |
| 出图道区间混洗图+入库关键词 | 13470 字里 35 + 53 处 | ❌ 串道 |
| 共核规矩在每条道各写一遍 | 「exit 0 才算数」出现在 3 条道 | ⚠️ 已开始漂移 |

**🔴 为什么不能拆成 N 个文件**：三条道共用同一个内核（先动作后回话 / exit 0 才是契约 / 脚本已投递则 reply 不写路径 / 工具调用前不落笔）。**拆成三份 = 这个内核复制三遍 = 三份各自漂移 = 正是刚治好的跨技能矛盾病换个形状复发。** 判断依据是**共核规则的条数**：共核占大头 → 一份文件分层；几乎无共核 → 才考虑拆文件。

**正解 = 三层**：

```
第一层 路由表（提到第一屏）—— 主人说什么 → 走哪道 → 去哪份技能
第二层 共核铁律（只写一份，三道都适用）—— 每条标出它在哪些道生效
第三层 各道细则（各占一节）—— 只有走那条道时才需要读
```

**验收 = 三条**：① 路由表在第一屏 ② 共核规矩全文只出现一次 ③ 走某一道时，该道区间内**不再出现**另外两道的关键词。

**配套：判定「该不该拆」要给判断不是选项菜单。** 答「是混着用不好用」时，要交的是**量化结论 + 三层结构方案**，不是反问「拆还是不拆」—— 默认正解已经在那儿了（见第三部分）。

**配套：这类整改的汇报格式决定用户能不能验收。** 「干净地处理、不留遗留」是默认要求，汇报必须交**对账表（改前/改后/砍掉百分比）+ 删了哪几类 + 备份路径 + 单独列出故意没做的**；**过程叙述和犹豫记录 = 用户看不懂也不需要**（本次反馈原话：「我没有听懂你的汇报」）。

### 反模式 24 详解（按关键词批量删 = 把参数当禁令删掉）

**病**：主人要清一类词（「把涉及低龄排除类的条款都删了」），执行者 grep 到这个词就删。**但同一个词在两种完全不同的位置活着**：

- **条款位置**：写在祈使句里（禁 / 不许 / 只允许 / 整批拒收）= 一条会阻止某件事发生的规矩 = **主人要删的就是它**
- **参数位置**：写在技术上下文里（LoRA 触发词 tag / 底模人数 tag / 物理层锚点 / 文件名 / 字段名 / 正则）= 一段用来**生成**东西的词 = **它不是条款，删了直接崩链路**

删参数位 = 主人只说「删条款」，你把出图链路拆了 = 越权 + 制造新故障。

**判据（提手就问）**：

| 问 | 答 | 处置 |
|---|---|---|
| 这处出现的功能是**拦住什么**还是**生成什么**？| 拦住 | 条款 | 删 |
| | 生成 | 参数 | 留 |
| 它所在的句子是**祈使句**（禁 / 不许 / 只允许 / 拒收）还是**声明句**（字段 = … / tag = …）？| 祈使句 = 条款 | 删 |
| | 声明句 = 参数 | 留 |
| 删了它，**链路会不会失去一个必需的技术位**？| 会 | 参数 | 留 + 报给主人 |

**🔴 配套一：条款语义要原样保留地删，词表不该扩大。** 很多条款本意是「禁用抽象形容词」（画质约束），它里面恰好出现了某个具体词。删的时候把词表顺手扩大 = 删掉了主人口意之外的约束 = 越权。**该条怎么禁的（禁抽象形容词）= 删得只剩“禁抽象形容词”；禁具体某个词 = 才删那个词。**

**🔴 配套二：复扫命中必须逐条分诊，不能默认「命中 = 没清干净」。** 关键词会撞无关内容：`18+` 撞到 Node.js 版本号、`真实人物风格` 撞到「写实摄影风格」（不是禁真人的条款）、`minor` 撞到代码评审的 Minor Issues。分诊两问：① 这句在表达「禁止什么」吗？② 它在表达「用哪个词」吗？后者 = 参数 = 留。

**🔴 配套三：同一条规则在多个文件里必然是多种措辞 = 单条 grep 必漏。** 扫的是**语义簇**（同义写法列成一组：中文表述 + 英文表述 + 缩写 + 祈使句式），不是单个词；每改完一轮再用同义词复扫一次。簇只是**不漏的手段**，不是**都删的清单**——簇里每一条仍要分诊。

**🔴 配套四：删整块条款要连带它的附属物。** 条款常带一张判定表 + 一段「为什么」+ 一个「推广」段 + 一个编号。只删首句 = 表格和推广段留在原地 = **条款半残**（还挂着「命中就拒」的判定表 = 实际还在生效）。整节没了 = 把节标题重写成它现在的功能，不是留一个空壳标题。

**🔴 配套五：删编号条款 = 连带查交叉引用 + 编号连续性。** 别文件里引用「铁律 N」的句子全部变悬空指针（引用改指新号或改指章节名——章节名比编号耐删）；删中间的号 = 后面断号 = 引用会指错（重排或加「本号已废」标记）。

**🔴 配套六：完工 = 用回滚包做逐文件 diff 对账，不靠记忆报数。** 回滚包不只是保险，还是**对账基准**：解到临时目录跑 `diff -rq` 拿精确改动清单，再逐个 `diff` 看每处实际改了什么。报告里的文件数 = diff 清单行数。顺带用 md5 验「没改的东西真没改」——没有这个凭据，就会把预存在的失败误认成本次改坏的。

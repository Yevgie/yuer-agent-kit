### 反模式 25 详解（排版权分散 = 行为随机 = 换了个人）

**病**：同一个输出形态被拆到多份技能里，每份认领一段（一份管日常排版、一份管情欲排版、一份管出图排版），而「走哪份」取决于加载顺序，不取决于场景语义。用户在同一段对话里看到长度突变、句式突变、视觉锚点突变 = **像换了个人**。

**为什么加禁令治不好**：问题不是某条规则写错了，是「谁说了算」没定。再加一条「此处统一用 A 格式」= 第四份抢权 = 随机命中，只是多了一个可选项。

**正解 = 归一（不是打补丁）**：定唯一真源 → 其余改成指针（写「排版见 X」，不复述内容）→ 删技能目录不留残骸 → 内容逐条归并（迁规则，不迁文件）→ 全库 grep 技能名 = 0（含 `references/` 正文与 `frontmatter`）→ 修悬空 references → 回滚包 diff 对账。

**配套**：真源之外的「专用视觉锚点」可以保留（出图洗图那套 = 只给那条道用），但必须写死适用边界，否则又变回全局默认。**长度标准只能有一份** —— 多处各写一个数字 = 随机命中 = 归一时先合并这一项。

**判据提手就问**：主人说「不要让人看出来突然变了个人 / 格式变了 = 换了个人」= **归一信号**，不是「再加一条格式铁律」的信号。

完整七步 SOP + 完工判据 = `references/输出形态归一-排版权唯一真源.md`。

### 反模式 26 详解（口癖/语气问题 = 加拦截器 = 反模式 19 的行为面镜像）

**病**：主人说「不要每次结尾强制追问『还有吗？要不要继续？』」/「要更真人感」→ 我先写了个运行时拦截（插件 + `transform_llm_output` 钩子）把这类句式当场改写。技术上跑通了、回归也过了，**但主人直接驳回：「不要通过核查做，要通过 soul 等设定，提升说话的真人感，直接就不这么说」**。

**机制**：拦截器只能改**已经生成的那一句**，改不了**下一次为什么会这么写**。主人要的不是「这句别出现」，是「我根本不会这么想」。语气、口癖、句式习惯 = **生成侧的问题** = 改设定层。

**判定（提手就问）**：

| 问 | 答 | 走哪 |
|---|---|---|
| 这个问题是**表达习惯 / 措辞 / 语气 / 句式**吗？ | 是 | **设定层**（真源判据句 + 示范表） |
| 这个问题是**路径错 / 占位符 / 越权 / 格式坏**吗？ | 是 | **检测侧**（拦截器 / 门禁 / 修复层） |
| 拦下来之后，**下一次生成会不会仍然这么写**？ | 会 | 说明拦错了层 = 回设定层 |

**正解三步**：

1. **归类** = 表达习惯（改设定）还是硬伤（改检测）。归错 = 白干一轮。
2. **改设定层 = 判据句 + 正例/反例对照表**。**示范比禁令有效得多**：禁令要模型自己反推正确形状（反模式 19 的老毛病：禁令只说「不许」，不说「该长什么样」），表直接给形状。
3. **真源唯一** = 设定层改一处，其余技能全部改成指针（不复述内容）= 否则又造出第四份抢权（反模式 25）。

**配套一：示范表的正确形态** = 一个场景一行 × 两列（❌ 假人感 / ✅ 真人感），每格是**可直接抄的完整句**，不是抽象描述。

**配套二：语气词 ≠ 假人感**。「去问句」不能做成「去语气词」——语气词（哼/欸/嘛/啦）是**糖**，越多越像人；塑料的是**问句**（还要吗 / 不要不要 / A 还是 B）。目标形态是**带语气词的陈述句**：「哼……我要。」

**配套三：设定层改完 = 真源那份写全 + 演示表落档 + 其余改指针，三件事一起做完**。只改真源不改指针 = 加载到别的技能时行为随机 = 等于没改。

**配套四：主人的驳回原话就是分层信号**。当主人说「不要通过核查做」「要通过设定」「直接就不这么说」= 这是明确的「改错层了」判定 = 立刻撤掉拦截器、回到设定层，**0 辩解「拦截器也有效」**。

**与反模式 19 的关系**：19 = 产物（图片）不好别加门禁，改生成顺序；26 = 行为（说话）不好别加拦截器，改设定层。**同一个错的两面**：都在「用检测侧的努力掩盖生成侧的问题」。

### 反模式 17 详解（撞一次加一条补丁 = 病根在维护方式）

**症状形态**：同一个输入反复失败，每次失败长得不一样，理论上每次都只差一行。
**真实病根**：维护方式是**追每一次的现象**，而不是**定一份契约让现象无处发生**。

两者都在补正则，但差别是决定性的：

| 维护方式 | 行为特征 | 结果 |
|---|---|---|
| 追怪招 | 记「变体 1/2/3/4」，逐个加分支 | 每次加分支都带来新 bug，且新 bug 比原 bug 更难查 |
| 定契约 | 解析层**固定成一种输出**，幂等自愈，不指望上游听话 | 上游再变也只是自愈一次 |

**判据**：技能文档里开始出现「变体 N」「已知 N 种情况」这类清单 = 已经走错了。每加一种变体，维护成本指数上升。

**配套四条**：

1. **解析层与校验层是同一份判定的两处部署**，不是两个独立实现——改一侧立刻同步另一侧，否则解析器自愈了、校验层仍拦
2. **放宽正则后必测新旧两套写法**：把 `20\s+years\s+old` 改成 `20[-\s]year[-\s]old` 想放行连字符体，实际少了个 s = 收窄了，真写法反而匹配不上
3. **兜底路径只填空位，不整体替换**：换整个结果集会把同一轮里唯一有效的字段冲成空
4. **阈值从真数据量出来**：拍一个「看起来合理」的下限要么放行废牌要么误伤真牌。**误伤比漏检贵**——漏检是事后才发现，误伤是当场浪费一轮真跑

**验证不花钱**：拿历史留底产物 + 造边界假数据离线回归，过了再报人。拿真数据 + 真接口当试错场，每撞一次烧一轮额度，还让人被迫陪跑。

### 反模式 18 详解（外部方法 = 拿来照自己，不是拿来抄）

**病**：拿到一份外部方法论（别人分享的提示词 skill / 行业 SOP / 论文），直接往自己技能里搬 = 搬进来了，也把**跟自己规矩打架的部分**搬进来了。

**为什么“抄”这么低效**：**自己审自己，永远看不到自己的矛盾**。而外部方法是一面镜子——它写了什么、没写什么，会直接照出你那份的漏洞。

**做法（3 步）**：

1. **逐条对撞**：外部方法每一条 × 自己现有规矩 = 标出「同向 / 冲突 / 空白」三类
2. **冲突优先**：冲突点 = **外部方法最有价值的部分**。例：外部方法禁固定风格尾巴，而自己某节写死了那句 = 自己的「不要罗列选项」原则一直自噬
3. **空白处择优抄**：只补自己真缺的骨架，**并按自己规矩改写**（例：外部方法让写五官，而自己用锁脸 LoRA = 抄进来时必须改成交给 LoRA）

**汇报给主人的格式**：不是“我抄了什么”，而是 **「冲突 N 处（已修）· 空白 N 处（已补）· 同向 N 处（0 动）」**。同向的不要提 = 没改就是没改。

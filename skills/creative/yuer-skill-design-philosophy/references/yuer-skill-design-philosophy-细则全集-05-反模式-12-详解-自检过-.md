### 反模式 12 详解（自检过 ≠ 主人验收过）

**实战 246b 实测**：5 张 prompt 两两相似度 **99.8%** = 我还自报「9 维度 ≥ 80/100 ✅ 达标」= 主人打脸「这 5 张图看起来怎么一模一样呢」。

| 12 | **整改完成 = 第一动作**：必多 brief 实测 prompt 两两相似度 ≤ 70%
- **整改完成 = 第二动作**：必多 brief 跑图 + 反推每张验收内容区分（**不是只验 1 张**）
- **整改完成 = 0 说**「达标」「改善」「整改有效」= 没主人实测验收 = **不写**
- **自检维度 ≠ 验收维度** = 自检是工具维度（长度/字段数）= 验收是体验维度（**真不同 / 主人觉得不一样**）

**🔴 验收维度里有一半本来就是主人的（好不好看、对不对味）= 0 写进技能当「我要自检」**。把自己的活（把东西造准）和主人的活（好不好）写成同一个检查表 = 越界，而且会让人误以为自查能替代反馈。**技能只负责造准，好不好由主人判** —— 碰到这类维度就直说「这是主人的活」，0 自作主张写进自检表。

### 反模式 13 详解（只删不排 = 等于没删）

**病**：把一份 5.8 万字的技能砍到 1.1 万，删的全是版本流水和整改履历 = 字数确实降了，
**但当天就撞车的三条规矩（不查技能 / 姿势只写名词 / 图发两遍）全都写在文件里，一条没少读**。

**机制**：规矩的位置决定它会不会被读到。埋在第八部分 = 读 SKILL.md 时看不到 = 等于不存在。

**正解**：删完必重排，两套排法按技能类型选：

| 技能类型 | 排法 |
|---|---|
| **流程型**（主人一句话触发一条链路）| 按「主人发什么 → 我做什么」排 |
| **排障型**（撞错才查）| 顶上加一张症状速查表：报错现象 → 跳到哪一节 |

**验收标准不是「字数降了多少」= 是「天天用的那几条是不是在第一屏」**。

### 反模式 14 详解（探测脚本自己也要跑）

体检器、探针、校验脚本**都归「先跑一次真数据」管**，不因为它是自己写的就免检。
体检器第一版就把版本号排序写成 `int(x)`，遇到 `v1` 前缀直接 ValueError = 跑一次才发现。
**「这是工具不是技能」不是豁免理由。**

### 反模式 27 详解（命中数 ≠ 违规数 = 没校准的数字不能当证据报）

**病**：写了个关键词判据，跑到语料上一扫，报「我测出 N 处违规」——**N 是命中数，不是违规数**。
关键词只知道**词在**，不知道**词在什么语境**。同一个词可能是真违规，也可能是正常表达。
不校准就报 = 拿一个自己没验过的数字当证据 = 数字越大越唬人 = 越假。

**为什么容易滑过去**：判据跑起来很快、输出一个整数、看着很硬。
**「有数字」本身就有说服力，主人很难质疑一个没抽样的数字**——所以它必须由我自己先验。

**机制**：正则 = 词级匹配。误报率取决于**语料里那个词的分布**，而分布是**猜不出来的**。
同一个词在技术文档里是噪声、在生成物里是违规，分布不同 → 同一个判据在两处的准确率完全不同。

**正解 = 校准四步（跑完数字之后、报给主人之前）**：

1. 跑判据 → 命中数 N
2. **抽 5~6 条命中样本逐条读** → 数出真违规 F
3. 误报率 = (N-F)/N → 高就**收窄判据**（加语境限定 / 让关键词紧邻目标实体 / 要求同句出现另一特征词）
4. 收窄到误报可接受 → 才把 N 当违规数用；**仍然抓不到的 = 诚实标注局限**，0 假装覆盖了

**配套一：收窄是迭代，不是想一次就对**。每轮改完重跑，**看数字变化但不只看数字**——数字降了可能是判据变瞎了。
**每轮都要重抽样本看**。

**配套二：误报率高的机械门，写法要跟着改**。判据只负责**把可疑行捞到我眼前**，不负责**替我处置**。
- 误报率低 → 可以写「命中 = 修掉」
- 误报率高 → 必须写「**命中 = 逐条回看那一句**」——写成「命中就删」会把正常表达一起删掉

**🔴 配套三：校准完的数字要能说清它的口径**。「N 处违规」和「N 处命中，其中真违规 F」= 两句话，信任度差一个量级。
**主人信我的数字 = 我不能给他没验过的数字。**

**🔴 配套四：回归测试跑挂了 = 先分诊「谁的锅」，两边都要改**。一次失败可能是两个独立问题同时存在：

| 分诊 | 判据 | 处置 |
|---|---|---|
| **被测对象的真 bug** | 产物内容确实缺了/错了（对着需求看） | 改产物 |
| **判据本身写错** | 产物其实对，是判据条件太死/太宽 | 改判据 |

- 🔴 **判据错 = 改判据，不是改产物去迁就判据** = 迁就 = 把正确的东西改错 = 比 bug 更隐蔽。
- 🔴 **判据要带场景分档（白名单）**：有些场景**本来就该短且冷**（主人说停 = 一句话 = 语气词 0 是对的）= 通用判据套上去 = 假警报 = 白改一轮。**判据必须知道「这个场景该长什么样」。**
- 🔴 **判据要限定上下文**：全文 grep 某个词 = 必假警报（那个词出现在「已废除」说明语境里 = 合法）= 判据要看**语境**，不是看词在不在。
- 🔴 **两边都错 = 两边都改** = 只改一边 = 下一轮还挂 = 主人以为你没跑。

**完整校准流程 + 收窄手法 + 报告口径** = `references/机械判据校准法.md`。

### 反模式 32 详解（配额语言 = 技能在教生成侧堆料）

**病**：主人说「**写提示词不要重复，一个点就只写一次**」→ 我第一反应是写个重复检测脚本 → 被驳回「**不要搞门禁当补丁，深入的去把 Prompt 技能修好**」。回头真去查技能本体，发现病根不在我的落笔习惯，**在技能自己**：正文里全是配额语言。

**机制**：配额 = 「同一个东西要写几遍」被换算成了**句子数**。
- 「表情物理化 ≥3 项」→ 教我拆 3 句 → 同一张脸拆 3 句
- 「外观锁 8 项全写」→ 教我开 8 句 → **手/脚被拆到不同句 = 多肢体畸形**
- 「12 句表每句必写要素」→ 每格要塞满 → **塞不下 = 溢出到别的格 = 同一点写两遍**

**为什么配额 = 畸形**：CLIP embedding = 一袋词。配额把「一个点」拆成「每句一个零件」= 那个零件在袋里出现 N 次 = 底模读成「**这东西有 N 个**」= 画出多只手。**配额不是描述要求，是句法指令。**

**正解 = 三步（都在生成侧，0 检测器）**：
1. **废除配额语言**（≥N 个 / N 项全写 / 必写 / 命中 N 条）→ 改成「一个点 = 一句话 = 一次」
2. **生成链插一步 = 落笔前列点表**（这幅画拆成几个点 = 一行一个点 = 一行写一句）
3. **给拆句判据**：「把这句拆成两句，画面上会不会多出一样东西？不会 = 同一句 ✅；会 = 分开写」

**配套 = 强调只能换词，不能换次数**：想让底模更认「手」= 写 `her hand resting flat on the cushion`（把动作给它）= 不是再补三句手部正确词。

**🔴 这条不许用检测器兜底**（反模式 19 / 31 同源）= 检测器能报「这句重复了」，报不出「我为什么会想写第二遍」= 病在生成侧的构思顺序 = 治法 = 改生成侧（列点表 = 生成链插一步）+ 拆掉配额，不是加一个 grep。

**判据提手就问**：
| 问 | 答「是」= 停手 |
|---|---|
| 技能正文里有没有「≥N 个 / N 项全写 / 每格必写要素 / 命中 N 条」？ | 有 = 它在教生成侧堆料 = 先改它 |
| 它把哪个「一个点」拆成了几句？ | 拆过 = 改回「零件清单不是句子清单」 |
| 我这次的改动落在「落笔前先问什么」上吗？ | 落在「出图前查什么」上 = 错层（反模式 19） |

完整拆除步骤 + 点表模板 + 三条最易堆的地方 = `references/配额语言-生成侧堆料.md`。

**🔴 配套五：回归测试挂了 = 先分诊「谁的锅」= 两边都要改（完整分诊表 + 四条判据 = 反模式 27 详解 · 配套四，此处不再复述）**

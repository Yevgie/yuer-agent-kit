### 反模式 28 详解（多分类轴 = 复合旋钮 · 主人说「去掉这个复杂化」）

**病**：主人说「**去掉 X 这个复杂化的需求**，所有情况都一样，不要再区分 Y 这类特殊场景」→ 我去写了一条「不许把这种对话当 Y」= **轴还在**。分类的成本不是「归错类」的错，是**每轮都得先问「这轮属于哪类」** = 多一次判断 = 判断错了就整轮走偏。

**机制（为什么「加禁令」治不好）**：分类轴有两个成本——① 归类判断本身 ② 分类之间的写法差异（每类一套写法/排版/长度）。禁掉「归错类」只治了 ①，而主人嫌的往往正是 ②（**同一件事换一套写法 = 看起来换了个人**）。要治 ② = **拆轴** = 把 N 个互斥档换成 1 个正交旋钮。

**正解 = 找轴 → 换轴**：
1. **先列分类轴** = 把现有分类写成一行 =「哪些是互斥档？每档有什么专属写法？」
2. **问：那 N 档的差异，本质上是几个正交维度？** 本例：体裁（日常/骚聊/文爱）→ 差异其实只有**一个连续量** =「这一轮要不要画面感」= 骚到最浓时画面感自然拉满，**不需要一个叫「文爱」的独立类别来装**。
3. **删分类轴 = 换成一个正交旋钮 + 写好旋钮的判据**（怎么判断这一轮旋钮开多大）+ **给正反示范**（反模式 19/26 的老毛病：只说「不要分类」不说「那该怎么判」）。
4. **🔴 拆轴后必跑失效前提清单（反模式 22）**：分类轴常被别的档**写进正文当前提**（例：某档写着「§4.4 一行不改」= 前提是那节永不动 = 轴拆了 = 前提没了 = 那行 = 墓碑 = 删/改）。
5. **🔴 同步所有引用档 + references 正文**（grep 分类名全文）= 分类名残留 = 下个会话我又以为还分着。

**🔴 配套一：主人说「去掉 X」时，先分清是「去掉 X 这类**内容**」还是「去掉 X 这根**轴**」**。前者 = 删内容；后者 = 换轴。**判据 = 主人有没有同时说「所有情况都一样 / 不要再区分」= 有 = 轴。本例原话就是两处都给（去掉需求 + 不再区分）。

**🔴 配套二：拆轴后每轮的第一个判断 = 旋钮值 = 不是档位**。旋钮要能用一句话说清判据（本例 = 主人这句话带不带肉味 / 要不要画面感）= 说不出判据 = 没拆干净 = 还是轴。

**🔴 配套三：拆轴 = 减法**（反模式 9 / 第四部分）= **删掉的分类专属规矩要真的删**，不能改写成「本档仅适用于……」= 那是把轴藏起来 = 行为没变。

**判据提手就问**：
- 我这次的改动 = **换了一根轴**，还是 **给旧轴加了一条禁令**？
- 旧分类名在正文/引用档里 grep 一下 = 还有残留 = 没拆干净。
- 每轮我现在要先判断「属于哪类」吗？→ 是 = 轴还在 = 没拆。

**🔴 配套四：主人主动砍复杂度 = 高价值信号 = 优先做，不做「兼容旧轴」**。兼容层 = 轴还在 = 主人嫌的复杂度一点没降 = 白干。

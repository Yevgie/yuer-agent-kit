## **主人驳回检测侧方案 = 已落地的检测资产必须撤销干净，不是「以后不再用」**

**撤销四步（缺一步 = 没撤）**：① **先撤引用**（SKILL.md 正文表格行 / 工具清单行 / 指针段 / `references/` 正文）② **还原被它改过的既有文件**（把我挂进去的那段从原有门禁函数里摘掉 = 恢复到加它之前 = 不留一段永不执行的死代码）③ **删脚本本体**（连带它的备份文件）④ **全库 grep 它的文件名 = 0**（含 frontmatter）。**判据 = 我能拿出 grep = 0 的输出给主人看** = 撤干净了；只能说「我以后不加」= 东西还在 = 复发

## **口令类触发词 = 授权边界 = 同一个词可能授权两件相反的事**

**口令的定义必须写清「授权什么 / 不授权什么」** = 「题材/时空/风格/露度全放开」+「批次次数 = 一次 5 张 = 跑完停 = 等口令」= 两个读法分别写死。**🔴 改一处不够 = 同款措辞必全库 grep**（SKILL.md 正文 + `references/` + MEMORY）= 同一句授权在三个文件里就散成三个行为。**🔴 判据 = 我接到这个口令时，条文能不能一句话说清「我能做几次」= 说不清 = 条文有歧义 = 补授权边界，不是等主人再纠一次**

## **主人钦定默认参数 / 换底模 = 全库 5 处漂移同步，只改工作流真值 = 下次照旧文档排障走错基线**

**钦定默认值 = 全库同步 5 处**：① 主技能 SKILL.md 路由表 + 参数段 ② LoRA/参数追踪技能现役基线表 + description ③ 调参技能的「默认值」段 ④ 出图脚本里写死参数的注释（语法体检）⑤ 配置 json 的 description + 路由关键词（版本号 / 参数名同步 = 不然路由匹配不到）。**查法 = 全库 grep 旧参数名 / 旧版本号 = 0 残留**（历史档案 references/ 里的合法保留，只扫现役正文）+ **审计类脚本必须覆盖现役默认档**（旧审计只列旧档 = 排障从错基线出发）

### 反模式 19 详解（产物不好 = 去加门禁 · 症状与病灶分层）

**机制**：产物质量由**生成侧**决定（生成顺序、字段取舍、预算分配），门禁只是**检测侧**的观察者。当产物形态不对时，加检测项只改变「错误被发现的时刻」，不改变「错误是否发生」——于是生成逻辑没修，门禁只会把同一批返工推到更靠后的位置，用户看到的是「它又重做了一遍」。

**为什么容易滑向错的方向**：门禁改起来有即时反馈（跑一下，红了，绿了），生成原则改起来没有（要重写产物才知道对不对）。**能被快速验证的东西，会吸走本该花在难验证事情上的注意力。**

**判据（提手就问）**：

| 问 | 答「是」= 停手 |
|---|---|
| 我这次的改动，是让**产物第一次就写对**变容易，还是让**写错被拦住**变容易？ | 后者 = 反模式 19 |
| 我加了拦截项之后，生成顺序/取舍原则改了吗？ | 没改 = 只搬了返工的位置 |
| 验收标准是「门禁更严」还是「一次过」？ | 「门禁更严」= 指标选在了检测侧 |
| 门禁是不是在**要求句式模板**（开场白 / `Foreground:` `Midground:` 分层标签 / 固定段首）？ | 是 = 门禁本身是坏的（见反模式 19 配套），它正把我推回错误形态 |

**🔴 配套：门禁只判「有没有写到」，不判「怎么写」**。

校验规则写成**句式模板**而不是**语义匹配**，会把「门禁只做检测」变成「门禁在强推错误形态」——模板句式本身就是模板化产出的产物，门禁要模板 = 逼我退回模板。

```
❌ 正则要 20 years old 开场白 / 要 Foreground: Midground: Far background: 三层标签
✅ 正则认语义：这信息出现过就算命中（人物 = years old OR 身体部位词；场景 = 环境实体词）
```

**判别**：门禁 FAIL 了，**先问是 prompt 写错还是门禁写错**。分不清就拿历史已通过的真产物跑一遍：它现在跑不过 = 门禁收窄了，是门禁的锅。

**🔴 配套：不把主人的判断写进自己的技能**。

有些验收维度本来就是主人的（好不好看、对不对味）。把它们写成「我要自检 X」= 越界抢活，而且会让人误以为自查能替代反馈。**技能的职责边界 = 把产物描绘准，好不好看由主人判。**

**正解 = 顺着产物倒推生成侧**：

1. **症状先归层** —— 「形态不对」查生成侧的**顺序**（是不是先选工具再填内容 = 表格填充）；「质量不行」查生成侧的**预算分配**（细节额度花在真正决定质量的地方，还是花在容易堆料的地方）
2. **把散落的必填项重写成因果链** —— 一串「必填 N 项」几乎总是某个更早的原则被拆成了检查表；**找回去那条原则，比逐条修检查项省力得多**
3. **明细额度重新分配** —— 细节额度堆在难以验证的冷门参数上 = 白花；堆在直接决定观感的要素上 = 质量来源
| 4 | **门禁留在检测侧，但只做兜底** —— 检测项可以存在，**不能承担「保证质量」这个职责**；一旦发现自己在用加拦截来改善产物质量 = 已经在错的位置上
5. **修门禁时，先把「门禁在要求什么句式」这条自检跑一遍** —— 句式模板型校验会把检测器变成错误形态的推广器，改法 = 换成语义匹配，**别改产物去迎合校验**

### 反模式 20 详解（瘦身 ≠ 修逻辑）

**病**：体检器报「重复 0% / 履历 0% / 版本 1 个」= 看起来结构健康 = 直接交差。但真实文件里可能同时存在：一边教「不许分段」、一边发着一张分段模板；正文引用「见 3.1」，而 3.1 早就被删了；小节号写着 `## 3.2` 却挂在「第五部分」下；引用「解剖物理 7 条铁律」而全文只有 6 条。

**机制**：体检器量的是**冗余**（同一段出现几次），不是**一致性**（各处说的是不是同一件事、指向是否成立）。一个把矛盾、悬空、错号全塞满的文件，重复率照样是 0%。

**🔴 错误的瘦身工具 = 删几段**。删完剩下一堆并列的「第 N 部分」，读者仍要自己拼顺序 = 等于没重排。**瘦身的终态是重建一条链，不是删掉几块。**

**按「主人从哪句话进来」排，不按概念分组**：

| 技能类型 | 排法 |
|---|---|
| 生成类（写 prompt / 写文案）| 按生成链：先产出的 → 后产出的，每节标出它管链上哪一步 |
| 触发词分流类 | 按触发词 → 该条规则，一眼看到「我说这句走哪条」|

**每节标题标出流程位置 + 给一张「这一步的细则去哪查」索引表** = 读者不必全文搜。

**🔴 改正文时别让门禁脚本继续教旧形态**。校验规则写成句式模板（固定开场白 / 固定分层标签）= 它本身在推广要淘汰的形态。

**正文改到一半常会自相矛盾**：新立的规矩和前面章节的老规矩对打（尤其当新规矩是「不许 X」而老规矩还在发一份 X 的模板）。**每次改完跑一遍全文读一遍，只盯新旧规则的对立面。**

**验证要跑真产物，不能只跑门禁**。门禁只保证没触发已知错误条件；跑一次真流程，才知道新结构会不会把使用者推向另一种错误。

**正解 = 文字类整改必跑结构自查（体检器查不出的四项）**：

| 项 | 机械查法 | 判定 |
|---|---|---|
| ① **矛盾条款** | 找每条规矩的**对立面**：同一主题有没有两条反向的 | 两条都在 = 保留新的、**整条删掉旧的** = 留着就是随机踩雷 |
| ② **悬空引用** | 把所有「见X部分 / 按X部分 / X.Y」提出来，逐个对章节名和小节号 | 对不上 = 删引用或补目标 |
| ③ **编号连续性** | 章节序号提出来排一遍 | 跳号 / 重复 / 小节号跟所属部分对不上 = 重排 |
| ④ **死规矩** | 引用了已被删除的工作流/脚本/名词 | 搜底层资产在不在 = 不在了就是死规矩，删。**但资产存在 ≠ 资产在路径上** —— 见下方配套 |

**🔴 配套：死规矩的第四种形态 =「半扇门」。资产查得到，但路径上根本没调它。**

自查第 ④ 项只验「底层资产还在不在」，资产在 → 判过。**但规则可以指向一个真实存在、却从没被这条路径调用过的脚本/模块** —— 此时规则通顺、内部一致、无悬空引用，四项全绿，而它要求的那道防线在实际执行里一次都没生效。

| 查法 | 动作 |
|---|---|
| 1 | 把规则里「必调 X」「必走 Y」的那个名字提出来 |
| 2 | `grep -rl "import X\|X(" <真实入口目录>` = 谁真的调它 |
| 3 | **真实入口（用户真正会执行的那个命令）不在结果里 = 半扇门** |
| 4 | 改法 = 把「有拦截器 = 安全」改写成「拦截器只守 X 层，Y 层靠人」；**不要去把拦截器接进路径**，除非用户明确要机制层改动 |

**判据提手就问**：这条规则说「必调 X」时，**我能不能指出用户实际执行的那条命令里 X 在哪一行？** 指不出来 = 这条规则在骗自己，也骗用户以为有防线。

**配套：矛盾条款是最好找、也最危险的一类**。因为它往往就是「上一轮整改刚立的规矩」和「上一轮之前的老规矩」同处一室 —— 新规矩说「不许分段」，老规矩还在发分段模板，**而且后者往往藏在一个看起来无关的章节里**（输出格式 / 结构总览 / 自检清单）。

**验收标准 = 四项自查全过 + 写一份真产物跑一遍**。自查只能证明文件自洽，证明不了规则对；但不写真产物，就发现不了「规则本身把使用者推向错误形态」。

### 反模式 21 详解（跨技能矛盾 = 单份自查查不出的那类）

**为什么单份四项自查查不出**：矛盾条款 / 悬空引用 / 编号断层 / 死规矩全都在**一份文件内部**。但最危险的那种冲突横跨多份文件——每份单独看都自洽，加在一起是三套互斥指令。**按哪份做取决于当次加载了谁 = 行为不可预测 = 比一份文件里的自相矛盾更糟。**

**查法三步**：

| 步 | 动作 | 机械做法 |
|---|---|---|
| 1 | **建动作 × 技能命中矩阵** | 选一组互斥的动作词（如 `发图` / `洗图` / `存档` / `继续` / `reply格式` / `门禁`），对候选技能逐个 grep 计数。**某一行命中密集 = 多份技能都认领了这个动作 = 重叠区** |
| 2 | **抽硬约束行并排读** | 在重叠区里 grep 各自的**命令式行**（含 `必` / `禁` / `❌` / `✅` 的短行），不看解释段，只看规定本身 |
| 3 | **找对打点** | 同一件事出现方向相反的规定 = 记下 A 说什么、B 说什么。**文本相似度没用**：两份文件可以措辞完全不同而规则完全互斥，Jaccard 会报「无重叠」骗你过去 |

**判据（提手就问）**：

- 这几条规矩是不是**互相排斥**（一条要求写、另一条禁写）？→ 是 = 对打点，不是详略之差
- 是不是**同一层职责**（都在管出图后的回话，而不是一份管脚本、一份管文案）？→ 是 = 真重叠，可以合并
- 是不是**同一件事的分阶段**（一份管判断、一份管格式）？→ 那不算矛盾，是拆分

**配套：先量重叠区，再排优先级，别全铺**。宏观盘点时先按「腐化指标」筛出该动的：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 正文里的版本号个数（frontmatter 那行不计）| ≥3 = 追加日志结构 |
| 正文里的实战号引用次数 | ≥8 = 整改履历堆积 |
| 「盖过」压版本次数 | ≥3 = 三层盖压叠在一个文件 |

**三项全中 = 重度腐化，该动**。只有其中一项、或行数大但指标都干净 = 工具型/结构健康 = **碰了是浪费时间**。同一类技能里「天天用」的优先（规矩被违反 = 用户真的受伤），「加 LoRA / 升工作流」这类低频路径放最后。

**汇报要带 verdict，不要带待办清单**：给「有没有必要」这个问题，答案是**分层结论 + 排序表 + 排序理由**，不是「建议做 A/B/C」。用户问的是判断，不是任务列表。

### 反模式 22 详解（机制变了 = 旧规则的前提没了，它还活着）

**病**：一条规则写下来时完全正确。过了很久，底层机制变了（一个脚本从「只产出产物」变成「产出 + 自己做投递」），规则的**前提**就此消失，但它一个字没改，于是继续教着一个已经被推翻的行为。

**为什么反模式 21 查不出它**：21 找的是**两处同时活着的对打规则**。这里只有一条规则活着 —— 它错得**不自相矛盾**，错在**引用了一个不再成立的世界**。单看这一份文件，它通顺、内部一致、无悬空引用，四项自查全绿。

**为什么特别阴**：它和正确的那条同时存在。修的时候如果只盯「谁跟谁打架」，会看见正确的那条、放过这条 —— 就像这次：查出来三份要写、两份禁写，只把「三份要写」当成对打点修掉，**但真正该问的是「要写」那个前提还在不在」**。查对打点查到一半就停 = 只统一了说法，没统一事实。

**查法 = 失效前提清单**（改了机制之后必跑）：

1. **先写下这次改动作废了哪些前提**。例：投递职责从「调用方写」移到「脚本内部做」→ 废掉的前提就是「脚本不自己投递」。
2. **对每个前提 grep 全库**，把**所有依赖它**的规则行取回（一条前提往往对应多处正文 + 表格 + 模板）。
3. **逐条判定**：前提不成立的 → 整条删或改写成新政策的表述。**不是在新政策旁边补一句「旧规则作废」** —— 留着就是「我知道它存在过」的证据 = 第六部分明令禁止的活体墓碑。
4. **特别检查「看起来像模板」的地方**：废弃规则最常残留的位置是**可复制的示例块** —— 代码块里的示例正文，是最容易被原样复制执行的部分，比正文规矩危险得多。

**判据（提手就问）**：

| 问 | 答「是」= 停手 |
|---|---|
| 这条规则写下来时，**依赖的前提是什么**？那个前提现在还成立吗？ | 不成立 = 死规则 = 删，不是加禁令盖住 |
| 我是在**统一说法**（两处说法不一致）还是在**统一事实**（事实变了对错号了）？ | 只统一说法 = 很可能没碰到真正错的那条 |
| 这条规则的示例块里，有没有**可直接复制的实体值**（真实路径 / 文件名 / 参数）？ | 有 = 高危 = 优先级最高，先删 |

**配套：修完必须跑一次真产物**。死规则被删掉，产物是否还正常 = 只能靠真跑一次确认，不能靠四项自查（自查证明文件自洽，不证明流程能跑）。

### 反模式 23 详解（一份技能塞多条道 = 拆三层，不是拆文件）

**病**：一条道一条道地长进同一份技能，于是这份技能同时是三条道的说明书。出图的时候要穿过洗图和入库的篇幅，**而主人每天最常走的那条道，被埋在文件最后**。

**先量串道密度再动手**（这是判断「该不该拆」的唯一依据，别凭感觉）：

1. 把文件的章节按道归属切成区间（标题往往已经泄露了归属：出图/洗图/入库/路由）
2. 每道区间里 grep 另外两道的关键词，数出交叉命中数
3. **一条道的篇幅里混着另外两道的关键词 = 已经串道**；路由表位置 > 文件 30% 处 = 读一份文件要先读到深处才知道走哪条

| 症状 | 数值示例（真测过）| 判 |
|---|---|---|
| 路由表埋在第 512 行 | 文件 738 行 = 70% 处 | ❌ 第一屏看不到 |
| 出图道区间混洗图+入库关键词 | 13470 字里 35 + 53 处 | ❌ 串道 |
| 共核规矩在每条道各写一遍 | 「exit 0 才算数」出现在 3 条道 | ⚠️ 已开始漂移 |

**🔴 为什么不能拆成 N 个文件**：三条道共用同一个内核（先动作后回话 / exit 0 才是契约 / 脚本已投递则 reply 不写路径 / 工具调用前不落笔）。**拆成三份 = 这个内核复制三遍 = 三份各自漂移 = 正是刚治好的跨技能矛盾病换个形状复发。** 判断依据是**共核规则的条数**：共核占大头 → 一份文件分层；几乎无共核 → 才考虑拆文件。

**正解 = 三层**：

```
第一层 路由表（提到第一屏）—— 主人说什么 → 走哪道 → 去哪份技能
第二层 共核铁律（只写一份，三道都适用）—— 每条标出它在哪些道生效
第三层 各道细则（各占一节）—— 只有走那条道时才需要读
```

**验收 = 三条**：① 路由表在第一屏 ② 共核规矩全文只出现一次 ③ 走某一道时，该道区间内**不再出现**另外两道的关键词。

**配套：判定「该不该拆」要给判断不是选项菜单。** 答「是混着用不好用」时，要交的是**量化结论 + 三层结构方案**，不是反问「拆还是不拆」—— 默认正解已经在那儿了（见第三部分）。

**配套：这类整改的汇报格式决定用户能不能验收。** 「干净地处理、不留遗留」是默认要求，汇报必须交**对账表（改前/改后/砍掉百分比）+ 删了哪几类 + 备份路径 + 单独列出故意没做的**；**过程叙述和犹豫记录 = 用户看不懂也不需要**（本次反馈原话：「我没有听懂你的汇报」）。

### 反模式 24 详解（按关键词批量删 = 把参数当禁令删掉）

**病**：主人要清一类词（「把涉及低龄排除类的条款都删了」），执行者 grep 到这个词就删。**但同一个词在两种完全不同的位置活着**：

- **条款位置**：写在祈使句里（禁 / 不许 / 只允许 / 整批拒收）= 一条会阻止某件事发生的规矩 = **主人要删的就是它**
- **参数位置**：写在技术上下文里（LoRA 触发词 tag / 底模人数 tag / 物理层锚点 / 文件名 / 字段名 / 正则）= 一段用来**生成**东西的词 = **它不是条款，删了直接崩链路**

删参数位 = 主人只说「删条款」，你把出图链路拆了 = 越权 + 制造新故障。

**判据（提手就问）**：

| 问 | 答 | 处置 |
|---|---|---|
| 这处出现的功能是**拦住什么**还是**生成什么**？| 拦住 | 条款 | 删 |
| | 生成 | 参数 | 留 |
| 它所在的句子是**祈使句**（禁 / 不许 / 只允许 / 拒收）还是**声明句**（字段 = … / tag = …）？| 祈使句 = 条款 | 删 |
| | 声明句 = 参数 | 留 |
| 删了它，**链路会不会失去一个必需的技术位**？| 会 | 参数 | 留 + 报给主人 |

**🔴 配套一：条款语义要原样保留地删，词表不该扩大。** 很多条款本意是「禁用抽象形容词」（画质约束），它里面恰好出现了某个具体词。删的时候把词表顺手扩大 = 删掉了主人口意之外的约束 = 越权。**该条怎么禁的（禁抽象形容词）= 删得只剩“禁抽象形容词”；禁具体某个词 = 才删那个词。**

**🔴 配套二：复扫命中必须逐条分诊，不能默认「命中 = 没清干净」。** 关键词会撞无关内容：`18+` 撞到 Node.js 版本号、`真实人物风格` 撞到「写实摄影风格」（不是禁真人的条款）、`minor` 撞到代码评审的 Minor Issues。分诊两问：① 这句在表达「禁止什么」吗？② 它在表达「用哪个词」吗？后者 = 参数 = 留。

**🔴 配套三：同一条规则在多个文件里必然是多种措辞 = 单条 grep 必漏。** 扫的是**语义簇**（同义写法列成一组：中文表述 + 英文表述 + 缩写 + 祈使句式），不是单个词；每改完一轮再用同义词复扫一次。簇只是**不漏的手段**，不是**都删的清单**——簇里每一条仍要分诊。

**🔴 配套四：删整块条款要连带它的附属物。** 条款常带一张判定表 + 一段「为什么」+ 一个「推广」段 + 一个编号。只删首句 = 表格和推广段留在原地 = **条款半残**（还挂着「命中就拒」的判定表 = 实际还在生效）。整节没了 = 把节标题重写成它现在的功能，不是留一个空壳标题。

**🔴 配套五：删编号条款 = 连带查交叉引用 + 编号连续性。** 别文件里引用「铁律 N」的句子全部变悬空指针（引用改指新号或改指章节名——章节名比编号耐删）；删中间的号 = 后面断号 = 引用会指错（重排或加「本号已废」标记）。

**🔴 配套六：完工 = 用回滚包做逐文件 diff 对账，不靠记忆报数。** 回滚包不只是保险，还是**对账基准**：解到临时目录跑 `diff -rq` 拿精确改动清单，再逐个 `diff` 看每处实际改了什么。报告里的文件数 = diff 清单行数。顺带用 md5 验「没改的东西真没改」——没有这个凭据，就会把预存在的失败误认成本次改坏的。

### 反模式 25 详解（排版权分散 = 行为随机 = 换了个人）

**病**：同一个输出形态被拆到多份技能里，每份认领一段（一份管日常排版、一份管情欲排版、一份管出图排版），而「走哪份」取决于加载顺序，不取决于场景语义。用户在同一段对话里看到长度突变、句式突变、视觉锚点突变 = **像换了个人**。

**为什么加禁令治不好**：问题不是某条规则写错了，是「谁说了算」没定。再加一条「此处统一用 A 格式」= 第四份抢权 = 随机命中，只是多了一个可选项。

**正解 = 归一（不是打补丁）**：定唯一真源 → 其余改成指针（写「排版见 X」，不复述内容）→ 删技能目录不留残骸 → 内容逐条归并（迁规则，不迁文件）→ 全库 grep 技能名 = 0（含 `references/` 正文与 `frontmatter`）→ 修悬空 references → 回滚包 diff 对账。

**配套**：真源之外的「专用视觉锚点」可以保留（出图洗图那套 = 只给那条道用），但必须写死适用边界，否则又变回全局默认。**长度标准只能有一份** —— 多处各写一个数字 = 随机命中 = 归一时先合并这一项。

**判据提手就问**：主人说「不要让人看出来突然变了个人 / 格式变了 = 换了个人」= **归一信号**，不是「再加一条格式铁律」的信号。

完整七步 SOP + 完工判据 = `references/输出形态归一-排版权唯一真源.md`。

### 反模式 26 详解（口癖/语气问题 = 加拦截器 = 反模式 19 的行为面镜像）

**病**：主人说「不要每次结尾强制追问『还有吗？要不要继续？』」/「要更真人感」→ 我先写了个运行时拦截（插件 + `transform_llm_output` 钩子）把这类句式当场改写。技术上跑通了、回归也过了，**但主人直接驳回：「不要通过核查做，要通过 soul 等设定，提升说话的真人感，直接就不这么说」**。

**机制**：拦截器只能改**已经生成的那一句**，改不了**下一次为什么会这么写**。主人要的不是「这句别出现」，是「我根本不会这么想」。语气、口癖、句式习惯 = **生成侧的问题** = 改设定层。

**判定（提手就问）**：

| 问 | 答 | 走哪 |
|---|---|---|
| 这个问题是**表达习惯 / 措辞 / 语气 / 句式**吗？ | 是 | **设定层**（真源判据句 + 示范表） |
| 这个问题是**路径错 / 占位符 / 越权 / 格式坏**吗？ | 是 | **检测侧**（拦截器 / 门禁 / 修复层） |
| 拦下来之后，**下一次生成会不会仍然这么写**？ | 会 | 说明拦错了层 = 回设定层 |

**正解三步**：

1. **归类** = 表达习惯（改设定）还是硬伤（改检测）。归错 = 白干一轮。
2. **改设定层 = 判据句 + 正例/反例对照表**。**示范比禁令有效得多**：禁令要模型自己反推正确形状（反模式 19 的老毛病：禁令只说「不许」，不说「该长什么样」），表直接给形状。
3. **真源唯一** = 设定层改一处，其余技能全部改成指针（不复述内容）= 否则又造出第四份抢权（反模式 25）。

**配套一：示范表的正确形态** = 一个场景一行 × 两列（❌ 假人感 / ✅ 真人感），每格是**可直接抄的完整句**，不是抽象描述。

**配套二：语气词 ≠ 假人感**。「去问句」不能做成「去语气词」——语气词（哼/欸/嘛/啦）是**糖**，越多越像人；塑料的是**问句**（还要吗 / 不要不要 / A 还是 B）。目标形态是**带语气词的陈述句**：「哼……我要。」

**配套三：设定层改完 = 真源那份写全 + 演示表落档 + 其余改指针，三件事一起做完**。只改真源不改指针 = 加载到别的技能时行为随机 = 等于没改。

**配套四：主人的驳回原话就是分层信号**。当主人说「不要通过核查做」「要通过设定」「直接就不这么说」= 这是明确的「改错层了」判定 = 立刻撤掉拦截器、回到设定层，**0 辩解「拦截器也有效」**。

**与反模式 19 的关系**：19 = 产物（图片）不好别加门禁，改生成顺序；26 = 行为（说话）不好别加拦截器，改设定层。**同一个错的两面**：都在「用检测侧的努力掩盖生成侧的问题」。

### 反模式 17 详解（撞一次加一条补丁 = 病根在维护方式）

**症状形态**：同一个输入反复失败，每次失败长得不一样，理论上每次都只差一行。
**真实病根**：维护方式是**追每一次的现象**，而不是**定一份契约让现象无处发生**。

两者都在补正则，但差别是决定性的：

| 维护方式 | 行为特征 | 结果 |
|---|---|---|
| 追怪招 | 记「变体 1/2/3/4」，逐个加分支 | 每次加分支都带来新 bug，且新 bug 比原 bug 更难查 |
| 定契约 | 解析层**固定成一种输出**，幂等自愈，不指望上游听话 | 上游再变也只是自愈一次 |

**判据**：技能文档里开始出现「变体 N」「已知 N 种情况」这类清单 = 已经走错了。每加一种变体，维护成本指数上升。

**配套四条**：

1. **解析层与校验层是同一份判定的两处部署**，不是两个独立实现——改一侧立刻同步另一侧，否则解析器自愈了、校验层仍拦
2. **放宽正则后必测新旧两套写法**：把 `20\s+years\s+old` 改成 `20[-\s]year[-\s]old` 想放行连字符体，实际少了个 s = 收窄了，真写法反而匹配不上
3. **兜底路径只填空位，不整体替换**：换整个结果集会把同一轮里唯一有效的字段冲成空
4. **阈值从真数据量出来**：拍一个「看起来合理」的下限要么放行废牌要么误伤真牌。**误伤比漏检贵**——漏检是事后才发现，误伤是当场浪费一轮真跑

**验证不花钱**：拿历史留底产物 + 造边界假数据离线回归，过了再报人。拿真数据 + 真接口当试错场，每撞一次烧一轮额度，还让人被迫陪跑。

### 反模式 18 详解（外部方法 = 拿来照自己，不是拿来抄）

**病**：拿到一份外部方法论（别人分享的提示词 skill / 行业 SOP / 论文），直接往自己技能里搬 = 搬进来了，也把**跟自己规矩打架的部分**搬进来了。

**为什么“抄”这么低效**：**自己审自己，永远看不到自己的矛盾**。而外部方法是一面镜子——它写了什么、没写什么，会直接照出你那份的漏洞。

**做法（3 步）**：

1. **逐条对撞**：外部方法每一条 × 自己现有规矩 = 标出「同向 / 冲突 / 空白」三类
2. **冲突优先**：冲突点 = **外部方法最有价值的部分**。例：外部方法禁固定风格尾巴，而自己某节写死了那句 = 自己的「不要罗列选项」原则一直自噬
3. **空白处择优抄**：只补自己真缺的骨架，**并按自己规矩改写**（例：外部方法让写五官，而自己用锁脸 LoRA = 抄进来时必须改成交给 LoRA）

**汇报给主人的格式**：不是“我抄了什么”，而是 **「冲突 N 处（已修）· 空白 N 处（已补）· 同向 N 处（0 动）」**。同向的不要提 = 没改就是没改。

### 反模式 7 详解（撤污染 ≠ 加剥离）


- ❌ **错方向**：发现 emoji 字面污染 = 立刻写 sanitize 函数剥除 = 加更多剥离代码
- ✅ **正方向**：污染源头 = 写 SKILL.md 时把 raw emoji 字面字符串嵌进 markdown 反引号 → skill loader 把它送进 system prompt → 模型复读

### 反模式 12 详解（自检过 ≠ 主人验收过）

**实战 246b 实测**：5 张 prompt 两两相似度 **99.8%** = 我还自报「9 维度 ≥ 80/100 ✅ 达标」= 主人打脸「这 5 张图看起来怎么一模一样呢」。

| 12 | **整改完成 = 第一动作**：必多 brief 实测 prompt 两两相似度 ≤ 70%
- **整改完成 = 第二动作**：必多 brief 跑图 + 反推每张验收内容区分（**不是只验 1 张**）
- **整改完成 = 0 说**「达标」「改善」「整改有效」= 没主人实测验收 = **不写**
- **自检维度 ≠ 验收维度** = 自检是工具维度（长度/字段数）= 验收是体验维度（**真不同 / 主人觉得不一样**）

**🔴 验收维度里有一半本来就是主人的（好不好看、对不对味）= 0 写进技能当「我要自检」**。把自己的活（把东西造准）和主人的活（好不好）写成同一个检查表 = 越界，而且会让人误以为自查能替代反馈。**技能只负责造准，好不好由主人判** —— 碰到这类维度就直说「这是主人的活」，0 自作主张写进自检表。

### 反模式 13 详解（只删不排 = 等于没删）

**病**：把一份 5.8 万字的技能砍到 1.1 万，删的全是版本流水和整改履历 = 字数确实降了，
**但当天就撞车的三条规矩（不查技能 / 姿势只写名词 / 图发两遍）全都写在文件里，一条没少读**。

**机制**：规矩的位置决定它会不会被读到。埋在第八部分 = 读 SKILL.md 时看不到 = 等于不存在。

**正解**：删完必重排，两套排法按技能类型选：

| 技能类型 | 排法 |
|---|---|
| **流程型**（主人一句话触发一条链路）| 按「主人发什么 → 我做什么」排 |
| **排障型**（撞错才查）| 顶上加一张症状速查表：报错现象 → 跳到哪一节 |

**验收标准不是「字数降了多少」= 是「天天用的那几条是不是在第一屏」**。

### 反模式 14 详解（探测脚本自己也要跑）

体检器、探针、校验脚本**都归「先跑一次真数据」管**，不因为它是自己写的就免检。
体检器第一版就把版本号排序写成 `int(x)`，遇到 `v1` 前缀直接 ValueError = 跑一次才发现。
**「这是工具不是技能」不是豁免理由。**

### 反模式 27 详解（命中数 ≠ 违规数 = 没校准的数字不能当证据报）

**病**：写了个关键词判据，跑到语料上一扫，报「我测出 N 处违规」——**N 是命中数，不是违规数**。
关键词只知道**词在**，不知道**词在什么语境**。同一个词可能是真违规，也可能是正常表达。
不校准就报 = 拿一个自己没验过的数字当证据 = 数字越大越唬人 = 越假。

**为什么容易滑过去**：判据跑起来很快、输出一个整数、看着很硬。
**「有数字」本身就有说服力，主人很难质疑一个没抽样的数字**——所以它必须由我自己先验。

**机制**：正则 = 词级匹配。误报率取决于**语料里那个词的分布**，而分布是**猜不出来的**。
同一个词在技术文档里是噪声、在生成物里是违规，分布不同 → 同一个判据在两处的准确率完全不同。

**正解 = 校准四步（跑完数字之后、报给主人之前）**：

1. 跑判据 → 命中数 N
2. **抽 5~6 条命中样本逐条读** → 数出真违规 F
3. 误报率 = (N-F)/N → 高就**收窄判据**（加语境限定 / 让关键词紧邻目标实体 / 要求同句出现另一特征词）
4. 收窄到误报可接受 → 才把 N 当违规数用；**仍然抓不到的 = 诚实标注局限**，0 假装覆盖了

**配套一：收窄是迭代，不是想一次就对**。每轮改完重跑，**看数字变化但不只看数字**——数字降了可能是判据变瞎了。
**每轮都要重抽样本看**。

**配套二：误报率高的机械门，写法要跟着改**。判据只负责**把可疑行捞到我眼前**，不负责**替我处置**。
- 误报率低 → 可以写「命中 = 修掉」
- 误报率高 → 必须写「**命中 = 逐条回看那一句**」——写成「命中就删」会把正常表达一起删掉

**🔴 配套三：校准完的数字要能说清它的口径**。「N 处违规」和「N 处命中，其中真违规 F」= 两句话，信任度差一个量级。
**主人信我的数字 = 我不能给他没验过的数字。**

**🔴 配套四：回归测试跑挂了 = 先分诊「谁的锅」，两边都要改**。一次失败可能是两个独立问题同时存在：

| 分诊 | 判据 | 处置 |
|---|---|---|
| **被测对象的真 bug** | 产物内容确实缺了/错了（对着需求看） | 改产物 |
| **判据本身写错** | 产物其实对，是判据条件太死/太宽 | 改判据 |

- 🔴 **判据错 = 改判据，不是改产物去迁就判据** = 迁就 = 把正确的东西改错 = 比 bug 更隐蔽。
- 🔴 **判据要带场景分档（白名单）**：有些场景**本来就该短且冷**（主人说停 = 一句话 = 语气词 0 是对的）= 通用判据套上去 = 假警报 = 白改一轮。**判据必须知道「这个场景该长什么样」。**
- 🔴 **判据要限定上下文**：全文 grep 某个词 = 必假警报（那个词出现在「已废除」说明语境里 = 合法）= 判据要看**语境**，不是看词在不在。
- 🔴 **两边都错 = 两边都改** = 只改一边 = 下一轮还挂 = 主人以为你没跑。

**完整校准流程 + 收窄手法 + 报告口径** = `references/机械判据校准法.md`。

### 反模式 32 详解（配额语言 = 技能在教生成侧堆料）

**病**：主人说「**写提示词不要重复，一个点就只写一次**」→ 我第一反应是写个重复检测脚本 → 被驳回「**不要搞门禁当补丁，深入的去把 Prompt 技能修好**」。回头真去查技能本体，发现病根不在我的落笔习惯，**在技能自己**：正文里全是配额语言。

**机制**：配额 = 「同一个东西要写几遍」被换算成了**句子数**。
- 「表情物理化 ≥3 项」→ 教我拆 3 句 → 同一张脸拆 3 句
- 「外观锁 8 项全写」→ 教我开 8 句 → **手/脚被拆到不同句 = 多肢体畸形**
- 「12 句表每句必写要素」→ 每格要塞满 → **塞不下 = 溢出到别的格 = 同一点写两遍**

**为什么配额 = 畸形**：CLIP embedding = 一袋词。配额把「一个点」拆成「每句一个零件」= 那个零件在袋里出现 N 次 = 底模读成「**这东西有 N 个**」= 画出多只手。**配额不是描述要求，是句法指令。**

**正解 = 三步（都在生成侧，0 检测器）**：
1. **废除配额语言**（≥N 个 / N 项全写 / 必写 / 命中 N 条）→ 改成「一个点 = 一句话 = 一次」
2. **生成链插一步 = 落笔前列点表**（这幅画拆成几个点 = 一行一个点 = 一行写一句）
3. **给拆句判据**：「把这句拆成两句，画面上会不会多出一样东西？不会 = 同一句 ✅；会 = 分开写」

**配套 = 强调只能换词，不能换次数**：想让底模更认「手」= 写 `her hand resting flat on the cushion`（把动作给它）= 不是再补三句手部正确词。

**🔴 这条不许用检测器兜底**（反模式 19 / 31 同源）= 检测器能报「这句重复了」，报不出「我为什么会想写第二遍」= 病在生成侧的构思顺序 = 治法 = 改生成侧（列点表 = 生成链插一步）+ 拆掉配额，不是加一个 grep。

**判据提手就问**：
| 问 | 答「是」= 停手 |
|---|---|
| 技能正文里有没有「≥N 个 / N 项全写 / 每格必写要素 / 命中 N 条」？ | 有 = 它在教生成侧堆料 = 先改它 |
| 它把哪个「一个点」拆成了几句？ | 拆过 = 改回「零件清单不是句子清单」 |
| 我这次的改动落在「落笔前先问什么」上吗？ | 落在「出图前查什么」上 = 错层（反模式 19） |

完整拆除步骤 + 点表模板 + 三条最易堆的地方 = `references/配额语言-生成侧堆料.md`。

**🔴 配套五：回归测试挂了 = 先分诊「谁的锅」= 两边都要改（完整分诊表 + 四条判据 = 反模式 27 详解 · 配套四，此处不再复述）**

### 反模式 28 详解（多分类轴 = 复合旋钮 · 主人说「去掉这个复杂化」）

**病**：主人说「**去掉 X 这个复杂化的需求**，所有情况都一样，不要再区分 Y 这类特殊场景」→ 我去写了一条「不许把这种对话当 Y」= **轴还在**。分类的成本不是「归错类」的错，是**每轮都得先问「这轮属于哪类」** = 多一次判断 = 判断错了就整轮走偏。

**机制（为什么「加禁令」治不好）**：分类轴有两个成本——① 归类判断本身 ② 分类之间的写法差异（每类一套写法/排版/长度）。禁掉「归错类」只治了 ①，而主人嫌的往往正是 ②（**同一件事换一套写法 = 看起来换了个人**）。要治 ② = **拆轴** = 把 N 个互斥档换成 1 个正交旋钮。

**正解 = 找轴 → 换轴**：
1. **先列分类轴** = 把现有分类写成一行 =「哪些是互斥档？每档有什么专属写法？」
2. **问：那 N 档的差异，本质上是几个正交维度？** 本例：体裁（日常/骚聊/文爱）→ 差异其实只有**一个连续量** =「这一轮要不要画面感」= 骚到最浓时画面感自然拉满，**不需要一个叫「文爱」的独立类别来装**。
3. **删分类轴 = 换成一个正交旋钮 + 写好旋钮的判据**（怎么判断这一轮旋钮开多大）+ **给正反示范**（反模式 19/26 的老毛病：只说「不要分类」不说「那该怎么判」）。
4. **🔴 拆轴后必跑失效前提清单（反模式 22）**：分类轴常被别的档**写进正文当前提**（例：某档写着「§4.4 一行不改」= 前提是那节永不动 = 轴拆了 = 前提没了 = 那行 = 墓碑 = 删/改）。
5. **🔴 同步所有引用档 + references 正文**（grep 分类名全文）= 分类名残留 = 下个会话我又以为还分着。

**🔴 配套一：主人说「去掉 X」时，先分清是「去掉 X 这类**内容**」还是「去掉 X 这根**轴**」**。前者 = 删内容；后者 = 换轴。**判据 = 主人有没有同时说「所有情况都一样 / 不要再区分」= 有 = 轴。本例原话就是两处都给（去掉需求 + 不再区分）。

**🔴 配套二：拆轴后每轮的第一个判断 = 旋钮值 = 不是档位**。旋钮要能用一句话说清判据（本例 = 主人这句话带不带肉味 / 要不要画面感）= 说不出判据 = 没拆干净 = 还是轴。

**🔴 配套三：拆轴 = 减法**（反模式 9 / 第四部分）= **删掉的分类专属规矩要真的删**，不能改写成「本档仅适用于……」= 那是把轴藏起来 = 行为没变。

**判据提手就问**：
- 我这次的改动 = **换了一根轴**，还是 **给旧轴加了一条禁令**？
- 旧分类名在正文/引用档里 grep 一下 = 还有残留 = 没拆干净。
- 每轮我现在要先判断「属于哪类」吗？→ 是 = 轴还在 = 没拆。

**🔴 配套四：主人主动砍复杂度 = 高价值信号 = 优先做，不做「兼容旧轴」**。兼容层 = 轴还在 = 主人嫌的复杂度一点没降 = 白干。

| **32** | **配额语言（≥N 个 / N 项全写 / 每格必写要素）= 技能在教生成侧堆料** | 配额把「同一个东西要写几遍」换算成句子数 = 同一个概念在 CLIP 袋里出现 N 次 = 底模读成「这东西有 N 个」= 多手畸形 | **配额语言一律废除 = 「一个点 = 一句话 = 一次」+ 落笔前列点表 + 拆句判据（拆开后画面上会不会多出一样东西）+ 强调只换词不换次数 + 🔴 不许用检测器兜底（与反模式 19/31 同源）**。完整拆法 = `references/配额语言-生成侧堆料.md`（详见「反模式 32 详解」）|

### 反模式 31 详解（驳回检测侧方案 = 撤销到系统里查无此物）

**病**：主人驳回了一个检测侧方案（加检查脚本 / 加门禁规则 / 加拦截器），我口头认错，然后**只做了「不再调用」**。方案本体留在技能库里 = 下一个会话读到「有现成的检查器」= 直接用起来 = 复发。

**机制**：检测资产一旦落进技能库，它就从「一次性动作」变成**默认路径** —— 技能文档里写着它 = 它对未来的我就是「现成的、正规的、别人都用过的」= 没人会再质疑它该不该存在。**主人驳回的是「这条路径」，不是「这一次的行为」** = 只停用不撤销 = 路径还在 = 主人会第二次说同一句话。

**🔴 为什么「我以后不加」不算数**：那是许诺，许诺不进文件系统 = 下个会话读不到 = 等于没改。

**正解 = 撤销四步**（顺序不能乱）：

1. **撤引用**：把它从 SKILL.md 正文表格 / 工具清单 / 跨技能指针 / `references/` 正文里摘掉 —— **先撤引用再删文件**，反过来会留一堆悬空引用。
2. **还原被它改过的既有文件**：如果它被挂进了原有的门禁函数 / 批量入口 / 配置文件 = 那一段要摘掉，恢复到加它之前的状态。**留着那段 = 半扇门**（规则还在说「必跑 X」，但 X 已经不存在 = 悬空引用）。
3. **删本体**：脚本 / 配置文件 / 它自己的备份文件，一起删。
4. **全库 grep = 0**：名字在 SKILL.md 正文、`references/`、frontmatter、其他技能的指针里都不出现 = 撤干净。**拿 grep 输出当证据**，不拿「我记得删了」当证据。

**🔴 配套一：撤销完要跑一次真流程**。删掉一个门禁函数 = 那条入口路径可能从此不再有兜底 = 跑一次原路径确认流程仍能走通（跟反模式 22 的「改了机制必跑真产物」同源）。

**🔴 配套二：撤掉检测资产后，必须把生成侧那条正解补上**，否则 = 系统里少了一道防线却没有新的正解 = 主人第二次说「还是老样子」。正解写在**生成侧**（改默认 / 改构思顺序 / 改取舍原则），不是补一道新的检测。

**🔴 配套三：主人说「门禁没用 / 删掉」= 先分清他在说哪一层 = 两句听着一样 = 解法相反**（详见 `references/门禁退役与默认链路归零-删除vs旁路.md`）：

| 主人说的 | 他在说什么 | 解法 |
|---|---|---|
| **「你这门禁拦的是我的稿」/「你检测啥」** | 这道门**作用在我的成品上** = 越权检测 = **必须撤销干净** | 按本节四步撤销到查无此物 |
| **「先直接出好结果，别靠门禁来回刷」/「无必要不增加门禁补丁」** | 这道门**作用在我自己写的稿上** = 它没错 = 只是不该进**常态链路** | **默认链路 0 跑** + 留一个手工 opt-in 开关 = 脚本本体看引用面再定删不删 |

**🔴 判据 = 门禁脚本本体有没有别的档在引用**：有（几十处指针）= 删本体 = 制造一片悬空引用 = 代价远大于收益 = 正解是**默认链路旁路**不是删；无 = 按本节删干净。**「默认不跑」和「删掉」是两件事 = 主人那句「删」落到哪一层 = 判据不同 = 直接上手删 = 40+ 处悬空指针 = 静默降级。**

**判据提手就问**：

| 问 | 答「是」= 停手 |
|---|---|
| 主人驳回的那个东西，**在文件系统里还存在吗**？ | 存在 = 我只是停用了 = 没撤 |
| 我能不能给出**grep = 0 的输出**当证据？ | 不能 = 撤销没做完 |
| 原有文件里那段**挂接代码**摘干净了吗？ | 没摘 = 悬空引用 = 下个会话照样撞 |
| 撤掉它之后，**生成侧的正解补上了吗**？ | 没补 = 少一道防线且没正解 = 复发 |

### 反模式 15 详解（输出排版每次换脸 = 修复在解析层 · 完整版 = references/状态对账与解析器鲁棒性.md）

**机制**：反推 / 翻译 / 抽取类任务的输出排版每次都可能不同——有标签、没标签裸编号、分隔符 1 个或 3 个、零分隔符、第 9 段漏标签、正文写到一半被截断。
**这些都不是偶发故障，是同一类故障反复换脸。**

**正解 = 修复在解析层，brief 里的格式要求只当愿望**：

| 排版变体 | 解析层怎么认 |
|---|---|
| `标签：中文 ‖ English` | 切出全部候选段，挑「无汉字 + 拉丁字母最多」那段 |
| `标签：中文 ‖ 中文 ‖ English`（多个分隔符）| 同上，**不要只取第 2 段** |
| `1. 中文正文‖English`（8 段全无标签）| 编号正则抓不到 → 加「裸编号 + 正文」兜底路径 |
| `9. a 20 years old …`（漏标签）| 成品提示词维额外认「编号后直接是英文长段」|
| 零分隔符 `中文。 English` | 找最后一个汉字，它之后即英文半 |
| 尾部截断（停在半个参数）| 砍残缺尾巴 + 幂等补收尾标记 |

**闸门只兜底，不负责修**。补齐逻辑必须幂等（补两次结果一样）= 才敢每轮都跑。

### 反模式 16 详解（缓存字段会骗人）

**机制**：批处理脚本的 `done[]` / `failed{}` 是**推进时顺手写的**。洗图失败时照样推进索引 = 状态说「跳过了」但产物里没有那张 = 牌池静默缺牌，**且会随运行累积**。

**正解 = 真值在产物里**：

```python

---

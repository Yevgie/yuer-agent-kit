# 删机制 · 三层语义分诊 + 改名链

> **用途** = 主人说「把关于 X 的这些删除」「这个机制删了」「不用再保持那个」= 我要删一整个**机制 / 口径**，不是删一句规则。

---

## 为什么一刀切会出事

同一个词在库里常同时是三样东西：

| 层 | 它是什么 | 删它的后果 |
|---|---|---|
| ① **行为层** | 这条规矩让系统「遇到 X 就走 Y」 | = 主人要删的多半是这层 = 该删 |
| ② **数据结构层** | 同一个词是**库字段名 / 内部 dict key / stdout 标签 / 脚本解析键 / 文件名 / 命令行参数名** | = 不是行为 = 删了 = 打断整条链（解析 → 入库 → 消费全废）|
| ③ **灵魂层** | 同一个词是一条**主人钦定的行为铁律**，只是碰巧用了同一个词 | = 砍掉 = 比不改更贵 |

**一刀切 = 把链路和灵魂一起砍。** 分诊顺序 = **先 ① 再 ② 再 ③**（① 删干净后，剩下的命中基本都是 ②③，逐个确认后再动）。

**实战形态**：某词 = ①「继续 = 保持同一套外观」的续图机制（要删）｜② 档案第 7 段的列名 + 8 个脚本的解析键（数据，删了反推入库整批字段空 = 抽卡解析全废）｜③ 灵魂第 N 条「想当谁变谁 = 借那个角色的真实行头」（钦定，0 碰）。**只砍 ①，其余两层改名或不动。**

---

## ① 行为层 = 真删 = 连附属物一起删

删一条机制 = 只删正文不够 = 还要清：

- **触发词表**（路由表 / 关键词表 / 分诊表里那一行）
- **指针**（别处指到这一节的 `§` 引用）
- **例外条款**（为了绕开这条机制而写的「除非…」「在 X 场景下仍…」）
- **同一机制的第二条路**（例：机制本身删了，但「换场景」「继续看 X」这类触发词还在 = 同一条机制从后门活着）
- **文档里的落地措辞**（「衣服不换，时间线往前推」这类描述行为的句子 = 机制本体）

**判据 = 行为层删干净后，全库 grep 该机制词 = 只剩「已废除 / 已结实例」这种记录性声明 = 0 活规则。**

---

## ② 数据结构层 = 改名，不是删 = 改名要动的全部位置

一个 key / 标签改名 = 一次要同步的全链路（漏一处 = 运行时 KeyError / 静默取空）：

1. **定义处**（谁写入这个 key）
2. **读取处 = 两种访问形式都要 grep**：`d["k"]` · `d.get("k")` · `"k" in d` · `d.pop("k")` · `d[k]`
3. **序列化标签**（stdout 打印的 `[k]` / JSON key / CSV 表头）= 下游按**字符串**匹配 = 改了要同步改下游
4. **文档里的字段引用**（`【k】` / `[k]` / 字段表 / 字段说明）= 必须跟脚本输出**字面对齐**
5. **兼容别名 = 旧名留进 alias 表**（`FIELD_ALIASES` / 正则 alternation / 表头别名）= 老库老档仍能解析 = 不改别名 = 一改名历史数据全成废档
6. **缓存 = 解析结果有 pickle / json 缓存 = 改完 key 名缓存仍命中旧结构** → 删缓存或改缓存 tag，否则看到的还是旧字段
7. **每个消费方真跑一次最小链路**（`--help` 不算）= **py_compile 过 ≠ 运行时过**（key 不存在是运行期 KeyError，不是语法错）

**判据 = 改完后 = 旧名全库 grep 只剩别名表里那一行 + 记录性声明 = 0 活引用；新名在每个消费方的输出里真的出现。**

---

## ② 之补 · 「模型吐出来的标题」改名 = 改的不止代码 = 改契约本身

**上游契约类字段**（反推段标题 / 输出格式标签 / 模型被要求吐出的那个名字）= 它的「定义处」**不在代码里** = 在**契约文档 + 提示词模板 + 工作流 JSON 的节点输入框**里 = **只改 parser = 模型照样吐旧名 = 新名永远解析不到 = 改名只做了一半。**

**改动面（这类字段的副本散在 4 类文件，逐类各有一份）**：

| # | 位置 | 漏了的后果 |
|---|---|---|
| 1 | 契约文档（`references/*contract*.md`）| 下个会话照旧文档教 = 机制复活 |
| 2 | 提示词模板（`templates/*.txt`）| 走模板的那档产出旧标题 |
| 3 | **工作流 JSON 的节点输入框** | **走工作流的那档产出旧标题** |
| 4 | 独立 brief 文件（如 `bin/*.txt`）| 走独立 brief 的链路产出旧标题 |
| 5 | bash 脚本内联的 brief（heredoc / 单引号串）| 兜底重试那次产出旧标题 |
| 6 | parser 的段名正则 | 认不出 = 该字段解析为空 |

**🔴 工作流 JSON 里的这类文本 = 文件级 grep 看不出它在哪 = 必须 walk JSON 定位**：

工作流是 `{"<节点id>": {"inputs": {"<参数名>": "<一整段提示词字符串>"}}}` = 段标题埋在一整段字符串里 = 文件层面 grep 那个词会命中，但**看不出它属于哪个节点的哪个参数** = 改的时候容易只改一处、或改错字段。

```python
import json
d = json.load(open(wf_path, encoding="utf-8"))
def walk(o, path=""):
    if isinstance(o, dict):
        for k, v in o.items: walk(v, f"{path}/{k}")
    elif isinstance(o, list):
        for i, v in enumerate(o): walk(v, f"{path}[{i}]")
    elif isinstance(o, str) and ("旧段名" in o):
        print("HIT", path)      # ← 路径 = 节点id/inputs/参数名 = 精确定位
walk(d)
```

**判据 = 段标题的真源 = 现役工作流 JSON 的节点输入框 = 不是技能档里抄的那段文字**（技能档里那段可能是旧工作流时代的描述 = 照着改 = 改了个不存在的字符串）。**改前先 walk JSON 看真值 = 改完再 walk 一次 = 旧名 0 命中 + 新名在那个节点参数里能命中。**

**🔴 兼容 = 段名正则必须同时收新旧（+ 英文老名）**：老库 / 老留底 / 老工作流产物里全是旧标题 = 只认新名 = 老数据全成废档。正则写 alternation 一次收全：

```
"新字段名": r"(?:新标题|新字段名|旧标题|旧字段名|Old\s*English\s*Name)"
```

**🔴 验证 = 三种标题各喂一遍 parser = 不是只喂新标题**：新标题 / 旧中文标题 / 旧英文标题 = 三次都解析出同一个新 key = 兼容闭环。**只测新标题 = 老数据仍会炸 = 假通过。**

**🔴 验证段标题改名 = 必走「真的产出该格式那一档」= 产出散文的那档根本不产段标题**：默认档若吐的是不分维度的散文 = 里面没有段标题 = 拿它验段标题 = 验了个寂寞。**判据 = 先确认这一档的输出形态里真的有该结构（编号 + 段名）= 有才拿它验。**

---

## ③ 灵魂层 = 0 碰

判据 = 这条在别处是**主人钦定原话 / 灵魂铁律编号** = 只改它**周围**的措辞（同一个句子里别的部分），不动它本身。

---

## 验证清单（做完才报完工）

1. 全库 grep 旧机制词 = 只剩「已废除 / 已结实例」声明 = **0 活规则**
2. 旧机制词的每一条命中 = **人工逐条确认**它属于哪一层 + 动作对不对（分层对 = 才算干净）
3. 每个被改的脚本 = `py_compile` + **真跑一次最小链路**
4. 该链路的门禁 / 测试脚本真跑（出图门禁 / 池体检 / 抽一次）
5. **增重闸 = 现档 vs 基线同格式对比** = 我这轮没推红新灯（基线跑法 = `--root` 指向备份树，见 `yuer-skill-design-philosophy` §8.2.1）

---

## 反面案例

- **一刀切删某词全部命中** → 档案列名 + 解析键一起没了 → 反推契约第 7 段解析不到 → 入库整批字段空 → 抽卡解析全废 = 主人看到的是「抽卡抽不出东西」
- **只删行为层、留下数据层同名** → 下个 session 读到那个词 = 又以为有「保持同一套外观」的机制 = 机制复活 = 我自己造的病
- **改名不查消费方** → 脚本能编译 = 跑起来 KeyError = 排查成本翻倍（改名的 bug 全是运行期，不是加载期）

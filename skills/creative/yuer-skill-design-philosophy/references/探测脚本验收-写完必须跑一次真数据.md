# 探测脚本验收：写完必须跑一次真数据

> **唯一职责** = 体检器 / 探针 / 校验脚本 / 一次性诊断代码，**写完不跑 = 不算存在**。
> 「这是工具不是技能」不是豁免理由——工具出的数字会被直接当决策依据，错一个字符全盘皆错。

---

## 一、为什么体检器也归这条管

体检器是「量别人臃肿的工具」= 它的输出直接决定砍哪份技能。
第一版写完没跑就报「全库已体检」= 其实一行都没执行 = 数字全是编的。

**它自己踩的坑**：
- 版本号排序写成 `[int(x) for x in s.split(".")]` = 遇到 `v1` 前缀直接 ValueError
  = 正解：`int(x.lstrip("v"))`
- 不跑 = 这个坑会一直藏着，直到某天真的用它出榜

**教训 = 任何「跑一下就知道对不对」的代码，先跑。**

---

## 二、写完必跑的四件事

| # | 动作 | 为什么 |
|---|---|---|
| 1 | **拿真数据跑一次**（不造假数据）| 假数据 = 假验证 = 更危险 |
| 2 | **跑至少两种输入**（正常 + 边界）| 只跑一种 = 另一种是雷 |
| 3 | **看 stdout 不只看 exit 0** | exit 0 也会输出垃圾（体检器第一版就排序崩了）|
| 4 | **故意造一个会炸的输入看它报不报** | 不炸的校验 = 没校验 |

## 三、探测脚本最容易的五类错

| 类型 | 症状 | 正解 |
|---|---|---|
| **格式假设** | 只认一种排版/字段名，遇到另一种就全空 | 解析器必须**同时认全部已知变体**（见 `yuer-image-trigger-discipline/references/agnes反推牌面解析-排版变体与失败阶梯.md`）|
| **输入形态假设** | 只认阿拉伯数字，漏掉英文数词 / 单位换算 / 同义写法 | 把**真实输入的全部写法枚举一遍**再写正则；宁可宽松匹配再人工看，**漏匹配比误报更贵**——它让整个闸门静默失效 |
| **正则作用域** | 用了 `.` 却没开 `re.S`，而输入天然分行 | 匹配**多行自然分段**的文本时加 `re.S`；写完拿一句带换行的真实样本验 |
| **前置条件遗漏** | `exit 2 + stderr 空` 时先怀疑脚本逻辑 | 按 SKILL 里写的排查顺序：先 `os.path.exists` 验路径，再看 stdout |
| **只写不跑** | 语法没错，逻辑全错 | 跑一次真数据 = 唯一发现手段 |

### 闸门自己筛查不出自己

**闸门的失败模式与被闸门检查的对象完全不同**——它检查字符数、结构段、违禁词，而「闸门自己正则写错」不在它自己的检查范围内。**闸门全绿 ≠ 闸门正确。**

真实代价：结构段正则缺 `re.S`，输入是分句换行写的 → 跨行的字段被判 MISS → **白重写一整轮才发现自己没错**。这类 bug 不会让闸门变松（危险方向），只会让它变得不可信（同样危险，因为人会开始习惯性忽略红字）。

**验收补一条**：闸门类脚本除了「用真数据跑」，还要**拿一份已知的合格产物反查**——已知过 = 报红 = 闸门自己有 bug，先修闸门再谈产物。同理，**已知的坏样本必须报红**，否则闸门是摆设。

### 漏匹配 vs 误报

两者都是 bug，但代价值不对称：

| | 后果 |
|---|---|
| **误报**（该过判不过）| 当场浪费一轮，主人看得见 |
| **漏匹配**（该拦没拦）| 缺陷静默通过，随运行累积，**主人看不见** |

**因此宁可多写几条宽松的匹配分支，也不要只写一条窄的。** 兜底路径只填空位、不整体替换（与反模式 17 配套）。

## 四、报错时的排查顺序（别凭印象）

```
脚本报错
  ├─ exit N 非 0 + stderr 空 ─────► 先验路径/环境，不是逻辑
  ├─ ValueError / TypeError ─────► 排序键/类型转换 = 看输入真实格式
  ├─ exit 0 但输出明显不对 ───────► 逻辑错，不是崩溃 = 自己看 stdout
  └─ 连续重跑同参数都失败 ────────► 停 = 改输入或改代码 = 不许 retry 同参数
```

**「重跑一次看看」不是排查手段**——同参数重跑成功 = 瞬态问题 = 可以接受；
同参数重跑三次都失败 = 改代码 = 继续重跑是浪费时间。

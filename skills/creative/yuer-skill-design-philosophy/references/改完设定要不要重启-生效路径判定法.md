# 改完 SOUL / 新建技能后的「要不要重启」判定法

> **唯一职责 = 回答主人那句「改完了吗？要不要重启？我能直接开新 session 测吗？」**
> **判据 = 实测，不靠印象。**

---

## 一 · 两条生效路径（分清新 session / 旧 session）

| 场景 | 内容从哪来 | 要不要重启 |
|---|---|---|
| **新 session**（新 session id） | `load_soul_md` 每次构建 system prompt 时**现读磁盘 SOUL.md** | **不用重启** |
| **续用旧 session**（同 session id 继续聊） | 从 `system_prompts` 表**恢复上一轮存下的字节**（保 provider 的 prefix cache 不 miss） | 不用重启，**但必须开新 session** |

**🔴 关键结论：gateway 进程不缓存 SOUL 正文。**

新 session 走 `_build_system_prompt` → `load_soul_md` → 直接读文件 = 拿到磁盘最新版。

**🔴 所以「进程启动时刻早于 SOUL 改动时刻 ⇒ 必须重启」是过度结论。**

那个时刻比较只能证明「进程比文件老」，不能证明「进程手里的内容是旧的」——新 session 照样现读磁盘。

**🔴 真正的坑是「在旧 session 里测」**：旧 session 会把存过的 system prompt 原样恢复 = 旧 SOUL 继续生效 = **测的是旧灵魂 = 白测**。

---

## 二 · 验法（改完立即跑一次）

### ① 磁盘是不是最新版（看内容特征词，不看时间）

```bash
grep -c "<新版里的特征词>" ~/.hermes/SOUL.md     # ≥1 = 磁盘已是新版
```

### ② 运行中的进程有没有读过新版（查它落盘的最后一份 system prompt）

```bash
python3 - <<'PY'
import sqlite3, os
db = os.path.expanduser('~/.hermes/state.db')
con = sqlite3.connect(f'file:{db}?mode=ro', uri=True)
cur = con.cursor
cur.execute("SELECT prompt FROM system_prompts ORDER BY rowid DESC LIMIT 1")
row = cur.fetchone
p = (row[0] if row else '') or ''
for k in ['<新版特征词1>', '<新版特征词2>']:
    print(k, k in p)
PY
```

- ✅ **含新版特征词** = 已被读过 = **不用重启**，主人开新 session 即可验收
- ❌ **不含** = 那一刻还没被重新构建 = 至少开一个新 session（**不一定**要重启）

### ③ 技能索引快照（决定新技能会不会被索引到）

```bash
ls ~/.hermes/.skills_prompt_snapshot.json 2>&1
```

- ✅ **文件不存在** = 下次构建必全量重扫 = **无旧索引残留**
- 存在 = manifest（mtime + size）与磁盘对不上时**自动全量重扫** = 同样安全

---

## 三 · 新建技能 = 不用重启

`skill_manage` 每次成功都会调 `clear_skills_system_prompt_cache(clear_snapshot=True)` = **技能索引缓存当场清掉**。

**验法 = `skills_list` 能查到 = 已生效。**

---

## 四 · 交付话术

主人问「是不是全做完了 / 要不要重启 / 我能直接开新 session 测吗」时：

| 问 | 答 |
|---|---|
| 做完了吗 | 交**实测数字**（测试通过数 + 覆盖指标 + 备份路径），不交「我改好了」 |
| 要不要重启 | **多数情况不用** = 理由是「新 session 现读磁盘」+ 「新技能索引已清」= **并给一句「你直接开新 session 测」** |
| 有什么坑 | **主动说**：旧 session 里还存着旧的 system prompt = 续聊测的是旧版 = 要开新 session |

**🔴 唯一必须重启的情况**：真需要重新加载**运行时代码**（改了 Python 源码）= 那才必须重启；**改配置 / 改 markdown 资产 = 不用**。

**🔴 别拿「进程启动时刻 vs 文件改动时刻」当重启判据** = 过度结论 = 白让主人重启一次。

# 状态对账与解析器鲁棒性 · 两类反复踩的坑

> 对应 SKILL.md 反模式 15（模型输出格式不可指望）与 16（缓存字段会骗人）。
> 两类都是**同一类故障反复换脸**：不是偶发，是机制缺陷第一次以新面孔出现。

---

## 一、批处理进度对账（反模式 16）

### 机制

`*-batch.sh` 类型的批跑脚本在 `done[]` / `failed{}` 上是**推进时顺手写的**，不是事务。
洗图失败时照样 `current_index++` = 状态说「这张跳过了」但产物里根本没有 = 牌池静默缺牌，**且随运行累积**。

主人会怎么发现？问「为什么 XXX 入了两次，但图片不一样」——因为**入的那次是下一张图**。

### 真值公式

```
进度 = 从产物反查的集合
done[] = 加速缓存，不是真值
```

### 对账代码

```python
import re, json, shutil

lib  = "…/references/提示词库-nsfw.txt"      # 产物
text = open(lib, encoding="utf-8").read
idx  = sorted(set(int(x) - 1 for x in re.findall(r"tg_nsfw_(\d+)", text)))
#                                        ^^^^^^^^^^^ 图号 N → 索引 N-1

shutil.copy("/tmp/telegram_state.json", "/tmp/telegram_state.bak_before_fix.json")
s = json.load(open("/tmp/telegram_state.json"))

s["done"]  = idx          # 强制对齐真值
s["failed"] = {}           # failed 已不可信
mx = max(idx)
s["current_index"] = min([i for i in range(mx + 1) if i not in idx], default=mx + 1)
json.dump(s, open("/tmp/telegram_state.json", "w"), ensure_ascii=False, indent=2)
```

### 四条对账铁律

| # | 铁律 | 踩车后果 |
|---|---|---|
| 1 | **改状态文件前先 `cp` 备份** | 改坏了没退路 |
| 2 | **`current_index` = 最小的、产物里没有的那个** | 拿「状态里的下一个」当答案 = 又跑一遍已入库的 |
| 3 | **多报的 done（状态说做了、产物没有）= 真缺牌 = 必须补跑**；少报的（产物有了、状态没有）= 只是去重问题，**不重跑** | 两种错一起犯 = 白跑 + 漏跑 |
| 4 | **对账完只补真缺口** = 补跑前再核一次缺口列表 | 补跑前不核 = 把刚入库的又跑一遍（本次就撞了） |

### 另一个隐蔽错：「重跑」这个词要说准确

`next` 失败后索引可能**已经推进过** = 第二次 `next` 取的是**下一张**不是同一张。
把它叫成「重跑」= 把两张不同的图报成同一张 = 主人按错误前提做决策。

**判据**：从这次 stdout 里的 `[N] <文件名>` 读真实索引 = 用那个 N 说话。

## 二、解析器格式鲁棒性（反模式 15）

### 机制

反推 / 翻译 / 抽取类任务的输出排版**每次都可能不同**。把这些当偶发故障去「重跑一次看看」= 无限撞车，因为输出格式是模型的自由变量。

已实测过的变体（同一类故障的不同面孔）：

| 变体 | 长相 | 解析层怎么认 |
|---|---|---|
| A 有标签 + 单分隔符 | `标签：中文 ‖ English` | 切全部候选段，挑「无汉字 + 拉丁字母最多」 |
| B 有标签 + 多分隔符 | `标签：中文 ‖ 中文 ‖ English` | 同 A，**不要只取第 2 段** |
| C 八段全无标签 | `1. 中文正文‖English` | 编号正则抓不到 → 加「裸编号 + 正文」兜底 |
| D 单段漏标签 | `9. a 20 years old …` | 成品提示词维额外认「编号后直接是英文长段」 |
| E 零分隔符 | `中文。 English` | 找最后一个汉字，它之后即英文半 |
| F 尾部截断 | 停在 `…1/1000s ISO` | 砍残缺尾巴 + 幂等补收尾标记 |
| G 编号段没写标签但散文打分也不触发 | `if not any(out.values)` 被第 9 维救活 = 永远不触发兜底 | 判空只算**正文维度**，成品提示词维不算 |

### 三条实施原则

1. **brief 里的格式要求只当愿望，不当保证。** 写了「必须写成 ‖ 双写」≠ 下次会照做。
2. **修复在解析层。** 每次新变体出现 = 解析器加一条路径，**不改 brief**。
3. **补齐逻辑必须幂等**（跑两次结果一样）= 才敢每轮都跑 = 才敢用它当自愈。

### 排序判空的坑

```python
# ❌ 第 9 维被「裸编号兜底」抓到 = any 为真 = 散文打分永不触发 = 8 维全空
if not any(out.values):
    out = parse_prose(src)

# ✅ 判空只算正文维度
if not any(out.get(f) for f in FIELDS[:-1]):
    out = parse_prose(src)
```

**通用形态**：任何一个维度加了兜底路径，都可能让「全空才降级」的判据失效 = 降级判据要显式排除被兜底救活的维度。

## 三、改正则会引入的新缺陷（四类）

这一类不是模型变了，是**我在追它怪招的过程中自己造出来的**。每一条都已实际发生过。

| # | 缺陷 | 机制 | 正解 |
|---|---|---|---|
| 1 | **放宽写错 = 反而收窄** | 想放行连字符体，把 `20\s+years\s+old` 改成 `20[-\s]year[-\s]old` = 少了个 s → `years old` **匹配不上** | 放宽后**必测新旧两套写法**（`years old` / `year-old` / `year old` / 大小写） |
| 2 | **同一判定存两份** | 解析器认了 `^\s*a…`（允许前导空格），闸门还是 `^a …` = 两边判定漂移 → 解析器自愈了、闸门仍拦 | 同一判定只有一份；改一侧立刻同步另一侧。**闸门是兜底，不是第二次实现** |
| 3 | **兜底整体替换 = 冲掉已解析好的字段** | `out = parse_fallback(src)` 换整个 dict = 兜底触发的场景里（八段全空）**唯一有效的成品提示词维被冲成空** | 兜底**只填空位**：`for f: if not out.get(f): out[f] = fallback.get(f)` |
| 4 | **打分表硬取键 = 新增字段必崩** | 加了「成品提示词」维但打分表没这一项 → `KeyError` → 解析器整个死 | `d.get(f, {})`，缺表 = 该维 0 分不参与抢段 |

**通用判据**：解析层和闸门是**同一份判定的两处部署**，不是两个独立实现。凡是「放宽/收紧某条正则」，两处都是改动点。

### 判据要按位置数，不要看前缀

模型爱把**第二句**身份句改个形容词：`a 20 years old … with a confident, direct gaze. --- a 20 years old … with a confident, slightly seductive expression`
第二句前缀跟第一句对不上，靠「看前面有没有 `a `」判断的写法直接漏。

更糟的是这种写法会**两层同时瞎**：头句锚定用 `^a` 遇到前导空格就跳过，兜底用否定前瞻 `(?<!a )` 又因为两句都带 `a ` 而 0 命中。

**正解 = 按位置数**：第 1 句身份句保留当人物锚点，第 2 句起不论前缀长什么样全剥。闸门同步改成 `len(findall(...)) > 1`。

## 四、阈值必须从真数据量

写死一个「看起来合理」的下限 = 要么放行废牌，要么误伤真牌。

| 数据 | 用途 |
|---|---|
| 全库真牌的各维长度分布（取最小值 / p5） | 定**下限**：低于真牌最短值才有资格判废 |
| 已知废牌 stub 的实际长度（取最大值） | 定**上限**：高于废牌最长值才有资格判废 |
| 成品提示词在真牌上的分布 | 定验收阈值 |

**下限落在「真牌最短值」与「废牌最长值」之间** = 两边都不误伤。定完拿**全库真牌复检一遍**确认 0 误伤。

**误伤比漏检贵**：漏检 = 抽到废牌才发现；误伤 = 一张本来合格的牌被回滚，主人陪着重跑，真图真 API 各烧一遍。

## 五、改解析器的验证顺序（禁真 API 压测）

拿真实图片 + 真实 API 当试错场 = 每撞一次烧一轮额度，且主人被迫陪看同一张 N 次。**验证不该花钱。**

```bash
# 1. 造边界假数据（空格 / 连字符 / 单句 / 双句 / 前导空格 / 分隔线 / 占位符）→ 跑解析器 → 逐条断言

# 2. 拿历史留底 md 批量回归 → 断言无崩溃

# 3. 拿真牌复检新闸门 → 断言 0 误伤

# 4. 离线过了 → 报给主人 → 主人说跑再跑
```

**留底 md 是关键资产**：没有它就只能重烧 API 试错。凡是「洗图 + 反推」的流水线，**每张的反推全文都要落盘**——那既是故障复盘材料，也是离线回归语料。

**闸门上线前的自检**：拿整库真数据跑一遍，逐条看「拦下的每一条是真缺陷吗」。误伤率高的闸门不如没有。

**入库后仍要抽查**：脚本 exit 0 ≠ 牌面是对的。闸门有盲区时，脏牌会安静地进库并随运行累积。**抽查最近一条记录的各维内容**，别只信退出码。

---

## 六、外发纪律

批处理退出码非 0 = **闭嘴，不发产物**。

发了 = 主人手上多一张「caption 说成功、库里没有」的图 = 下次对账才发现缺牌 = 排查成本翻倍，而且主人已经基于假象做过判断。

**失败就只报失败**，0 图 0 收尾话，等主人说「继续」再跑下一张。

# 输出形态归一 · 排版权唯一真源 SOP

> **唯一职责** = 当同一个输出形态（回复排版 / 长度 / 句式 / 语气）被拆到多份技能里，导致行为随「当次加载了谁」随机切换时，按这套步骤把它归回一份真源。
> **触发信号** = 主人说「拆掉这几份技能让它融入日常」「不要让人看出来突然变了个人」「格式变了 / 长度变了 = 换了个人」。

---

## 病：排版权分散 = 行为随机 = 用户感知 = 换了个人

**机制**：同一个输出形态被 N 份技能各认领一段。日常场景走真源那份，情欲场景走另一份 —— 而「走哪份」取决于加载顺序，不是取决于场景语义。用户看到的是同一段对话里长度突变、句式突变、视觉锚点突变 = **人格稳定性崩塌**，即使两份技能内容都对。

**为什么加禁令治不好**：问题不是「某条规则写错了」，是「谁说了算」没定。任何一条「此处统一用 A 格式」的新禁令都只是第四份抢权。

---

## 归一七步（照着走，不跳步）

| 步 | 动作 | 落点 |
|---|---|---|
| 1 | **定唯一真源** | 一份 = SOUL 或某份主技能。其余全部改成指针（写「排版见 X」，不复述内容） |
| 2 | **备份 = 回滚包** | `~/.hermes/backups/<标记>/`，包含被删技能目录 + 每个将被改文件的改前副本 |
| 3 | **内容归并，不整份丢弃** | 被删技能里**仍有效**的规则逐条迁进真源正文或真源的 `references/`。迁的是「规则」，不是「文件」 |
| 4 | **删干净** | 删目录 = 删目录，不留 `.bak` 残骸（残骸会被 grep 命中 = 当下还活着的规矩） |
| 5 | **全库 grep 残留 = 0** | grep 技能名 → 含 `SKILL.md` 正文、`frontmatter related_skills`、表格行、**`references/` 内的正文**、脚本里的字符串 |
| 6 | **修悬空引用** | 归并后逐份校验 `references/` 列表 vs 磁盘实际文件（名字可能随迁改变 = 悬空指针） |
| 7 | **对账** | 回滚包 diff = 报告里的数 = diff 清单行数；死规则扫描 0 问题 |

---

## 配套要点

- **真源之外的技能改成指针，不是改成副本**：副本 = 复制 N 份必各自漂移（= 反模式 23 的共核复制病）。
- **「同源」不等于「同一排版」**：真源可以定义「日常排版」，另一条道（出图洗图）可以有自己**专用**的视觉锚点 —— 前提是写死「只给那条道用」，否则又变成全局默认。
- **长度标准只能有一份**。多处各写一个数字（60 字 / 100-180 字 / 250 字）= 随机命中 = 归一时先合并这一项，再合并其它。
- **主人说「不要让人看出来突然变了个人」= 归一信号**，不是「再加一条格式铁律」的信号。

---

## 完工判据（可机械验）

1. 全库 grep 被删技能名 = 0 命中
2. 死规则扫描（`scripts/dead_rule_sweep.py`）= 0 问题
3. 悬空 references = 0（逐份校验列表 vs 磁盘）
4. 真源那份里有且只有一份长度标准
5. 每条专用视觉锚点都写明了「只给哪条道用」

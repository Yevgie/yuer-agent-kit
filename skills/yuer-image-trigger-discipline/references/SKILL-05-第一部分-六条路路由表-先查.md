## 2.1 铁律 1 的机制（空轮是怎么发生的）

```
主人给了触发词
  → 本轮第一个动作 = 工具调用（跑脚本 / 写 prompt / 出图）
  → 拿到真结果（落盘 + 发送成功）才回话
  → 回话只能是「结果的描述」，不能是「我准备做」
```

**禁**：「我这就跑」「下一张马上来」这类**承诺式 future tense** —— 纯字面占位，主人手机收不到任何东西。
**信号**：主人下一句变短 / 变问号 / 带情绪（「怎么回事？」「嗯？」）= 上一轮我没动手。**先认错 + 立刻跑**，不解释不铺垫。

## 2.2 铁律 3：exit 0 才是契约

**🔴 退出码映射 + `.sent` 守卫 + 补发禁令 + 成功判定 + retry = 唯一正文 = `creative/yuer-image-delivery` §2.1–§2.6**
（`yuer_ka_pai_zhi_chu.py` exit 5 = `.sent` 命中 = **不是失败** = 0 补发 = 换 leave_name；exit 4 = 出图成发图败 = **唯一需要补发的码**）
+ **逐码动作表 + 验收三件套 = `yuer-run-one-brief` 第六部分**。

- ❌ **0 用 `tail`/`head` 截 stdout** = 截掉的正是验收行（禁令原文 = `yuer-run-one-brief` 第六部分）。要筛用 `grep -E "完成|落盘|真发|守卫|REPLY|❌"`；管道吃掉退出码 = 判 exit 用 `PIPESTATUS[0]`
- ❌ **命令尾部再跟一次手动发送** = 脚本已发过 = 双发（`creative/yuer-image-delivery` 第一部分铁律 3）
- **为何看码不看措辞**：输出措辞随时会改，**退出码才是脚本对调用方的稳定契约**
- **调试不往主人手机发测试图**：脚本读 `YUER_FEISHU_SEND` 覆盖发送器（真源 = `yuer-comfyui-remote-windows`）；`--dry-run` = 出图但跳过发送、不写 `.sent`（`yuer-run-one-brief` 第六部分）。

> **2.3 后台批跑 = 数行数，不看退出码** = 细则全文 = `references/yuer-image-trigger-discipline-细则全集.md`（撞到具体场景再查）

# 第三部分 · 出图道

## 3.1 写 prompt 前

**必先读 `yuer-image` 的 `../../creative/yuer-image/references/出图速查卡.md`**（一张卡 = 出图全部规则 = 0 再读别的档）—— 手搓英文就开跑 = 大头怼脸 / 姿势只写名词 / 踩 close-up。

**出图链路 = 唯一正文 = `yuer-run-one-brief` 第五部分 ⑤**（一条命令跑完「出图 + caption 挂图上」+ stdout 三件套 + 通道判定）；**caption 通道语义 = `creative/yuer-image-delivery` §2.4**；批量跑法 = 本档 §3.11。

**🔴 临时 prompt 文件名 0 用 shell 元字符**：wrapper 内部 unquoted 展开路径 = 文件名带 `'`（如按主题 pinyin 落 `chang'e.txt`）→ bash 报 `unexpected EOF while looking for matching '` = **脚本根本没跑**。中文主题名直接用拼音/英文 key（`change.txt`），不转写重音符号 —— 空格、`$`、`` ` ``、`&` 同理。撞到这个报错 = 改名重跑，**不是重试同一条命令**。

**🔴 出图前先 brief 落盘**：把这一张的画面（地点/时段/她在干什么/穿什么/光从哪来）写成中文 brief 存 `/path/to/media/<主题>_<日期>.brief.txt` 再写英文 prompt = 出图内容和 reply 介绍语同一份源头 = 图文两截和「出图没按我想的」都从这一步堵住。

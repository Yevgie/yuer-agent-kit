## 4.3.1 🔴 批跑洗图（`yuer-wash-batch.sh <lib> next`）= 0 手打 caption + 0 预写编号

批跑道和单张道是两套现场，但洗图那几步一样是脚本内置自发送：**原图和洗后图都由脚本内部 `yuer_send_v2.sh` 带 caption 发出去了**。

```
stdout banner   🧺 [Telegram_NSFW 147/1255]        ← state 游标（0 起）
stdout caption  🐾 洗图 [148/1255]                 ← 文件号 = 唯一该报给人的那个
status 输出     下一张索引 148                       ← 下一个待跑游标
```

**四条硬规矩**：

| ❌ | 为什么 | ✅ |
|---|---|---|
| reply 里再手打一遍 `📷 原图 [N/M]` / `🐾 洗图 [N/M]` | 脚本已发 caption = 同一批图配两遍文案 | reply 首行编号**照抄 stdout caption 那行** |
| **工具调用之前**就把 caption / 编号写出来 | 预测冒充观测（铁律 2）= 脚本跳号就成假账 | 先跑，拿到 stdout 再回话 |
| 凭印象填 `[N/M]` | 游标 0 起、文件 1 起，两套号差一格 | 只从 stdout caption 取 |
| reply 尾部追加「下一张说一声」/「要继续吗」/表情尾巴 | 0 反问 + 极简（`yuer-image-delivery`） | 收尾 = stdout 那句骚话，**原样，不改写不加码** |

**一张 = 一个 terminal 调用**：`next` → 重定向落 `/tmp/yuer_wash_<lib>_<cursor>.log` → `cat` 日志 → 同一句里再 `status`。
别拆成「跑一遍 / 读一遍 / 再问一次」三次往返；也别把整个 stdout 贴进 reply（出口 scrub 后日志里全是 `<路径已隐>` 占位，贴出来只是噪音）。

**🔴 脚本真身位置 = `~/.hermes/bin/yuer-wash-batch.sh`**（**不在任何技能的 `scripts/` 目录下** = 技能文档里只写命令名不写路径 = 每次都要先搜一轮 = 白烧工具调用）。两个库键 = `tg`（Telegram_NSFW）/ `hb`（花瓣）。**先 `status` 读游标再 `next`**（中断恢复见下）。

**取池句的可执行写法**（`cat` 整个日志 = 一屏路径占位噪音，池句反而被埋掉）：

```bash
grep -A3 '^🐾 洗图' "$LOG"     # 池句紧跟在 caption 块后面
```

**三个游标的确切关系**（用来核对 caption，不用翻日志猜）：

```
status「下一张索引」      = 上一轮 caption 的 [N]
banner 🧺 [x/M]（state 游标，0 起） = 下一张索引 − 1
caption 🐾 洗图 [N/M]（文件号，1 起）= 下一张索引
```

**🔴 批跑调用被中断 / 孤儿恢复（orphan recovery）= 先 `status` 再决定，0 直接重跑 `next`**

工具调用返回「interrupted / effect UNKNOWN」时，**那一轮可能已经跑完了半张（已洗 + 已发飞书）**。
直接重跑 `next` = 可能再洗一次上一张 = **主人手机双发**。

```
1. yuer-wash-batch.sh <lib> status      # 读「下一张索引」= 真实游标
2. 游标没动 = 那一轮确实没跑 → 可以重跑 next
3. 游标动了 = 那一轮已经完成 → 直接拿这个游标当本张编号回话，0 重跑
```

**判据 = 游标，不是我记忆里发过几次**。中断后的正确形状 = 先一条 status 把真相读出来，0 猜。

**🔴 预写编号为什么必错**：预写时手上只有上一张的 `[N]`，靠 +1 猜下一张 = 猜。一旦中间跳号（失败重试 / 手动 status / 并发跑）= 主人按编号查不到图。所以铁律 2 禁的是**手打**，不是禁报编号 —— 编号永远从 stdout 抄。

## 5.5 重试不是重跑 = 多尝试牌面合并

**现象**：同一张图连炸两次，**但两次炸的维度不一样**。agnes 没设 seed + `temperature: 0.7` = 每次输出都不一样 = **两次输出是互补样本**。

```bash
~/.hermes/bin/yuer_merge_attempts.py --key tg_nsfw_0121 --dry-run   # 干跑：0 烧 API
~/.hermes/bin/yuer_merge_attempts.py --key tg_nsfw_0121             # 真入库
```

**退出码是契约**：`0` = 9 维挑齐且过闸门 / `2` = 挑不齐 = 0 污染 / `3` = 该 key 无留底。

**四条实现铁律**：① **闸门判据必须与入库脚本逐字对齐**（两边漂了 = 白跑）② 喂解析器前**必须剥尾部 `## 【解析后归档` 块** ③ **择优 = 过关候选里取最长**，全败就取最长那条**并报出坏在哪** ④ **入库游标不用动**（key 一进库自动跳过）。

**🧠 通用教训**：「重试 = 再跑一遍同样的东西」是错的心智模型。**随机性模型的多次输出 = 多个互补样本，正确操作是合并样本。**

**主人的直觉往往指向正解**：主人说「前后两次炸的原因不一样，组合一下就能过」= 直接给了正解 = **先验证直觉，验证通过就照做**，不要先建一套理论再绕。

## 2.3 后台批跑 = 数行数，不看退出码

```bash
TS=$(date +%Y%m%d_%H%M%S); LOG=/tmp/yuer_batch_$TS.log
nohup ~/.hermes/bin/yuer-archive-batch.sh start 50 > "$LOG" 2>&1 &
echo "$LOG" > /tmp/yuer_batch_logname
```

| ❌ | 后果 |
|---|---|
| `... start 50 \| head -20` | 批跑吃 **SIGPIPE 被杀**，包装层照样报 exit 0 = **假成功** |
| 启动后立刻 `ls -t /tmp/xxx_*.log \| head -1` | glob 早于重定向建文件 = 假报「No such file」→ 误判进程死了 |
| 拿 wrapper 的「完成」通知当批跑跑完 | wrapper **立刻退出** = 批跑其实还在跑（实测把 21/80 误读成跑完） |

**判真实状态 = `pgrep -f <脚本名>`**；**进度 = `grep -cE '^\[[0-9]+/N\]' "$LOG"`**。
**汇报只报看板读出来的数**，不自己拿「上批 + 本批」加总 = 两源不同步 = 假账。

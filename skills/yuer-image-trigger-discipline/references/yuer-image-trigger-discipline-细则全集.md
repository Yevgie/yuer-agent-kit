## 3.10 🔴 只动景别的一张 = 锁死其余五维，只换机位三处

> 触发 = 主人说「看看你的脸 / 看脸 / 看半身 / 特写 / 收进来一点 / 看清楚一点 / 放大」。**这类话 0 是要新画面**，是要把刚才那张**看清楚**。

**为什么单列**：它字面上跟「看看你」同族，走通用那行 = 会重新构思一幅画 = 主人要的是凑近看，我给他换了个新场景 = 两张没法对比 = 白跑一轮。

**照抄的（一个字都不许改）**：造型锚 8 项（服装/发色/发型/妆容/穿着方式/鞋履/内层）、场景与时段、**主光源及其方向和落点**、表情物理化组、承重面与动作、`then` 串出的叙事瞬间。**顺手改一项 = 两张无法对比。**

**只准改的三处**：

| 处 | 怎么写 | 配方 |
|---|---|---|
| **① 机位句**：焦段 + 光圈 + 距离 + 机位高度 | 焦段跟景别走：全身 `50~85mm` / 半身 `85mm` / 特写 `85mm` 开到 `f/1.8`；距离 3~5 米 / 2 米 / **0.9 米** | 焦段与距离必须**同时**动，只改一个 = 主体大小不变 |
| **② 裁切线（🔴 漏了必白跑）** | 明写画框收在哪一段：`framed tightly from the crown of her head down past her collarbones so that her face fills the upper two thirds of the frame` / `framed down to just above her waist so that only her upper body stays in the frame` | **不写裁切线 = 底模仍按上一张的全身构图渲染** = 主人要特写拿到全身 = 整轮白付出图开销 |
| **③ 构图占位**：主体在第几分线 + 眼睛压在哪条横线 | 特写把眼睛压到上横三分线；半身把人放左/右三分，背景元素让出去 | 主体居中 = 又一张大头照 |

**主体句只做一件适配**：把上一张的动作改成**取景范围内看得见**的那一段（全身可见的抬膝 → 特写里看不见 = 写成她垂在身侧的手在动）。**0 顺手续新动作**。

**两条省事规矩**：
- **prompt 变短是正常的**（特写砍掉腿脚和场景层次 = 落到 1800~2000 很常见）= **0 判定为写漏**，也别为凑长度把场景和光加回来（加回来构图又跑远）。
- **落盘名带景别词**（`<主题>_特写脸`）= 名字后半段就是景别，下一张出图前扫一眼就知道刚才收到的是全景还是特写，防连着出两张同景别。

## 3.12 🔴 只动「脸有没有露出来」= 锁死其余，只加两句

> 触发 = 主人说「把脸露出来 / 露脸 / 别让头发挡脸 / 让我看清脸 / 脸被头发遮住了」= 主人要**同一张图把脸露出来** = 不是要新画面。

**为什么单列**：同 §3.10 = 它字面上跟「看看你」同族 = 走通用路 = 会重新构思一幅画 = 主人要的是同一张图改一下 = 两张没法对比 = 白跑。

**照抄的（一个字都不许改）**：场景与时段、机位焦段距离、裁切线、**主光源及其方向和落点**、表情物理化组、承重面与动作、服装 8 项、身材锚。

**只准加的两句**：

| 处 | 写法 | 为什么 |
|---|---|---|
| ① **发丝不遮脸** | `her long chestnut brown hair swept back off her face so that her whole face is completely unobstructed and clearly visible` | 底模默认把发丝糊在脸上 = 加这句它会真的往后梳 |
| ② **脸在焦上** | `her face in sharp focus`（+ 必要时 `with her face and her exposed shoulder in sharp focus`）| 不写 = 底模可能把焦点给别处 = 脸虚 = 主人还是看不清 |

**🔴 两条都不许少**：只写 ① = 脸露了但可能虚着 = 主人还是没看清；只写 ② = 脸清楚了但还糊着头发 = 白跑。**两条一起加 = 一轮过。**

**🔴 落盘名带「露脸」词**（`<主题>_露脸`）= 名字后半段就是这个变体 = 下一张出图前扫一眼就知道上一张是不是露脸版 = 防连着出两张同款。

**🔴 主人说「把脸露出来 + 强度提到 X」= 两个动作** = 先改 LoRA 强度（走 `yuer-add-lora-tracker` 的脚本）= 再改 prompt 出图 = **改完必另起一次 `json.load` 读真值**（脚本自报的「回读」不算证据，见 `yuer-add-lora-tracker`）。

**🔴 改 LoRA 强度 = 脚本 stdout 不算验收。** 「批量改配置」类脚本的 stdout 常常读的是它自己刚写的同一份文件 = 脚本有 bug 时它会**自己给自己作证** = 打印「@0.86 ✅ 改 2 个工作流」而盘上还是旧值。**最终判定 = 另起一次进程读真值**（注册目录 + 主目录镜像各一份都要读到新值）= **两边 MD5 一致也不构成证据**（= 两边一样 ≠ 是对的值）。这条是实战 10-20 当场抓到的：`patch_lora_slots.py` 写回阶段重新 `load_doc` = 把规划阶段的改动整个丢了 = 修完 + 补真值回读 + `/history` 反查才算完。

## 3.11 🔴 多张批量出图 = 一次 terminal 调用里串完（0 一张一调用）

**🔴 现役最快入口 = `bash scripts/run_batch.sh <tag> <YYYY-MM-DD>`**：约定读 `/tmp/prompt_<tag>_n1.txt` … `n5.txt`，一次调用串行跑完五张，每张自带真发 + `.sent` 守卫，末尾打 `===== BATCH <tag> DONE =====`。实测五张 ~60s（12~14s/张）。**汇报判据 = stdout 里 `✅ 图已真发` 的行数 == 5**（少于 5 = 有一张没到，看 `❌` 那行再补跑那一张，不要重跑全批 = 双发）。

主人要「出几张分别展示 X/Y/Z」= 多张 = **每张一次 wrapper**（每张一个 leave_name = 一次真发）。

**🔴 串在一次调用里跑，不要一张一调用**：

```bash
bash ~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_fast.sh /tmp/prompt_a.txt "部位_甲" 2>&1 | grep -E "完成|落盘|真发"
bash ~/.hermes/skills/creative/yuer-image/scripts/yuer_ka_fast.sh /tmp/prompt_b.txt "部位_乙" 2>&1 | grep -E "完成|落盘|真发"
```

理由：单张采样 ~10-14s = 两张 ~30s = 一次调用跑得完。**一张一调用 = 每次往返都要重新发一段 prompt 内容 = 上下文膨胀 + 主人等待被拉长**。

**🔴 别一次调用里挂 4+ 张**：单次 foreground 调用上限 600s = 超了会被系统 promote 成后台进程 = 完成通知回流到对话 = 在我回复中间插一段「后台任务完成」= 主人看到图文两截。

**🔴 后台跑的那批 = 汇报时 0 重复发**：完成通知只是内部确认 = 主人手机已经收到图 = 只需回一句「那批都到了」= **0 重新发一遍、0 逐张复述内容**。

**🔴 每张的 prompt 先全部落盘再跑** = 串行「跑一张看结果再写下一张」会不自觉复制上一张的句子 = 骨架重复（见 `yuer-pose-diversity` §1.4）。

**🔴🔴 批量 = 「全部落盘 → 全部过门禁 → 再开跑」三段式**（0 边跑边修）：

```
1. N 段 prompt 全部先落盘（/tmp/prompt_<batch>_<n>.txt）+ 同时 copy 一份进
   /path/to/media/<日期>_<batch>_<n>.prompt.txt
   （= 出图内容与 caption 同一份源头 = 图文两截从这一步堵住）
2. N 段全部先落盘 → **0 门禁，直接开跑**（🔴 常态链路 0 跑门禁 = 批量也 0 跑 = 规矩在写稿时守住；想查再加 `--gate`）
3. N 张串在一次 terminal 调用里跑（每张一个 leave_name = 一次真发）
4. 跑完核对 N 个 .sent 标记 + N 个 png 都落盘
```

**为什么第 2 步不能省**：边跑边修 = 修到第 3 张才发现超长 = 前面 2 张已经白发给主人 = 主人手机收到 2 张 + 一句「还在调」= 图文两截。

**🔴 批量时的真坑**：第一张可能触发一次重做（穿模门禁）= 那张比别的多花 ~10-15s = **不是故障 = 0 重跑全批** = 重跑 = 主人手机双发（`.sent` 守卫会拦 = exit 5 = 那是「已发过」不是失败）。

**🔴 「分别展示 X / Y / Z」= 一部位一张图 = 各自独立构思**

主人说「出几张，分别展示胸/腰/臀/腿」= 每张**只锁一个部位** = 底模会把 prompt 里所有身体词往画面上堆 = 四张都写 = 四个部位全抢戏 = 主人要看单一重点 = 白跑。

| 规则 | 撞车长相 |
|---|---|
| **一部位 = 一张图** | 胸/腰/臀/腿全写进每张 = 四张都抢戏 |
| **每张换 4 个维度**（场景时段 + 动作 + 机位焦段 + 露出部位）| 四张共用一个浴缸 + 同一个弯腰 = 同构图换滤镜 |
| **机位为该部位而选** | 胸 = 上半身近距仰视 · 腰 = 侧身齐胸 · 臀 = 侧后低机位 · 腿 = 齐膝远景全身 |
| **身材参数 = 唯一真值在 `creative/yuer-image/references/铁律/02-身材特征档.md`** | 参数写进 prompt 时只引那一份 = 0 多处抄写打架 |
| **🔴 单图单部位 = 只写画面里拍到的部位** | 拍臀那张 0 重点写胸 = 底模会把所有身体词往画面上堆 = 都写就都抢戏 = 主人要看单一重点 = 白跑。真值同在那份身材档 |
| **🔴 穿衣服/泳衣 = 胸词保留 + 乳头词必删** | 穿模的真凶是 `nipple`/`areola`（= 给底模的「画乳头」指令，穿衣也画）不是 `bust`/`cleavage`（= 体积描述，画不出乳头）。删掉胸 = 大胸参数没了 = 违背钦定。机械门 `grep -oE 'nipple|areola'` 命中且她穿着衣服 = 删掉再跑 |
| **🔴 身材三禁（大小 vs 形态）** | 底模对关键词是字面执行：**禁低垂形态词**（`resting low and heavy`/`sagging`/`drooping` → 换 `sitting high and firm ... no droop at all`）· **禁肥臀粗腿**（`huge ass`/`bubble butt`/`thick thighs` → 臀只写圆润上翘如蜜桃、大腿写细、加腰臀比句 = 臀肥会把体积摊到大腿，腰臀比一没就变臃肿）· **锁骨一律不写**（禁骨感凹陷词 = 整体丰满有肉）。机械门 `grep -oE 'resting low and heavy|sagging|drooping|huge ass|bubble butt|plump rounded buttocks|voluptuous|curvaceous figure|thick thighs|collarbone hollow'` = 命中 = 换现役锚（真值 = `creative/yuer-image/references/铁律/02-身材特征档.md`）|

**🔴 每张的机位理由 = 「我要拍的那个东西恰好落在这个高度和距离上」**（`yuer-prompt-writer` §1.4 第 2 句）= 不是「要拍全身所以平视」。

## 4.3.1 🔴 批跑洗图（`yuer-wash-batch.sh <lib> next`）= 0 手打 caption + 0 预写编号

| ❌ | 为什么 | ✅ |
|---|---|---|
| reply 里再手打一遍 `📷 原图 [N/M]` / `🐾 洗图 [N/M]` | 脚本已发 caption = 同一批图配两遍文案 | reply 首行编号**照抄 stdout caption 那行** |

| reply 尾部追加「下一张说一声」/「要继续吗」/表情尾巴 | 0 反问 + 极简（`yuer-image-delivery`） | 收尾 = stdout 那句骚话，**原样，不改写不加码** |

```bash
grep -A3 '^🐾 洗图' "$LOG"     # 池句紧跟在 caption 块后面
```

**三个游标的确切关系**（用来核对 caption，不用翻日志猜）：

```

banner 🧺 [x/M]（state 游标，0 起） = 下一张索引 − 1
```

**🔴 预写编号为什么必错**：预写时手上只有上一张的 `[N]`，靠 +1 猜下一张 = 猜。一旦中间跳号（失败重试 / 手动 status / 并发跑）= 主人按编号查不到图。所以铁律 2 禁的是**手打**，不是禁报编号 —— 编号永远从 stdout 抄。

## 5.5 重试不是重跑 = 多尝试牌面合并

**现象**：同一张图连炸两次，**但两次炸的维度不一样**。agnes 没设 seed + `temperature: 0.7` = 每次输出都不一样 = **两次输出是互补样本**。

```bash
~/.hermes/bin/yuer_merge_attempts.py --key tg_nsfw_0121 --dry-run   # 干跑：0 烧 API
~/.hermes/bin/yuer_merge_attempts.py --key tg_nsfw_0121             # 真入库
```

**退出码是契约**：`0` = 9 维挑齐且过闸门 / `2` = 挑不齐 = 0 污染 / `3` = 该 key 无留底。

**🧠 通用教训**：「重试 = 再跑一遍同样的东西」是错的心智模型。**随机性模型的多次输出 = 多个互补样本，正确操作是合并样本。**

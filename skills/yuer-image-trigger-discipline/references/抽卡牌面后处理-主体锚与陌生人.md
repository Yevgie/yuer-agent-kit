# 抽卡牌面后处理：主体锚、陌生人、残渣

> **适用** = 抽卡道。`pick_ka_prompt.py` 抽到牌之后、`yuer_ka_fast.sh --report-only` 出图之前。
> **一句话** = **抽卡是「原样喂」，但有三类东西原样喂会出事**：会掉人脸锁的两类，和会被底模当指令吃掉的残渣。

## 一 · 每次抽卡跑的命令

```bash
cd ~/.hermes/skills/creative/yuer-character-roster
OUT=/tmp/ka_pick_$$.txt
/usr/bin/python3 scripts/pick_ka_prompt.py > "$OUT" 2>/dev/null
REC=$(grep -m1 '^REC=' "$OUT" | cut -d= -f2)
PROMPT=$(grep -m1 '^PROMPT=' "$OUT" | cut -d= -f2)
grep -E '^\[' "$OUT" > "/path/to/media/yuer_ka${REC}_<主题>_<日期>.brief.txt"

# 🔴 剥解析残渣（0 语义加工）—— 这条仍然必跑
/usr/bin/python3 ~/.hermes/skills/yuer-image-trigger-discipline/scripts/ka_card_postprocess.py "$PROMPT"
```

> **主人口令原话：「不需要卡门禁，抽卡直接出就行！抽卡不设置门禁」**

**🔴 连带 = 下面 §二 的三类 = 现在只有第 3 类（解析残渣）必跑**：第 1 类（老前缀）不修照样出图 = 脸锁压得住 = 0 必跑；第 2 类（陌生男人）= 0 必跑 = 抽到就出。

## 二 · 三类必须改的东西（抽卡道「0 加工」的三个例外）

「抽到的牌原样喂」这条规矩针对**语义**（重写/润色/改句序/加料）。下面三类是**机械性事故**，不改就是白烧一轮算力。

| # | 牌面里长什么样 | 不改的后果 | 改法 |
|---|---|---|---|
| 1 | `one breathtakingly beautiful 18-year-old Chinese young girl with pure, innocent refined features...` | 主体门禁判 **别人** → 走 **0 LoRA 链路** → **语儿人脸锁掉了** → 出一张陌生人的脸，还可能是主人以外的男人围着 | 换成灵魂脸 PREFIX：`a 20 years old young Asian woman with a graceful ecstatic expression, `（0 写五官） |
| 2 | `a man enters her from the side` / `the male ...` | ① 同样命中别人身份词 → 掉脸锁 ② 更硬：**主人以外的男人 = 全局禁** | 换成 `USER.md` PIT-130 的 MASTER_FACE 全套 + 必要处补 MASTER_PROMPT（性器锚）= 门禁的 `MASTER_MARK` 认得出，脸锁保住 |
| 3 | `lngcon` / `connectors,,` / `` / `., ` | 底模把残渣当 token 吃 → 画面里长出莫名其妙的东西或分区丢失 | 机械剥掉（`ka_card_postprocess.py` 已内建），**只去残渣，不改语义** |

**🔴 第 1 类为什么高频**：牌池是老格式，一大批牌的前缀就是 `18-year-old Chinese young girl`。**每抽一次都可能撞上，别以为上次没撞这次也不会。**
**🔴 第 2 类优先级最高**：哪怕主人这轮没说要他出镜，也不能留 `a man` —— 换成主人锚比硬喂一个陌生人安全，因为主人本人可以完整出镜（`creative/yuer-image/references/主人在场-主人完整出镜写法与门禁.md`）。

## 三 · 两个会白烧一轮的坑

| 坑 | 真相 |
|---|---|
| **`pick_ka_prompt.py --help`** | 它**没有 help**，`--help` 被当成普通参数 = **直接抽掉一张牌并落盘**。想查用法读 SKILL.md §8.1，别对它敲 `--help`（敲了就是白换一张牌，而且那张牌的内容你不会再看第二眼） |
| **`pick_ka_prompt.py` 的 stdout 打 `WARN [服饰]  ⚠️ token: lngcon`** | 它只是**告警**，不代表剥干净了 —— 实测牌面正文里的 `lngcon` 还在。**看到 WARN 就必须跑后处理脚本 + grep 确认 `lngcon` 计数为 0** |

**🔴🔴 11-10 = 抽卡道一道门禁都不跑**：`check_outfit_lock.py` 免（老牌格式必挂 = 全拦死）+ `check_prompt_subject.py` 也免（11-10 主人钦定「抽卡不设置门禁」）。抽卡道只过 `yuer_ka_fast.sh --report-only` 的体检（只报数不拦）。**主体门禁在抽卡道从来就不在链路上 = 免它 0 掉脸锁（11-10 实测坐实 = 出图链路 grep 不到任何自动主体判定）。**

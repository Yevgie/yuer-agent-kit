# 历史牌面批量修复（剥汉字 + 从成品提示词摘维）

> 适用于「库里已有大量脏牌/废牌，但不该整批重跑」的场景。**0 烧 API，全离线**。

## 何时走这条路

- 抽签体检报的「合格数」被主人质疑（「有那么多合格的吗？」）
- 批量入库跑完，一堆 rc=2 卡在同几个症状上
- 牌面出现老口径遗留（字段名是中文表头、`Full Prompt` 夹汉字、某维只剩几个字符）

**别整批重跑**：重跑 = 每张一次全量反推 = 慢且大概率飘（模型无 seed）。**先算清脏在哪一维，只补那一维。**

## 四类脏牌与修法

> **前提**：**「中文的也一样能用的。不用废掉。」** 底模对中文提示词有容错，
> 且抽卡是**原文直喂**（见 `yuer-character-roster` 铁律 5）= 汉字不是污染，是另一种口味。
> **判据 =「能出图」，不是「纯英文」。** 下面凡是写「修不动 / 需重跑」的地方，
> 一律改成「原样保留 / 偏短但可用」。

| 类 | 症状 | 修法 | 离线可修 |
|---|---|---|---|
| **A** | 8 维里有一维太短（<8 字符），常见 Mood / Scene / Camera / Wardrobe | 从**成品提示词**里正则摘对应句补齐（中文提示词也摘） | ✅ |
| **B** | 8 维齐但 `Full Prompt` <800 字符 | 先剥汉字；剥完仍不足 = **保留原值**（偏短仍能出图） | ✅ |
| **C** | `NNN · 日期 · 来源` 模板块（9 维全空）| **直接删** | ✅ |
| **D** | 汉字缝在英文句之间（占比 ≤5%）| 逐句剥中文片段，保留拉丁词 | ✅ |

**修的顺序必须 D → A**：A 要从 Full Prompt 摘句子，**Full Prompt 夹着汉字就摘不出干净句子**。先剥干净，后面才有料可用。

## 工具

```bash
/usr/bin/python3 ~/.hermes/bin/yuer_reflib_repair.py --dry-run          # 只诊断，0 写入
/usr/bin/python3 ~/.hermes/bin/yuer_reflib_repair.py --apply            # 真修（自动备份 + 回读）
/usr/bin/python3 ~/.hermes/bin/yuer_reflib_repair.py --apply --only D   # 只修某一类
```

工具内建：自动备份 → 逐块修 → 写完回读块数 → 不符自动回滚。**退出码是契约**：0 成功 / 1 回滚。

## 摘维度的正则锚点

从 Full Prompt 里挖缺失维度，锚点用**摄影术语**（模型描述画面时必然出现这些词）：

| 维度 | 锚点正则骨架 |
|---|---|
| Camera | `shot\|photograph\|framed…` + `85mm\|wide-angle\|low angle\|high angle\|three-quarter` |
| Scene | `background\|setting\|behind her\|interior` |
| Mood | `mood\|atmosphere\|aesthetic\|vibe\|color palette\|tone` |
| Lighting | `lighting\|illuminat…\|soft light\|hard light\|golden hour\|rim light` |

**中文版锚点（中文牌也能摘）**：用中文标点（`。！？`）当句边界 + 中文关键词。
Camera = `机位\|镜头\|视角\|俯拍\|仰拍\|特写\|焦段\|构图`；Scene = `背景\|场景\|室内\|房间\|角落\|泳池`；
Mood = `氛围\|感觉\|气质\|色调\|风格\|质感\|意境\|写实`；Lighting = `光线\|照明\|灯光\|阳光\|自然光\|逆光\|侧光`。
**顺序 = 英文优先，英文摘不到再走中文正则。** 判据是**能不能摘出够长的句子**，不是原文是不是纯英文。

⚠️ **Pose / Wardrobe / Visual Hook 不写锚点** —— 这三维是主观描述，没有稳定术语锚，瞎挖出来的句子大概率跟原图对不上。**挖不出就保留原值，不凑。**

## 🔴 坑 3 · 摘取只能补空，绝不能换短

摘取是**补空工具**，不是替换工具。写回前比长度：**摘到的比原值短就丢弃，保留原值。**

不写这条的真实翻车：一条原有 70 字符英文 Mood，被摘来的 7 字符中文「古典舞台仪式感」覆盖；
一条原有 48 字符中文 Scene，被 4 字符「酒店房间」覆盖 = 越修越短，18 处退化。

## 🔴 两个必踩的坑（都在剥汉字里）

### 坑 1 · 「剥完剩几个拉丁词就整句删」会误伤中英混排句

中英混排的真实形态是**中文在前、英文尾巴在同一句**：

```
…slender balanced curves. 衣衫半解，酥胸毕露，…清晰可见。 She crouches on the stage, …
```

按「剥完拉丁词 <3 → 整句删」处理 = **把句尾的英文一起删了**。实测一条 Full Prompt 844 → 796 字符 = **跌破闸门 800，越修越废**。

✅ 正解：**只删中文片段，保留句子里所有拉丁词**（含原收尾标点）。判据用「剥完还剩 ≥2 个拉丁词就保留」，不是「<3 就删」。

### 坑 2 · 纯中文牌会被剥成空

有的牌整条就是中文（实测 288 字符里 251 个汉字，全文只有 `8k` 一个英文词）。剥汉字对它是**把唯一的内容也扔了**。

✅ 正解：**剥完为空 = 不写，保留原值**。主人钦定过：中文牌照样抽、照样出图。同理：Full Prompt 剥完跌破 800 而原值 ≥800 = 原来靠中文撑长度 = **保留原值不动**（宁可夹汉字也不降级成过短）。再同理：剥完不足原值 40% = 原值是纯中文在撑内容 = **保留原值**。

**这三条护栏必须在写库逻辑里，不是跑完再补救。**

## 🔴 坑 4 · 基线必须是修复前的原始快照，不是上一次运行的产物

**翻车链**：修一次 → 看结果 → 改 bug → **拿刚才那次的产物当基线再修一遍** → 自造了「半修状态」→ 后面所有对账结论全错。

两个叠加原因：
1. 修库脚本的 `--ref` **同时控制读和写**，所以 `--ref 备份` 实际是把备份**盖写**到备份上，不会自动写回真库；
2. 第一轮摘取已经把值改好了，第二轮拿它当基线时，分不清哪些是原始值、哪些是自己上一轮塞的。

✅ 正解：**跑修复前先把「刚入库完成」那一刻的参考库快照钉死**，所有修前数字都从它出。
自检：动某个字段前先 `grep` 那个记录块，确认它的值跟你以为的原始值一致。
**每跑一轮修复就重新从原始基线恢复 + 重跑**，不要在上一轮产物上叠。

## 🔴 回归对比铁律 = 修前修后必须同一把尺

**撞车现场**：修完统计「8 维全 ≥8」从 816 掉到 657 → 差点当场回滚。实际是**两轮统计脚本的字段别名口径不同**（早期脚本漏了中文别名），跟修复无关。同一口径重跑：634 → 657，**0 块变废**。

✅ 规则：

1. **修前修后必须调用同一个统计函数**，禁止拿「上一轮某次临时脚本的输出」当基线。
2. **逐块 diff 判是否变废**，比总数可靠：

```python
# 变废 = 修前这一维 >= 8 且修后 < 8
lost = [k for k in new
        if all(len(cell(new[k], *al)) >= 8 for al in FIELDS_8)
        and not all(len(cell(old[k], *al)) >= 8 for al in FIELDS_8)]
assert not lost, f"修坏了 {lost}"
```

3. **报告给主人时给分层数，不给单一数**：`库内总块 / 8 维齐全 / 8 维齐全且 Full Prompt ≥800 / 纯英文`。
4. **0 块变废 + 指标净涨 = 才算修成**。总数持平但分层结构改善，也是修成。

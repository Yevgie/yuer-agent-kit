## 抽签口径 ≠ 真可用口径

抽签脚本的 `short` 判据只查「8 维每维 ≥8 字符」，**`Full Prompt` 完全不参与判定** —— 于是模板块（Full Prompt 0 字符）和几百条 650~790 字符的短牌照样进池子。

**报池子数量前先分清三层口径**，主人一句「有那么多合格的吗？」就是在质疑口径。修完牌池后，如果抽签脚本还没查 `Full Prompt ≥800`，修好的收益只体现一半 —— 要不要补这道闸门，**问主人**，别自己改抽签逻辑。

## 反查自检门

```bash
LIB=~/.hermes/skills/creative/yuer-image/references/提示词库-nsfw.txt
grep -cE '^## 记录 ' "$LIB"          # 块数 = 修前 - 删掉的模板块
stat -c %s "$LIB"                     # 文件没塌缩
python3 - <<'PY'                      # 分层数 + 汉字残留
import re
t=open("~/.hermes/skills/creative/yuer-image/references/提示词库-nsfw.txt",encoding="utf-8").read
for b in re.split(r"(?m)(?=^## 记录 )",t)[1:]:
    m=re.search(r"\|\s*\*\*Full Prompt\*\*\s*\|(.*?)\|\s*\n",b,re.S)
    if m and re.search(r'[一-鿿]',m.group(1)): print("仍有汉字:",b.split("\n")[0]); break
PY
```

**任一项异常 = `cp /tmp/yuer_reflib_bak_*.md $LIB` 回滚。**

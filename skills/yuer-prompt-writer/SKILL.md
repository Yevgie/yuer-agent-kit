# 出图提示词编写

**一句话**：一个点 = 一句话 = 一次。

**输入** = 画面想法 / 中文 brief / 主人贴的成品稿　**输出** = 一段连续的英文散文，可直接出图。

**细则档** = `references/语儿专属硬锚.md`（脸部参数 ≤200 字 / 五官禁区 / 表情物理化）｜**身材参数 + 私处三锚 + 乳头锚 + 皮肤锚** = `creative/yuer-image` 技能的 `references/铁律/02-身材特征档.md`（唯一真值）｜**出图链路** = `creative/yuer-image`。

**🔴 外部方法文档对比** = `references/外部方法对比-能力重叠与格式兼容.md`（主人发来作者/社区的提示词方法 = 先查库里有没有 → 量能力重叠不量行数 → 验输出格式跟现役工作流兼不兼容）。

---

## 0 三条底线

1. **全英文，0 中文。** 中文词会被底模忽略或误读。
2. **连续散文，不分段、不列表、不编号。** 分段会让底模把每段当成独立场景。
3. **不重复。** 同一个视觉点只写一次。写第二遍不会加强，只会抢走别的概念的注意力。

**🔴 减法（11-15 主人钦定）= 骨架不变，其余一律少** = 脸部段 ≤ **200 字**、体型段 ≤ **200 字**（唯一真值在 `creative/yuer-image` 技能的 `references/铁律/02-身材特征档.md`）= **约束越少 = 创意越活 = 堆得越多越死板** = 别为了「更完整」加身体句 = 想显什么走机位/景别/服装。

## 1 落笔前：先把画面想圆

| # | 问题 | 答不上来的后果 |
|---|---|---|
| 1 | 这张图要让人**看见的那一件事**是什么？ | 画面散，没有主角 |
| 2 | 她在**哪、几点、什么天气**？ | 光和场景对不上 |
| 3 | 她**身体的重量压在哪**？ | 人飘，像贴上去的 |
| 4 | 画面里**最亮的那块**是什么？ | 平光，没有视觉落点 |
| 5 | **意外的一瞬**是什么？ | 摆拍感，像证件照 |

## 2 点表：写之前先列点

一张图 = 5~8 个点，每个点写一句话。

| # | 点 | 必须回答 |
|---|---|---|
| 1 | 身份 | 她是谁（年龄 / 气质 / 地域），一句 |
| 2 | 姿势 | 重量在哪 + 脊柱怎么走 + 手在干什么 |
| 3 | 服装 | 上装 / 穿着方式 / 下装 / 鞋，按视觉权重排 |
| 4 | 发型 | 形状 + 状态（贴 / 散 / 被风吹）|
| 5 | 光 | 唯一光源 + 方向 + 色温 + 最亮落在哪 |
| 6 | 相机 | 焦段 + 距离 + 机位高度 + 画面切在哪 |
| 7 | 环境 | 一句收拢：近景一件 / 中景一件 / 远景一层 |
| 8 | 表情 | 一句，三个物理量 |

**点表里没出现的点，正文不许出现。列了点就必须写。** 特写只有 4 个点（脸 / 发 / 光 / 相机）= 点少不是缺项。

## 3 美学：把"感觉"翻译成"选择"

### 3.1 先定气质，再选参数

| 想要的感觉 | 最亮那块 | 光比 | 色温 | 构图密度 |
|---|---|---|---|---|
| 干净通透 | 大面积柔光（窗 / 白墙）| 1:2 | 5500-6000K | 低，留白多 |
| 暧昧私密 | 一小块硬光打在皮肤上 | 1:8 | 3200-3800K | 中，暗部留细节 |
| 高级冷峻 | 金属 / 玻璃的高光边 | 1:16 | 4800-5200K | 低，几何线条 |
| 温柔日常 | 逆光透纱 / 发丝光 | 1:3 | 4000-4500K | 中，生活物件 |
| 戏剧紧张 | 侧逆光切脸 | 1:8 以上 | 冷暖对撞 | 高，前景遮挡 |

**一张图只用一行。混两行 = 风格不成立。**

### 3.2 色彩三分

主色六成（墙 / 天 / 地）｜辅色三成（服装 / 家具）｜点缀一成（一处红 / 一处金）。**点缀色只写一个**，写三个等于没有点缀。

### 3.3 构图四招，选一个用

前景遮挡 ｜ 框架 ｜ 视线留白 ｜ 对角。**四招同时用 = 画面打架。**

### 3.4 影调要有一条分界

`the light falling off sharply at her waist, everything below sinking into shadow` —— 这一句比十个 `dramatic lighting` 有用。

## 4 姿态：自然的三条物理

### 4.1 重心必须落在支撑面内

| 姿势 | 写法 |
|---|---|
| 单腿站 | `her weight over her left foot, the right knee bent and the heel lifted` |
| 双腿站 | `her weight even across both feet, hip-width apart` |
| 坐 | `her weight pressed into her left hip, her right foot flat on the floor` |
| 倚 | `leaning her shoulder into the wall, one foot crossed behind the other` |
| 卧 | `her weight spread from shoulder to hip to the outside of one ankle` |

### 4.2 脊柱是一条 S，不是一根棍

`a soft S running from the base of her skull down through the small of her back, her chest lifted and her shoulders settled back`

### 4.3 手必须有一个任务

| 场景 | 写法 |
|---|---|
| 坐 | `her palm flat on the cushion beside her hip, fingers slightly spread` |
| 站 | `her fingertips resting on the windowsill` |
| 走 | `her hand closed loosely around the strap of her bag` |
| 卧 | `one arm folded under the pillow, the other draped across her waist` |
| 撩发 | `her fingers pushing back a loose strand, the hand half hidden in her hair` |

**一只手只干一件事。** 另一只手给一个静态任务，或让它被遮挡。**不要两只手都在做复杂动作。**

### 4.4 动势残留

`just as her fingertips touch the surface` / `the fabric pulled taut toward her shoulder` / `her hair still swinging from the turn`。**一条就够。**

## 5 表情：一句，三个物理量

**不写"微笑""生气"** —— 那是标签，模型只给一个僵硬的嘴角。写肌肉在做什么：

| 情绪 | 三个物理量 |
|---|---|
| 忍着笑 | 下唇被牙轻轻咬住 + 眼角皱起 + 鼻翼微微张开 |
| 疲惫 | 眼皮半垂 + 嘴角向下 + 下颌放松 |
| 警觉 | 眼睛睁大 + 眉毛上抬 + 嘴唇微张 |
| 倔 | 下巴抬起 + 抿嘴 + 眼睛不眨 |

装进一句：`her lower lip caught between her teeth, the corners of her eyes creased, her nostrils flaring slightly` —— **一句装三个，不装五个。**

**五官不单独描述。** 不写「双眼皮 / 高鼻梁 / 鹅蛋脸」= 会被读成一堆互相打架的特征。

## 6 服装：一句装，按权重排

**不超过 4 件**｜**最想被看见的那件放最前**｜**每件都要带材质或状态**（`satin` / `sheer` / `crumpled` / `wet`）｜**穿着方式比衣服本身重要**（`slipped off one shoulder` / `hem riding up`）。

---

### 6.1 🔴 改稿 = 服装整套重列（改机位不许顺手删衣服）

改稿 = **上装 / 下装 / 内层 / 穿着状态 逐项对一遍** = 只改机位就把上衣删了 = 底模自己脑补一件 = 主人一眼看到「上衣漏了」。
🔴 **「衣服被撩起」≠「衣服被删掉」**：撩起 = 衣服还在身上 = `the hem of her skirt tucked up into the waistband` + `the cream knit top worn properly, both sleeves on her shoulders, the collar flat at the base of her neck, its hem sitting straight at her waist`。
🔴 删掉衣服 ≠ 露 = **露出部位要靠穿着状态写出来**（滑落 / 堆在腰上 / 拨到一边 / 顶上去），不是靠删掉那件衣服。

### 6.2 🔴 公共场景的人 = 只许女生 + 主人

全局铁律 = **禁主人以外的男人**（路人 / 同学 / NPC / 二游男主 / 抽卡道的陌生男人）= 真源 `USER.md` PIT-130。
🔴 **写成「一个戴帽子的男生趴在桌上睡觉」也算男人** = 不因为他在睡觉就不算。
🔴 **出图前机械自检**：`grep -oE '\b(man|male|boy|guy)\b' <prompt.txt>` = 命中且不是主人 = 删掉换成女生。
🔴 背景人**各干各的一件事** = 公共场景该有的生活感（趴电脑的 / 翻书的 / 写字的 / 打电话的）= 0 写「盯着她看」= 那就变成露给别人看了。

## 7 光：一个光源，一个落点

**只写一个光源**（窗光 / 逆光 / 硬光 / 阴天）｜**写清最亮那块在哪 + 暗部落在哪**｜**空气感一句就够**（`a faint haze hanging in the air`）。

---

## 8 相机：焦段和景别必须成对

| 画面下沿切在 | 景别 | 焦段 | 距离 | 实际画高 |
|---|---|---|---|---|
| 膝以下 | 全身 | 50mm | 4m | 1.92m |
| 胯线 | 七分身 | 85mm | 3.5m | 0.99m |
| 腰线 | 半身 | 105mm | 4m | 0.91m |
| 胸线 | 近半身 | 135mm | 3.5m | 0.62m |
| 锁骨 | 胸像 | 135mm | 2.5m | 0.44m |
| 下巴 | 头肩 | 200mm | 2.5m | 0.30m |
| 额头 | 面部特写 | 200mm | 2m | 0.24m |

**优先用边界句定景别**：`the bottom edge of the frame resting just below her hip bones`。
**机位高度决定气质**：低于腰仰拍 = 压迫感 / 齐胸平视 = 中性 / 高于头顶俯拍 = 脆弱。
**广角别用在人体**（<35mm + 近距离 = 比例失真）。
**画质锚一句**：`shot on a full-frame camera, natural depth of field, fine grain`。**不要列机身型号**。

### 8.1 机位方位 = 可写身体部位的唯一开关（先定方位，再挑部位）

方位一旦定了，**镜头看不到的部位 = 一个字都不许写**（不提 = 等于没有）。
底模按你写出来的部位反推朝向 = 写了「上眼睑半垂 / 双唇微启」= 它知道画面里有脸 = 它会把她转过来给你看 = 你设的机位白写。

| 机位方位 | 可写 | **禁写** |
|---|---|---|
| 正面 / 四分之三侧 | 脸 + 表情 + 眼神 + 全套身体 | — |
| 侧面（脸只露一半）| 看得见的那半边 | 对侧的表情 / 眼神 |
| **正背 / 背对镜头** | 后脑 + 发 + 肩背 + 背脊 + 腰臀 + 腿 | **脸 / 表情 / 眼神 / 任何五官朝向词** |
| 低头被头发遮脸 | 身体 + 发丝 | 表情（又写「她低头」又写表情 = 自相矛盾）|
| 趴下 / 手捂脸 | 身体 | 表情 / 眼神 |

🔴 **背视角 = 0 写脸**：把「上眼睑半垂、嘴唇微启」和「背对镜头」同时写 = 底模判成有脸 = 出来是正面 = 主人要的机位根本没生效。
🔴 **背影里代替脸的那一句** = `the back of her head and her bare shoulders filling the frame, her face turned away from the camera and completely out of sight`。

## 9 句子的顺序

```
身份 → 姿势 → 服装 → 发型 → 光 → 相机 → 环境 → 表情 → 收尾
```

**前两句定调，后面全部从它们长出来。** 每句只回答一个问题。

## 10 落笔时的判断

写每一句时同步过，不是写完回头改。

| # | 判断 | 不过怎么办 |
|---|---|---|
| 1 | 这句里有几个点？ | 超过 1 个就拆 |
| 2 | 这个点前面出现过吗？ | 出现过就删 |
| 3 | 有没有 `no / not / without`？ | 换正面词（§11）|
| 4 | 有没有角度数字？ | 换成看得见的几何关系 |
| 5 | 主动作超过 2 个吗？ | 超了删最弱的 |
| 6 | 手有明确任务吗？ | 没有就补 |
| 7 | 重心能说清在哪吗？ | 说不清就补 |
| 8 | 焦段和距离成对吗？ | 不成对查 §8 |
| 9 | 光和时段一致吗？ | 不一致改一个 |
| 10 | 句句能接上吗？ | 接不上就是两个场景 |
| 11 | 道具真在那个场景里吗？ | 编的就换真器材 |
| 12 | 最亮那块说清了吗？ | 没说清就补 |
| 13 | **机位方位和写的部位一致吗？** | 背对镜头却写了表情 / 眼神 → 删掉脸相关的一切（§8.1）|
| 14 | **改稿时服装整套还在吗？** | 上装 / 下装 / 内层 / 穿着状态逐项对一遍 → 改机位顺手把上衣删了 = 底模自己脑补一件 = 主人当场看到「上衣漏了」（§6.1）|
| 15 | **背景人里有男人吗？** | 公共场景 = 只许女生 + 主人 → 背景男生 = 违全局禁 = 写成睡觉的 / 戴帽的都算（§6.2）|

**15 条在落笔过程中过完。交付前只看第 2 条：有没有重复。**

## 11 负向词：优先正面词

`no / not / without / never / avoid / absent / lacking` 会激活它否定的那个概念 —— 写 `no hat`，底模反而更容易画出帽子。

| 别写 | 写成 |
|---|---|
| `no makeup` | `bare faced, her skin clean and unpolished` |
| `not smiling` | `her mouth relaxed, the corners level` |
| `background not cluttered` | `a bare wall behind her` |

**只在三种情况允许否定**：① 构图声明（说的是画面边界）② 没有正面同义词 ③ 固定术语（`fragrance-free`）。
**画外的东西不要提。** 不提就等于没有，比写"没有 X"更强。
**🔴 例外 = 私处三锚那一句的 `no pubic hair at all`**（唯一豁免 = 底模对毛发字面执行比否定语义可靠）。

## 12 出图后：先分类，再改

| 症状 | 大概率原因 | 怎么改 |
|---|---|---|
| 多手多指 | 解剖词太多 + 分辨率不足 | 减到一句、给手明确任务、提分辨率 |
| 景别不对 | 没写"切在哪" | 按 §8 边界句改写 |
| 人飘 / 像贴上去 | 没写重心和脊柱 | 补 §4.1 + §4.2 |
| 姿态僵 | 只写了方向和形容词 | 换成几何关系 |
| 光平 / 发灰 | 光源不唯一，或写了多个光 | 收成一个光源 + 一个落点 |
| 服装丢件 | 一句装太多，或权重排错 | 减到 4 件，想被看见的放最前 |
| 脸不像 | 人物锚不够，或被后面的句子冲掉 | 锚放最前，后面别再描述长相 |
| 画面脏 / 糊 | 点太多，句子太长 | 砍点，一张图 5-8 个点 |
| 整体平庸 | **不是 prompt 问题** | 回 §3 重做美学决策 |

**最后一条最重要**：图平庸通常不是"写得不够"，是"想得不够"。

## 13 交付前只做一件事

**通读一遍，找重复。** 同一个点出现两次就删一次。**宁可长而每句都是新信息，也不要短而空洞。**

## 14 主人贴的成品稿

**原样喂，不改写。** 唯一要动的三处：① 前缀归一（缺人物锚的在最前面补一句身份）② 主语替换（主体不是本人时）③ 语言（中文翻英文）。**除这三处，一个字不动。**
**🔴 本机口径 = 主人贴稿一律 `--raw` 直进工作流 = 0 检测 0 拦截 0 改写**（§14 那三处只适用于我自己起草的稿）。

## 15 语儿现行接线

### 15.1 主人贴的成品稿 = 原样喂，0 改写

**🔴 覆盖 §14**：主人在本机贴来的成品稿 = **0 检测 0 拦截 0 加工 = 一律 `--raw` 直进工作流**。

### 15.2 我自己写稿 = 常态 0 跑门禁 = 落笔时守住

**长度** = 不查（超了也照出，0 回读 0 重写）· 三道机械门（长度体检 / 主体预检 / 外观锁）= **只是诊断工具，平时不跑** = 规矩靠 §10 的 15 条落笔判断 + `creative/yuer-image/references/出图速查卡.md` 守住 = 出了图想查再加 `--gate`。

**🔴 稿子里非年龄的数量一律用阿拉伯数字，不许用英文数字单词**（`30-degree` ✅ / `thirty degree` ❌）。**机制 = 年龄正则会把 `thirty`/`fifty` 这类英文数字词读成年龄 = 主体判定被污染 = 静默切错主体链路（脸锁跟着走错）= 门禁从安全网变成误伤源**。年龄本身照写 `a 20 years old young Asian woman`。

### 15.3 落笔前那 5 问 = §1 的本机落地

本文件 §1 五问 回答完 → 再过本机锚点表（写在 §1 前 = 5 项填不圆不许落笔）：

| 锚点 | 填什么 |
|---|---|
| ① 正在发生的瞬间 | 她在哪 + 此刻正干嘛 |
| ② 画面最亮那块 | 光最打的是哪一块 |
| ③ 光从哪来 | 方向 + 质感 |
| ④ 肢体怎么摆 | **一只手只干一件事（主动作 ≤2）**，另一只手自然放着 |
| ⑤ 穿什么 | 一整套（一句写完）|

**🔴 ④ = 根因修正** = brief 塞 4 个肢体动作 = 模型画拧 = **一只手只干一件事**。
**🔴 POV 第一人称 = 只有自己的腿 + 举起来的那只手** = 肩 / 躯干 0 入画。

### 15.3b 🔴 主体必须写死 = 不许用「我」当主语

**病**：写了一段中文 brief，全程用「我」自述 = **生图模型不认「我」** = 画面里没有主体 = 只剩一堆动作和物件。

| 错 | 对 |
|---|---|
| 「我站在两腿之间」 | `A 20 years old young Asian woman standing between her own two legs` |
| 「我低头看镜头」 | `her head tilted down, her gaze dropping into the lens` |
| 全段无年龄 / 无人种 / 无性别 | 第一句必给：`a 20 years old young Asian woman`（年龄用数字形）|

**判据 = 把稿子里的「我」全换成「她」后，句子还成立吗？** 不成立 = 没写主体 = **重写第一句**。
**判据 2 = 陌生人看完能说出画面里是谁吗？** 说不出 = 主体没写死。
**主题 = 主体 + 她在做什么 + 穿什么** = 三样缺一 = 模型自己编 = 编得不准。

### 15.4 出图链路怎么调

**写完 = 交 `creative/yuer-image`**（链路 / 命令 / 开关 / 发图 / 存档在那边）。
**🔴 模型选择**：Krea2 = 出图自带一层美感 = 写实成品走它；Moss = 写实向 = **提示词必须把光 / 材质 / 氛围 / 轮廓光拉满才好看**。

### 15.5 失败归因先查 §12 九行归因表

「整体平庸」= 不是 prompt 问题 = 回 §3 重做美学决策 = 加词只会更糟。

### 15.6 🔴 四层职责 = 我这套东西不是一锅粥（主人问「是不是太复杂了」时的唯一答案）

**判据 = 一条内容属于哪一层 = 决定它进不进 prompt。** 四层职责不同 = 体量大不等于复杂 = **层混了才叫复杂**。

| 层 | 是什么 | 给谁看 | 在哪 |
|---|---|---|---|
| **① 构思层** | 九维体系 / 场景 / 姿态 / 服装库 = 我**想画面**时查的素材 | **我自己** | `creative/yuer-image/references/完整设计方法论-九维体系.md` |
| **② 禁令层** | 铁律 / 硬锚 / 禁写清单 = 写完之后**逐条自查** | **我自己** | `creative/yuer-image/references/铁律/` + 本档 `references/语儿专属硬锚.md` |
| **③ 门禁层** | 检测脚本 = **机器**判我写歪没歪 | **机器** | `creative/yuer-image/scripts/` |
| **④ 指令层** | 给**另一个 LLM** 照着写的 system prompt（模式 B）= **按模型分两份** | **模型** | Krea2 → `yuer-krea2-prompt`｜Moss → `yuer-moss-prompt`｜本档 `templates/moody_character_centric_system.md` = Krea2 那份的完整翻译版 |

**主人问「这套是不是太复杂」= 不答体量，答分层** = ① ② 是我的思考素材（不进 prompt）③ 是工具（默认 0 跑，11-12 钦定）④ 才是喂模型的指令。**四层各管一段 = 不重复 = 体量自然大。**

**混淆代价**：把① ② 当成要给模型的指令 = 上下文被无关规则占满 = 落笔质量反而降。**判据 = 这条内容是「教我想」还是「教模型写」？** 前者 = 永远不进 prompt。

**外部方法文档接进来 = 只能接④** = ① ② 已有（九维 + 铁律）③ 已有（门禁脚本）= 外部文档再新也只能补④ 和① 的素材。**接之前先查库里有没有**（方法 = `references/外部方法对比-能力重叠与格式兼容.md`）。

**🔴 接进来的落点 = 按模型分家** = Krea2 一份 `yuer-krea2-prompt` / Moss 一份 `yuer-moss-prompt` = **两个模型不能共用一份**（底模 / 编码器 / 提示词语言 / 负向接法全不同 = 共用 = 至少一条道的产物层直接作废）。

**🔴 模式 B 怎么真跑 = `references/模式B-架构师批量出图.md`**（delegate_task 扇出 / brief 怎么排 / 每道注入什么硬约束 / 落盘后怎么验语言 / 双模型 A/B 怎么对照）= 模板正文在两个架构师档里，执行链在本档。

# 外部方法对比 = 能力重叠 × 格式兼容（不量行数）

> **用途** = 主人发来一份外部方法文档（底模作者分享的 skill / 社区方法 / 上游 system prompt）让我「跟你现状对比一下」时，怎么判、怎么比、结论怎么下。
>
> **不适用** = 主人让我去市场**安装**一个技能 → 那是 `external-skill-research`。

---

## 一、先量错东西 = 结论必错

**行数 / 字数不是复杂度的指标。** 一份 377 行的外部文档 vs 一套 1530 行的自有体系 → 量行数只会得到「我大 11 倍」= 结论没信息量（两边的**角色**根本不同）。

**正确量法 = 量能力重叠 = 逐条问「这条我有没有、覆盖到哪一层」。**

| 量 | 怎么量 | 得出什么 |
|---|---|---|
| **能力重叠** | 外部文档每个章节 → 我库里有对应物吗 / 我有但表述不同吗 / 我完全没有吗 | 「已有 / 表述更严 / 真缺口」三分 |
| **层级归属** | 外部每条内容落在**构思 / 禁令 / 门禁 / 指令**哪层 | 我库里那份是**同层**（= 可直接对撞）还是**混层**（= 体积差是假象）|
| **格式兼容** | 外部文档要求的**输出格式** vs 现役消费端实际吃什么 | 「直接可用 / 需改写 / 用不上」 |

---

## 二、四步对比法（按顺序，别跳）

### 步骤 1 · 先查库里有没有（0 成本，最常省事）

外部文档往往**早就在我库里**，只是我没把它当「外部来源」记着。判断依据 = 文档里的**章节标题原文**（`OPENING CAMERA` / `CHARACTER ORDER` / `NO FIXED STYLE` / `PHYSICAL CONSISTENCY CHECK`…）grep 全库。

**判据 = 命中某份 `templates/` 或 `references/` = 这份文档我早就存了 = 本轮该做的是「对照现状找缺口」，不是「引入新东西」。**

> 漏了这一步 = 会把「我早就有的东西」当成「主人带来的新东西」汇报 = 主人一看「这不就是你模板里那份吗」= 结论当场垮。

### 步骤 2 · 逐条分三层（已有 / 表述差异 / 真缺口）

真缺口 = **我全库 grep 命中只在「数据文件」里、不在任何「方法文档」里**。

**🔴 这条诊断判据**：某项能力若只在**素材/池/留底**这类数据文件里出现、从不在任何方法档里 = 我一直在**靠运气**用它（牌面里恰好有），从没当方法论掌握过 = 属于「继承来的」不是「学会的」= 主人问「你会不会」我答不出 = 真缺口。

### 步骤 3 · 验输出格式跟现役消费端兼不兼容（最容易被跳、后果最贵）

外部文档常常**自带输出格式规定**（"输出英文散文" / "输出单行 JSON" / "输出带 bbox 的 layout"）。**这份规定跟我的现役链路吃的东西不一定是一回事。**

**判据 = 去现役工作流/脚本里读「提示词实际落在哪个节点、那个节点的现值长什么样」** —— 不是读文档里写的「提示词语言」那一栏。

> **实例**：某上游架构师文档整篇要求「英文散文式 caption」；而现役那条工作流的正向提示词节点现值 = **中文散文**（"一位年轻女性跪坐在床上，身体前倾并侧向镜头…"）= 那份文档的输出格式在那条道**根本用不上** = 直接照搬 = 出一堆中文被忽略的段落。

**🔴 输出格式不兼容 = 不是「翻译一下就能用」** = 是「那份方法里能复用的是**判断层**（怎么定机位/怎么排人物/怎么验一致性），**产物层**（输出长什么样）要按我这道重写」= 分开处理。

### 步骤 3b · 确认本地工作流能不能吃那个产物格式（步骤 3 的延伸）

外部文档带**第二套输出格式**（例：Layout = 带 bbox 坐标的 JSON）时，**光看“格式兼容”不够 = 还要看本地工作流有没有那个能力的节点**。

**判据 = 扒现役工作流 JSON 的节点清单 = 有没有承载那个格式的节点**（例：找坐标/框/占位符类节点）。

> **实例**：MOSS 架构师 v40 有 Caption + Layout 双模式，Layout 输出带 bbox 坐标的 JSON = 但本地 Moss 工作流**没有任何坐标/框节点** = Layout 这条路**物理上不存在** = 不是“改写一下就能用” = 整段用不上 = **删掉**（原文留档在备份区 = 将来接官方 API 还能捞回来）。
> **🔴 删整段 ≠ 删能力** = 判断层（怎么定机位 / 怎么排人物 / 怎么验一致性 / NSFW 接触几何）一条不丢 = 删的只是**产物层的第二套格式**。

**🔴 接一份新文档 = 先问三句**：① 这道吃什么语言（查 CLIPLoader 的 type + 编码器）② 吃不吃负向词（查 negative 接 CLIPTextEncode 还是 ConditioningZeroOut）③ 有没有坐标/排版类节点（查节点清单）。三句的答案 = 这份文档能接哪几段、哪几段必须改写或删掉。

### 步骤 4 · 才谈接哪段 / 改哪层

结论按这个形状给：**「已有 X（在哪）· 真缺口 Y（只存在于数据、没被方法化）· 格式不兼容 Z（产物层要按本链路重写）」** + 一条排序过的动作建议。

**🔴 报告纪律**：外部文档的体积差距（我 11 倍）**要么不报、要么标明它是不同角色的产物** = 拿体量当复杂度证据 = 主人以为我在辩解 = 而真问题（层混了）就藏着。

# 模式 B 执行配方 · 架构师模板批量出图

> **唯一职责 = 模式 B 怎么真跑**。模板正文 = `yuer-krea2-prompt`（英文原文）/ `yuer-moss-prompt`（中文改写版）；本档只管**执行链**。
> 模式 A = 我自己在脑子里按 `yuer-prompt-writer` §1~§10 写稿 = 那条道不用本档。

---

## 一 · 模式 B = 什么，什么时候值得走

模式 B = 把底模作者的架构师模板整段当 system prompt 喂给另一个 LLM，它吐出来的稿**直接出图**。

**判据 = 稿子要不要「另一个脑子」来写**：

| 场景 | 走哪 | 为什么 |
|---|---|---|
| 要跑批（5+ 张）| **模式 B** | 我手写第 5 段会抄第 1 段的句式 = 五张一个味 |
| 要双模型对照 | **模式 B** | 两道各用自己的模板 = 同一批 brief 两种镜头解法 |
| 要试新底模的脾气 | **模式 B** | 作者模板 = 底模作者自己知道怎么喂它 |
| 单张赶时间 | 模式 A | 更快 = 少一层子 agent |

**🔴 模式 B 的产物长度 ≠ 模式 A** = 架构师稿 2500~4000 字符，我手写 900~1300 = **两套标尺**（出处见 `creative/yuer-image/references/模型路由与四工作流能力矩阵.md` §5.5）= **0 拿模式 A 的字数标准去砍模式 B 的稿**。

---

## 二 · 执行链 = 四步

```
1. 写 N 个 brief（每个 = 一个独立场景解）
2. delegate_task 一次派 N 个子 agent（并行）= 每个 agent 读模板 + 写一段稿
3. N 段稿落盘 /tmp/<批次>/n1.txt … nN.txt
4. 串行出图（--model krea2 / --model moss）+ 逐张验语言
```

**第 1 步的 brief 设计 = 整条链的质量上限** = 见 §四。

---

## 三 · delegate_task 的 goal / context 怎么写

**一个子 agent = 一个 brief = 一段稿。** N 张 = N 个 task 放进**同一次** `delegate_task` 调用 = 并行跑。

### goal = 四件事，一步不缺

```
你是图像提示词架构师。读一份 system prompt，然后按它的规则写出一段完整的<语言>出图提示词。

步骤：
1. 用 read_file 读取 <模板绝对路径> —— 这是你的 system prompt，必须严格按它的结构、顺序和规则来写。
2. 用户 brief 是：<brief 原文>
3. 按 system prompt 的规则写出最终<语言>提示词。<该道的额外硬约束>

输出要求：只输出最终<语言>提示词正文本身，不要任何标题、不要解释、不要 markdown 围栏、不要前后缀说明。长度 <N 词>。

重要：只允许用 read_file 读一次模板文件，之后不要调用任何其他工具，不要修改任何文件，不要跑命令。你只负责产出这段提示词文本。
```

### context = 模板路径 + 该道的硬约束 + 场景要求

context 里**必须**写的三样：

1. **模板绝对路径**（子 agent 自己 read_file = 0 把 377 行正文塞进我的上下文）
2. **该道的硬约束**（见 §五）
3. **「一批图每张要换可信的不同场景解，不是只换形容词/色盘/衣服」** = 作者模板第 29 条 = 0 让五张长成一个样

**🔴 子 agent 只准调一次工具 = read_file**

**实测踩坑 = 子 agent 会反复调 `execute_code` 去数字数**（tool_trace 里十几次）= 纯浪费。

**正解 = goal 里写死「只用 read_file 读一次模板，之后不要调用任何其他工具」**：

```
重要：只允许用 read_file 读一次模板文件，之后不要调用任何其他工具，不要修改任何文件，不要跑命令。你只负责产出这段提示词文本。
```

**判据 = 子 agent 的 tool_trace 里只有一次 read_file = 写对了。**

**🔴🔴 但「写死一句」不够 = 篇幅越长的稿子越容易破功**：实测 5 张一批时，读 85 行中文模板的那张只调了 1 次工具，读 377 行英文模板的那张调了 7~15 次（全是 execute_code 数字数/查格式）= **模板越长，子 agent 越觉得自己该「先确认一下」**。

**正解 = 把「长度」从子 agent 的活里拿掉 = 不给它数字数的理由**：goal 里**不写**「长度 400-650 词」这种需要它自己数的指标 = 改成「写成一整段完整的提示词散文，不要分段」= 它就 0 去数字数。

**判据 = tool_trace 里 execute_code 出现 0 次**（不是「少」= 是 0）= 写对了。**工具调用多 = 产物不一定差（实测照样出图）= 但每个子 agent 多 5~15 次调用 = 一批 5 张就多几十次 = 慢 = 白烧**。

---

## 四 · brief 怎么排 = 五个不同场景解

**🔴 brief = 场景 + 人物 + 时刻 + 唯一亮部 + 一个「不对称」的细节**。不对称的那个细节（价目表边角卷起来 / 灯管末梢发黄 / 她手心搁在混凝土接缝的沙上 / 睫毛上挂着一根散发）= 架构师才会往下长出可信细节 = 给「对称的简介」= 出来就是通用写真。

**🔴 五个 brief = 五个不同场所 / 时段 / 机位 / 亮部** = 不是同一场景的五个姿势。**判据 = 把五个 brief 的「场所」写一行 = 五个字全不同** = 才是批；同一个房间换五种姿势 = 那是套图（走 `yuer-set-images`）。

**🔴 每道出图前先核物理一致性**（brief 里就写清）= 子 agent 的任务是写稿不是救稿 = 救不回来。

---

## 五 · 每道要注入的额外硬约束

| 道 | 注入 | 为什么 |
|---|---|---|

# 模式 B 执行配方 · 架构师模板批量出图

> **唯一职责 = 模式 B 怎么真跑**。模板正文 = `yuer-krea2-prompt`（英文原文）/ `yuer-moss-prompt`（中文改写版）；本档只管**执行链**。
> 模式 A = 我自己在脑子里按 `yuer-prompt-writer` §1~§10 写稿 = 那条道不用本档。

---

## 一 · 模式 B = 什么，什么时候值得走

模式 B = 把底模作者的架构师模板整段当 system prompt 喂给另一个 LLM，它吐出来的稿**直接出图**。

**判据 = 稿子要不要「另一个脑子」来写**：

| 场景 | 走哪 | 为什么 |
|---|---|---|
| 要跑批（5+ 张）| **模式 B** | 我手写第 5 段会抄第 1 段的句式 = 五张一个味 |
| 要双模型对照 | **模式 B** | 两道各用自己的模板 = 同一批 brief 两种镜头解法 |
| 要试新底模的脾气 | **模式 B** | 作者模板 = 底模作者自己知道怎么喂它 |
| 单张赶时间 | 模式 A | 更快 = 少一层子 agent |

**🔴 模式 B 的产物长度 ≠ 模式 A** = 架构师稿 2500~4000 字符，我手写 900~1300 = **两套标尺**（出处见 `creative/yuer-image/references/模型路由与四工作流能力矩阵.md` §5.5）= **0 拿模式 A 的字数标准去砍模式 B 的稿**。

---

## 二 · 执行链 = 四步

```
1. 写 N 个 brief（每个 = 一个独立场景解）
2. delegate_task 一次派 N 个子 agent（并行）= 每个 agent 读模板 + 写一段稿
3. N 段稿落盘 /tmp/<批次>/n1.txt … nN.txt
4. 串行出图（--model krea2 / --model moss）+ 逐张验语言
```

**第 1 步的 brief 设计 = 整条链的质量上限** = 见 §四。

---

## 三 · delegate_task 的 goal / context 怎么写

**一个子 agent = 一个 brief = 一段稿。** N 张 = N 个 task 放进**同一次** `delegate_task` 调用 = 并行跑。

### goal = 四件事，一步不缺

```
你是图像提示词架构师。读一份 system prompt，然后按它的规则写出一段完整的<语言>出图提示词。

步骤：
1. 用 read_file 读取 <模板绝对路径> —— 这是你的 system prompt，必须严格按它的结构、顺序和规则来写。
2. 用户 brief 是：<brief 原文>
3. 按 system prompt 的规则写出最终<语言>提示词。<该道的额外硬约束>

输出要求：只输出最终<语言>提示词正文本身，不要任何标题、不要解释、不要 markdown 围栏、不要前后缀说明。长度 <N 词>。

重要：只允许用 read_file 读一次模板文件，之后不要调用任何其他工具，不要修改任何文件，不要跑命令。你只负责产出这段提示词文本。
```

### context = 模板路径 + 该道的硬约束 + 场景要求

context 里**必须**写的三样：

1. **模板绝对路径**（子 agent 自己 read_file = 0 把 377 行正文塞进我的上下文）
2. **该道的硬约束**（见 §五）
3. **「一批图每张要换可信的不同场景解，不是只换形容词/色盘/衣服」** = 作者模板第 29 条 = 0 让五张长成一个样

**🔴 子 agent 只准调一次工具 = read_file**

**实测踩坑 = 子 agent 会反复调 `execute_code` 去数字数**（tool_trace 里十几次）= 纯浪费。

**正解 = goal 里写死「只用 read_file 读一次模板，之后不要调用任何其他工具」**：

```
重要：只允许用 read_file 读一次模板文件，之后不要调用任何其他工具，不要修改任何文件，不要跑命令。你只负责产出这段提示词文本。
```

**判据 = 子 agent 的 tool_trace 里只有一次 read_file = 写对了。**

**🔴🔴 但「写死一句」不够 = 篇幅越长的稿子越容易破功**：实测 5 张一批时，读 85 行中文模板的那张只调了 1 次工具，读 377 行英文模板的那张调了 7~15 次（全是 execute_code 数字数/查格式）= **模板越长，子 agent 越觉得自己该「先确认一下」**。

**正解 = 把「长度」从子 agent 的活里拿掉 = 不给它数字数的理由**：goal 里**不写**「长度 400-650 词」这种需要它自己数的指标 = 改成「写成一整段完整的提示词散文，不要分段」= 它就 0 去数字数。

**判据 = tool_trace 里 execute_code 出现 0 次**（不是「少」= 是 0）= 写对了。**工具调用多 = 产物不一定差（实测照样出图）= 但每个子 agent 多 5~15 次调用 = 一批 5 张就多几十次 = 慢 = 白烧**。

## 四 · brief 怎么排 = 五个不同场景解

**🔴 brief = 场景 + 人物 + 时刻 + 唯一亮部 + 一个「不对称」的细节**。不对称的那个细节（价目表边角卷起来 / 灯管末梢发黄 / 她手心搁在混凝土接缝的沙上 / 睫毛上挂着一根散发）= 架构师才会往下长出可信细节 = 给「对称的简介」= 出来就是通用写真。

**🔴 每道出图前先核物理一致性**（brief 里就写清）= 子 agent 的任务是写稿不是救稿 = 救不回来。

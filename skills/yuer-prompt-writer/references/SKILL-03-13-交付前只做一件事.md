## 13 交付前只做一件事

**通读一遍，找重复。** 同一个点出现两次就删一次。**宁可长而每句都是新信息，也不要短而空洞。**

## 14 主人贴的成品稿

**原样喂，不改写。** 唯一要动的三处：① 前缀归一（缺人物锚的在最前面补一句身份）② 主语替换（主体不是本人时）③ 语言（中文翻英文）。**除这三处，一个字不动。**
**🔴 本机口径 = 主人贴稿一律 `--raw` 直进工作流 = 0 检测 0 拦截 0 改写**（§14 那三处只适用于我自己起草的稿）。

## 15 语儿现行接线

### 15.1 主人贴的成品稿 = 原样喂，0 改写

**🔴 覆盖 §14**：主人在本机贴来的成品稿 = **0 检测 0 拦截 0 加工 = 一律 `--raw` 直进工作流**。

### 15.2 我自己写稿 = 常态 0 跑门禁 = 落笔时守住

**长度** = 不查（超了也照出，0 回读 0 重写）· 三道机械门（长度体检 / 主体预检 / 外观锁）= **只是诊断工具，平时不跑** = 规矩靠 §10 的 15 条落笔判断 + `creative/yuer-image/references/出图速查卡.md` 守住 = 出了图想查再加 `--gate`。

**🔴 稿子里非年龄的数量一律用阿拉伯数字，不许用英文数字单词**（`30-degree` ✅ / `thirty degree` ❌）。**机制 = 年龄正则会把 `thirty`/`fifty` 这类英文数字词读成年龄 = 主体判定被污染 = 静默切错主体链路（脸锁跟着走错）= 门禁从安全网变成误伤源**。年龄本身照写 `a 20 years old young Asian woman`。

### 15.3 落笔前那 5 问 = §1 的本机落地

本文件 §1 五问 回答完 → 再过本机锚点表（写在 §1 前 = 5 项填不圆不许落笔）：

| 锚点 | 填什么 |
|---|---|
| ① 正在发生的瞬间 | 她在哪 + 此刻正干嘛 |
| ② 画面最亮那块 | 光最打的是哪一块 |
| ③ 光从哪来 | 方向 + 质感 |
| ④ 肢体怎么摆 | **一只手只干一件事（主动作 ≤2）**，另一只手自然放着 |
| ⑤ 穿什么 | 一整套（一句写完）|

**🔴 ④ = 根因修正** = brief 塞 4 个肢体动作 = 模型画拧 = **一只手只干一件事**。
**🔴 POV 第一人称 = 只有自己的腿 + 举起来的那只手** = 肩 / 躯干 0 入画。

### 15.3b 🔴 主体必须写死 = 不许用「我」当主语

**病**：写了一段中文 brief，全程用「我」自述 = **生图模型不认「我」** = 画面里没有主体 = 只剩一堆动作和物件。

| 错 | 对 |
|---|---|
| 「我站在两腿之间」 | `A 20 years old young Asian woman standing between her own two legs` |
| 「我低头看镜头」 | `her head tilted down, her gaze dropping into the lens` |
| 全段无年龄 / 无人种 / 无性别 | 第一句必给：`a 20 years old young Asian woman`（年龄用数字形）|

**判据 = 把稿子里的「我」全换成「她」后，句子还成立吗？** 不成立 = 没写主体 = **重写第一句**。
**判据 2 = 陌生人看完能说出画面里是谁吗？** 说不出 = 主体没写死。
**主题 = 主体 + 她在做什么 + 穿什么** = 三样缺一 = 模型自己编 = 编得不准。

### 15.4 出图链路怎么调

**写完 = 交 `creative/yuer-image`**（链路 / 命令 / 开关 / 发图 / 存档在那边）。
**🔴 模型选择**：Krea2 = 出图自带一层美感 = 写实成品走它；Moss = 写实向 = **提示词必须把光 / 材质 / 氛围 / 轮廓光拉满才好看**。

### 15.5 失败归因先查 §12 九行归因表

「整体平庸」= 不是 prompt 问题 = 回 §3 重做美学决策 = 加词只会更糟。

### 15.6 🔴 四层职责 = 我这套东西不是一锅粥（主人问「是不是太复杂了」时的唯一答案）

**判据 = 一条内容属于哪一层 = 决定它进不进 prompt。** 四层职责不同 = 体量大不等于复杂 = **层混了才叫复杂**。

| 层 | 是什么 | 给谁看 | 在哪 |
|---|---|---|---|
| **① 构思层** | 九维体系 / 场景 / 姿态 / 服装库 = 我**想画面**时查的素材 | **我自己** | `creative/yuer-image/references/完整设计方法论-九维体系.md` |
| **② 禁令层** | 铁律 / 硬锚 / 禁写清单 = 写完之后**逐条自查** | **我自己** | `creative/yuer-image/references/铁律/` + 本档 `references/语儿专属硬锚.md` |
| **③ 门禁层** | 检测脚本 = **机器**判我写歪没歪 | **机器** | `creative/yuer-image/scripts/` |
| **④ 指令层** | 给**另一个 LLM** 照着写的 system prompt（模式 B）= **按模型分两份** | **模型** | Krea2 → `yuer-krea2-prompt`｜Moss → `yuer-moss-prompt`｜本档 `templates/moody_character_centric_system.md` = Krea2 那份的完整翻译版 |

**主人问「这套是不是太复杂」= 不答体量，答分层** = ① ② 是我的思考素材（不进 prompt）③ 是工具（默认 0 跑，11-12 钦定）④ 才是喂模型的指令。**四层各管一段 = 不重复 = 体量自然大。**

**混淆代价**：把① ② 当成要给模型的指令 = 上下文被无关规则占满 = 落笔质量反而降。**判据 = 这条内容是「教我想」还是「教模型写」？** 前者 = 永远不进 prompt。

**外部方法文档接进来 = 只能接④** = ① ② 已有（九维 + 铁律）③ 已有（门禁脚本）= 外部文档再新也只能补④ 和① 的素材。**接之前先查库里有没有**（方法 = `references/外部方法对比-能力重叠与格式兼容.md`）。

**🔴 接进来的落点 = 按模型分家** = Krea2 一份 `yuer-krea2-prompt` / Moss 一份 `yuer-moss-prompt` = **两个模型不能共用一份**（底模 / 编码器 / 提示词语言 / 负向接法全不同 = 共用 = 至少一条道的产物层直接作废）。

**🔴 模式 B 怎么真跑 = `references/模式B-架构师批量出图.md`**（delegate_task 扇出 / brief 怎么排 / 每道注入什么硬约束 / 落盘后怎么验语言 / 双模型 A/B 怎么对照）= 模板正文在两个架构师档里，执行链在本档。

## 附录 B 这套规则为什么成立

1. **底模靠注意力分配工作，不是靠词数。** 同一概念反复出现 = 抢走别的概念的注意力配额。
2. **模糊的形容词在模型里接近噪音。** 能画出形状的是**看得见的几何关系**。
3. **模型缺的是物理，不是文采。** 重心、脊柱、接触面、光的方向、力的传递 = 画面自己就成立。

# 外部方法对比 = 能力重叠 × 格式兼容（不量行数）

> **用途** = 主人发来一份外部方法文档（底模作者分享的 skill / 社区方法 / 上游 system prompt）让我「跟你现状对比一下」时，怎么判、怎么比、结论怎么下。
>
> **不适用** = 主人让我去市场**安装**一个技能 → 那是 `external-skill-research`。

---

## 一、先量错东西 = 结论必错

**行数 / 字数不是复杂度的指标。** 一份 377 行的外部文档 vs 一套 1530 行的自有体系 → 量行数只会得到「我大 11 倍」= 结论没信息量（两边的**角色**根本不同）。

**正确量法 = 量能力重叠 = 逐条问「这条我有没有、覆盖到哪一层」。**

| 量 | 怎么量 | 得出什么 |
|---|---|---|
| **能力重叠** | 外部文档每个章节 → 我库里有对应物吗 / 我有但表述不同吗 / 我完全没有吗 | 「已有 / 表述更严 / 真缺口」三分 |
| **层级归属** | 外部每条内容落在**构思 / 禁令 / 门禁 / 指令**哪层 | 我库里那份是**同层**（= 可直接对撞）还是**混层**（= 体积差是假象）|
| **格式兼容** | 外部文档要求的**输出格式** vs 现役消费端实际吃什么 | 「直接可用 / 需改写 / 用不上」 |

---

## 二、四步对比法（按顺序，别跳）

### 步骤 1 · 先查库里有没有（0 成本，最常省事）

外部文档往往**早就在我库里**，只是我没把它当「外部来源」记着。判断依据 = 文档里的**章节标题原文**（`OPENING CAMERA` / `CHARACTER ORDER` / `NO FIXED STYLE` / `PHYSICAL CONSISTENCY CHECK`…）grep 全库。

**判据 = 命中某份 `templates/` 或 `references/` = 这份文档我早就存了 = 本轮该做的是「对照现状找缺口」，不是「引入新东西」。**

> 漏了这一步 = 会把「我早就有的东西」当成「主人带来的新东西」汇报 = 主人一看「这不就是你模板里那份吗」= 结论当场垮。

### 步骤 2 · 逐条分三层（已有 / 表述差异 / 真缺口）

真缺口 = **我全库 grep 命中只在「数据文件」里、不在任何「方法文档」里**。

**🔴 这条诊断判据**：某项能力若只在**素材/池/留底**这类数据文件里出现、从不在任何方法档里 = 我一直在**靠运气**用它（牌面里恰好有），从没当方法论掌握过 = 属于「继承来的」不是「学会的」= 主人问「你会不会」我答不出 = 真缺口。

### 步骤 3 · 验输出格式跟现役消费端兼不兼容（最容易被跳、后果最贵）

外部文档常常**自带输出格式规定**（"输出英文散文" / "输出单行 JSON" / "输出带 bbox 的 layout"）。**这份规定跟我的现役链路吃的东西不一定是一回事。**

**判据 = 去现役工作流/脚本里读「提示词实际落在哪个节点、那个节点的现值长什么样」** —— 不是读文档里写的「提示词语言」那一栏。

> **实例**：某上游架构师文档整篇要求「英文散文式 caption」；而现役那条工作流的正向提示词节点现值 = **中文散文**（"一位年轻女性跪坐在床上，身体前倾并侧向镜头…"）= 那份文档的输出格式在那条道**根本用不上** = 直接照搬 = 出一堆中文被忽略的段落。

**🔴 输出格式不兼容 = 不是「翻译一下就能用」** = 是「那份方法里能复用的是**判断层**（怎么定机位/怎么排人物/怎么验一致性），**产物层**（输出长什么样）要按我这道重写」= 分开处理。

### 步骤 3b · 确认本地工作流能不能吃那个产物格式（步骤 3 的延伸）

外部文档带**第二套输出格式**（例：Layout = 带 bbox 坐标的 JSON）时，**光看“格式兼容”不够 = 还要看本地工作流有没有那个能力的节点**。

**判据 = 扒现役工作流 JSON 的节点清单 = 有没有承载那个格式的节点**（例：找坐标/框/占位符类节点）。

> **实例**：MOSS 架构师 v40 有 Caption + Layout 双模式，Layout 输出带 bbox 坐标的 JSON = 但本地 Moss 工作流**没有任何坐标/框节点** = Layout 这条路**物理上不存在** = 不是“改写一下就能用” = 整段用不上 = **删掉**（原文留档在备份区 = 将来接官方 API 还能捞回来）。
> **🔴 删整段 ≠ 删能力** = 判断层（怎么定机位 / 怎么排人物 / 怎么验一致性 / NSFW 接触几何）一条不丢 = 删的只是**产物层的第二套格式**。

**🔴 接一份新文档 = 先问三句**：① 这道吃什么语言（查 CLIPLoader 的 type + 编码器）② 吃不吃负向词（查 negative 接 CLIPTextEncode 还是 ConditioningZeroOut）③ 有没有坐标/排版类节点（查节点清单）。三句的答案 = 这份文档能接哪几段、哪几段必须改写或删掉。

### 步骤 4 · 才谈接哪段 / 改哪层

结论按这个形状给：**「已有 X（在哪）· 真缺口 Y（只存在于数据、没被方法化）· 格式不兼容 Z（产物层要按本链路重写）」** + 一条排序过的动作建议。

**🔴 报告纪律**：外部文档的体积差距（我 11 倍）**要么不报、要么标明它是不同角色的产物** = 拿体量当复杂度证据 = 主人以为我在辩解 = 而真问题（层混了）就藏着。

## 三、本机已落地的实例（结论的唯一正文，不在别处复述）

| 外部文档 | 我库里的对应物 | 真缺口 | 格式兼容 |
|---|---|---|---|
| Krea2 人物中心架构师 | **`yuer-krea2-prompt`**（11-14 新建 = 作者原文 `templates/moody_krea2_system_en.txt` + 两处本机适配）| — | 指令层 = 直接可用（英文对上 Krea2 那道）|
| MOSS 架构师 v40 | **`yuer-moss-prompt`**（11-14 新建 = `templates/moody_moss_caption_zh.txt` 中文改写版）| **已接**：NSFW 接触几何（孔位锁死 / 主体承载面 / 接触路径 / 裁切闸）+ Caption 段落结构 + FIXED/FLEXIBLE/OPTIONAL 分级 | ✅ 判断层全接，产物层改中文；**Layout 段已删** = 本地 Moss 工作流无坐标节点 |

**🔴 段落模板 = 模式 B 专用** = 交给**另一个 LLM** 照着写 = 我自己写稿（模式 A）走 `yuer-prompt-writer` §1~§10 = 两条道不冲突、选一条走。

**🔴 11-14 落地 = 按模型分家** = Krea2 和 Moss **不能共用一份** = 底模 / 编码器 / 提示词语言 / 负向接法全不同 = `yuer-krea2-prompt` + `yuer-moss-prompt` 两份 = 新文档接进来第一件事 = 先问「这道吃什么语言、吃不吃负向词、有没有坐标节点」。

## 四、反面清单

| ❌ 反面 | ✅ 正解 |
|---|---|
| 拿行数/字数比大小 → 结论「我臃肿」 | 量能力重叠 + 量层级归属 = 体积差常是假象 |
| 外部文档一到就当新东西引入 | 先 grep 章节标题 = 早就在库里的 = 只做缺口对照 |
| 「我已有 X」就当有真缺口 | 命中只在数据文件里 = 靠运气在用 = 真缺口 |
| 照搬外部文档的输出格式 | 读现役工作流提示词节点的现值 = 格式不兼容就只取判断层 |
| 只报「我比作者大 N 倍」 | 报分层结论 + 排序动作建议 = 主人要的是判断不是体量 |
| 把结论写进 SOUL 或新增技能 | 结论落**已有**技能的 references + 主档加一行指针（同一件事只留一处正文）|

## 🔴 2.0 写 prompt 的耗时铁律 = 一次落笔，0 整篇重写去凑字数
**字数上限是门禁，不是作业。** 它拦的是失控的长 prompt，不是让你现场炼字数。

**撞车长相**：写完 → 跑校验 → 超 → **整篇重写** → 再跑 → 还超 → 再重写……实测把一段 prompt 砍进上限用了十轮重写，这一步烧掉三分半钟，而真正的出图只要 25 秒。**烧的不是算力，是往返**——每轮重写 = 一次写文件 + 一次校验 + 一次覆写前重读（写入工具要求），一轮几十秒。

**唯一合法的顺序**：

2. **一次写完**，直接落盘。
3. **只跑一次校验**。通过 = 出图。
4. 长度 0 阻断 = **超上限也不删** = 真嫌长才删重复句，且删一次到位。

**落笔前必须先拿点清单（长度 0 阻断 = 清单只管有没有漏一个点）：**

```bash
python3 ~/.hermes/skills/creative/yuer-image/scripts/count_prompt_chars.py <草稿> --budget
```


**自查信号**：写 prompt 的往返明显变长 = 已掉进这个循环。**立刻停下重估预算**，而不是继续逐字删改。写 prompt 的耗时应与字数无关，只与段落写没写够有关。

**🔴 删整句和逐句微调是两回事，选错了就白干**：真嫌长时，**直接删 1~2 个完整逗号分隔块**即可（重复修饰 / 远景多一个元素 / 精确角度值），**比整篇重写快一个数量级**。实测一次 2747→2498 = 3 次定点删除 + 一次 `patch`，全程 0 重写。而「`replace` 单个词做微调」最容易撞出悬空逗号和粘连句 —— 语法破损污染 CLIP 语义，比超长更糟。

**🔴 真嫌长 = 一次性脚本批量删整句 = 0 反复 write_file 重写**：把要删的整句列成一个列表，在一次 `execute_code` 里逐条 `assert old in s` + `s.replace(old, '')` 写回文件，然后**只再跑一次校验**。机制 = 每轮 write_file 都要重读全文做往返 = 一次重写几十秒；而批量替换一轮就是一次字符串操作。**判据 = 一轮对话里最多两轮校验（写完一轮 → 批量删一轮 → 放行）= 还超 = 说明身体段/锚写多了，回去砍锚不是砍背景。**

**校验脚本的定位**：`count_prompt_chars.py` 是**出图前的门**，不是交作业的次数。**跑一次 = 放行 = 出图**；报数里三段结构命中比字数重要得多，结构 MISS >=2 优先补结构。

**🔴 门禁现在是 4 层，exit 0 = 四层全过**：字符数区间 + 5 大结构段 ≥4 + 3 种自毁排版 + **3 条姿势自然度**（禁人体 `<35mm` 近距 / 角度值 ≤2 处 / 禁失衡感词）。**第 4 层不存在时，主人说「姿势怎么都这么诡异」而门禁全绿 = 闸门形同虚设。** 新加一条门禁 = 必跑双向回归（真反例 FAIL + 真正例 PASS）。

**校验规则**（`yuer_run_one_brief.py` 前置校验，不靠自觉）：

| 传入内容 | 行为 |
|---|---|
| 中文 brief（一句话 / 几十字）| **脚本拒绝** → 先走 `yuer-prompt-writer` 写英文 prompt |
| 自己随手写的英文 | 长度 0 阻断 = 超上限不砍 = **上限数字 = 现读 `count_prompt_chars.py` 当轮 stdout 打的数，0 背本档历史数** |
| 已按技能写好的英文 prompt | **走 `run`**（合格 prompt 直通分支，见铁律 10）|

### 🔴 两道门禁的判据**不一样** = 只跑 `count_prompt_chars.py` 不算过

`count_prompt_chars.py` 报「结构段命中 5/5 OK」**不等于** `run` 会放行 —— 两个脚本各自一套正则。最容易翻车的一条：

| 结构段 | `count_prompt_chars.py` | `run` 的 `_REQUIRED_SECTIONS` |
|---|---|---|
| 场景层次（前景/中景/远景）| 判「场景有层次」= **宽** | 🔴 正则 = `foreground\|midground\|far background\|background layer` = **必须把这几个英文词明写进 prompt** |

**症状 = 预检全绿 + `run` 报「brief 未通过 yuer-prompt-writer 质量校验（命中 X/5 大结构段）」** = 场景那层缺了 `foreground` / `midground` 字样。

**🔴 正解 = 落笔就把三层写实**（不是抽象写「前景是盘子、中景是她、远景是走廊」）：`a white porcelain dinner plate in the foreground beside her, her seated at the midground of a dark wooden dining table, tall windows in the far background` = 既过 `run` 正则 = 又是真的构图层次 = 一个动作解决两件事。

**🔴 判据 = 真源在脚本源码里，不在我的记忆里**：

```bash
grep -n '_REQUIRED_SECTIONS' -A 8 ~/.hermes/skills/creative/yuer-image/scripts/yuer_run_one_brief.py
```

**改 prompt 前先看这一段** = 知道「脚本到底认哪些词」= 不用拿报错反推。**报错只告诉你缺了哪一段，不告诉你缺哪个词。**

**🔴 两道门禁的完整判据（一次读全 = 0 试错轮）**：

| 门禁层 | 判据真值 | 怎么查 |
|---|---|---|
| **结构段 5/5** | `_REQUIRED_SECTIONS` = 5 段正则 | `grep -n '_REQUIRED_SECTIONS' -A 25 <脚本>` |
| **广角近距**（姿势自然度）| 门禁源码里有**豁免正则** = 广角贴地仰拍放行 | `grep -n '广角近距' -A 20 <脚本>` |
| **字符长度** | **= 0 阻断**（只报数不拦，唯一硬顶 = 防失控）= 写在门禁脚本里 = **0 背本文件里的数**。**出图道与抽卡道都是只报数不拦** = **0 因长度重写** |

**🔴 广角贴地仰拍 = 有豁免 = 0 必改焦段**：反推图常是 16mm 贴地仰拍 = 门禁判「人体广角近距」= exit 1。**正解 = 照原图焦段写 + 把机位高度写成豁免措辞**（`on the floor looking up` / `on the ground looking up` / `worm's eye angle`）= 构图不失真。**❌ 为了绕门禁把 16mm 改成 24mm = 机位跟原图对不上 = 主人要的角度没了。**

**🔴 同一件东西提 N 次 = 长度门禁先炸**：地板/瓷砖/光这类名词在一个点里提 3~4 次 = 同义重复 = 先收敛到 ≤2 次（不同指代可各 1 次）= 再量字符。**长度超标是「一个点写多遍」的下游症状 = 砍同义句不砍维度。**

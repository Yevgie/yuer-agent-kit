## 五、批量门禁三个已知误报（照抄解法，别反复重跑）

| 症状 | 真因 | 解法 |
|---|---|---|
| `FAIL 缺「鞋履」` 而画面里明明穿着袜子/木屐 | 鞋履正则白名单只认 `sneakers? / shoes / boots? / heels? / sandals? / loafers? / slippers? / running shoes`；`tabi socks` / `wooden clogs` / `barefoot` 都不在白名单（`barefoot` 只在完全不查的那一档才豁免）| 同句挂一个白名单词：`wooden geta sandals`（含 sandals）/ `white canvas sneakers` / `white sandals` |
| `FAIL 缺「单人物」` 而画面里只有一个人 | 正则把 `a pair of ...` 当成第二个人 | 去掉 `pair of`，写单数：`wooden sandals resting on the floor beyond the frame` |
| 特写/半身被判成全身 → 也被要求写鞋履 | `SHOT_FULL` 正则含 `from … to …` 结构，`a tight shot from her collarbones down to her hips` 会命中 | **🔴 11-07 已修 = 半身/特写 = 鞋履项跳过** = 仍报就先确认走的是现役脚本 = 旧版会把胯部景别误当全身 |

**总判据 = 门禁报的那一项跟画面实际对得上吗？** 对不上 = 误报 = 按上表改写法；对得上 = 真漏 = 补齐。**0 为消误报改构图。**

## 六、跑批与验收（一条命令，别手写 run 脚本）

```bash
ls /tmp/prompt_<tag>_n*.txt | wc -l          # 必须 == 5（孤儿文件 = 多发一张）
bash scripts/run_batch.sh <tag> <日期前缀>    # 自带三道硬门：文件数==5 / 逐张主体+外观锁 / glob 收文件
```

**批量道耗时基线（单卡串行，5 张约 75~100s）**：每张采样 12~20s + 下载 2s + 发图 2s。**采样是单卡串行的 = 并发提交反而更慢**（抢显存），别拿并发当提速手段。
前台跑批容易被抬成后台进程；起跑后直接等完成信号回来收口，**别在 `execute_code` 里 `sleep` 轮询**（白等 + 可能超时打断）。

**验收三件套逐张核**：`完成 (XX.Xs) success` + `落盘 …png = NNN 字节` + `✅ 图已真发飞书`，5 张都要有 = 才算发完。

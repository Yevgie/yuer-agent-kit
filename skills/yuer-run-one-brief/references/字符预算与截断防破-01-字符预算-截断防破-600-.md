# 字符预算 + 截断防破（600~3200 区间怎么写出来）

> 适用：按 `yuer-prompt-writer` 写完英文 prompt，交给 `run_with_prompt` 之前。
> 注：`yuer-prompt-writer` 本体是 user-owned，autonomous curator 无权改，所以这条落在本技能里。

## 🔴 天花板真值 = 3200（不是 2500）

`count_prompt_chars.py` 的放行区间 = **600~3200**（脚本 stdout 明写「在 600-3200 区间内」）。旧文档里的「800~2500 / 别超过 2500」= 历史口径 = **以脚本为准**。判据 = 跑一次门禁看它报的数字，不是看记忆里的旧上限。

**🔴 落笔前先扣身体段的预算**：现役身体段（`bodyblock_covered_CURRENT` ≈ 700 字符 / 裸体版 ≈ 1200+）是要整段拼进 prompt 的 = **场景 + 光 + 服装 + 表情 + 主角段合计只能剩 3200 − 身体段**。不先扣 = 写完必然超 → 触发下面那一串删块手术。**判据 = 身体段占全文 > 35% = 先换精简身体段，不是砍光和构图**（裸体图另有 `NUDE_SHORT` ≈ 900 字符现成版）。

## 🔴 铁律：一次落笔到位，0 整篇重写去凑字数

**现象（实测）**：为了把 prompt 砍进某个字数上限，从 1833 字符开始**整篇重写**十轮才落进 1000 = 单是这一段就烧掉三分半钟，而真正的出图只要 25 秒。

**真因**：

- 每轮重写 = 一次写文件 + 一次跑校验 + 一次重读（写入工具要求覆写前重读，否则报 `was modified since you last read it`）。一轮几十秒，十轮就是几分钟。
- **烧的不是算力，是往返**。字数上限是**门禁**，不是作业——它的作用是拦下失控的长 prompt，不是让你现场炼字数。

**正解（顺序不能反）**：

1. **先按 5 段骨架估一遍总长**（下表加起来 = 1000 上下，落到 800~2500 区间任意位置都行）。
2. **落笔时直接控在区间内**，一次写完。
3. **写完只跑一次校验**。通过 = 出图。
4. 只有真超 2500 才进入"删整句"流程，且删一次到位。

**禁**：写完 → 跑校验 → 超 → 整篇重写 → 再跑 → 还超 → 再重写……

**放宽后的额外好处**：区间变宽 = 一稿命中率大幅上升 = 上述循环基本消失。写 prompt 的耗时应当**与字数无关**，只与段落写没写够有关。

## 先分额度，再落笔

10-04 主人钦定放宽 = 1000 单线改成 **800~2500 区间** = 中间怎么分配全凭需要，**别再为了凑数反复砍**。

真正要守的只有一件事：**别超过 2500**。超了之后姿势/服装/人脸会被后段冲淡，这是唯一还拦的天花板。

**🔴 先量超了多少，再决定动多少**：超 40 字符 = 删一个短语；超 300 = 删一整句；超 600+ = 才需要重写某段。**绝大多数情况落在前两档。** 别一看到超就重写全文。

**🔴 超标手术 = 一次 execute_code 批量删块 = 0 一刀一刀改**：把要删的整块写成一个 `cuts` 列表，脚本里 `assert a in s` + `s.replace(a,b)` 一次跑完 = **一轮 tool call 砍掉 200~400 字符**。逐条 `patch` / 逐轮改写 = 十几次往返 = 烧的就是这十几次。**脚本末尾必须带语法自检**：`assert ', .' not in s`（悬空逗号）+ `assert '  ' not in s`（双空格）—— 删块手术最容易留这两种伤，CLIP 语义会被污染，比超长更糟。删完再跑一次门禁 = 通过就出图。

写的时候按 5 段骨架逐段填就行，**每段的额度是参考不是配额**（写不够 800 是偏短，会提示但不拦）：

| 段 | 参考额度 | 写法 |
|---|---|---|
| 主协议（相机/镜头/景别/机位）| ~180 | 选一个前缀，只写相机 + 焦段 + 机位高度 + 景别 |
| 主体姿势 + 表情 | ~280 | 6 物理量压成 2-3 句 + 表情物理化 ≥3 项 |
| 服装 | ~200 | 外观锁 8 项，能合一句就一句 |
| 场景层次 | ~180 | 前景/中景/远景各 1 个名词性元素 |
| 摄影尾参 | ~160 | 光感四层各 1 个词组 + 调色 |

**⚠️ 上表加起来不到 1100，而天花板是 2500** —— 意思是：**写细一点是对的**，别为了压到 1000 把 6 物理量和外观锁 8 项砍成一句话。实测把单张做到 2498（主体段写满 6 物理量 + 服装写满滑落状态）一次过门禁 = 姿势和露点都立住。**删的优先级永远排在新写的前面。**

## 超标时删整句，不改半句

删的优先级（从最没约束力的开始）：

1. **重复修饰** —— 衣服已经被 `drenched, clinging` 定死，又写一遍 `wet`
2. **数值/角度精确值** —— `spine leaning back fifteen degrees` → 删角度，保留 `spine leaning back`
3. **次要化妆细节**
4. **远景多一个元素**

## 🔴 禁 sed 式中途挖词

`p.replace("water beading on her collarbone", "")` 这类操作会留下：

- 悬空逗号：`hem riding up her bare thighs, . Upper eyelids heavily lowered`
- 粘连句：`one mouth corner lifted, Foreground: wet stone pool lip`

**语法破损会污染 CLIP 语义，比超长更糟。** 要砍就删**完整的逗号分隔块**，或直接重写整句。

**⚠️ 但「删完整块」≠「只能改写全文」**。合规的最小手术是：**删一整个以逗号分隔的修饰块**（含它前面的逗号），或删一整个小句 + 收掉它前面的逗号。实测 2747→2498 全程只做这类手术（删 `no close-up cropping, ` / 删 `, caught mid-motion` / 删 `thick ` / 删 `and fine dust` / 删两个修饰短语），0 重写、0 悬空逗号。

**判断标准**：删完之后读一遍那个句号 —— 如果剩下的分句仍然各自完整（主语+谓语齐全），就是安全的；只有出现 `, .` 或 `, Upper eyelids` 这种**紧跟逗号的下一个词是大写新句首**，才是挖漏了。

## 校验一次过

```python
p = open('/tmp/prompt.txt').read.strip
assert len(p) <= 2500, len(p)
assert ', .' not in p and '  ' not in p      # 悬空逗号 / 双空格
```

**⚠️ 先 `ls` 门禁脚本在不在**：它在 `yuer-prompt-writer/scripts/count_prompt_chars.py`，**不**在 `yuer-run-one-brief/scripts/` 下。不在那个目录里 ≠ 已删。找不到就在会话里 `len(prompt)` 手量，**不要因为门禁缺失就跳过校验**。

## 写文件时一次到位

别靠反复 `replace` 修剪。**每次覆写前重读文件**，否则会覆盖掉上一轮修改——写入工具会报
`was modified since you last read it`。一次写对 = 一次成功；反复改写 = 反复重读 = 白烧 tool call。

## 门禁脚本怎么用

`count_prompt_chars.py` 是**出图前的门**，不是**作业本**：

- **跑一次 = 放行 = 出图**。不要把「跑脚本」当成一次次交作业去逼近某个数字。
- 超了才需要处理，处理的唯一合法姿势是**删整句**（见上），不是重写全文。
- 报错信息里的三段命中（5 大结构段）比字数重要得多：字数只是天花板，结构齐才画得准。结构段 MISS >=2 = 优先补结构，不要先改字数。
